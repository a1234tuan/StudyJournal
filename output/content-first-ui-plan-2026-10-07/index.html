1. 结论：先局部减负，再改浏览方式，不推倒重做

推荐分成两个独立可交付批次：

  • 第一批（P0–P3）：低风险、能立即感受到的改善。 保持路由和数据处理方式，收窄列表、压缩重复页头、突出当天内容、调整知识页导航按钮。做完即可形成完整可用版本，不依赖侧览成功。
  • 第二批（P4）：日志只读侧览。 它不是 CSS 小修，而是导航与滚动模型改造；独立实施、独立失败回退，不拖累第一批。
  • P5：收敛验收。 在最终候选上集中跑必要的跨页面回归、一次生产构建及实际宿主检查；不在每个样式修改后跑全量和打包。

这里的“最小风险”不是承诺绝对没有 bug，而是缩小一次变更的影响范围，提前规定不可改变的行为，出错时只撤回相关层，不靠破坏功能凑视觉效果。

4. 逐项如何接入

A. 宽度：先只改容器，不碰内部业务

接入： TodayPage/JournalPage 外层增加页面专属修饰类与 CSS 变量；依旧渲染现有数据和组件，不换列表数据来源。

目标尺寸： 首页整体最大约 960px；日志主列最大 712px；辅助复习区约 224px，间隔约 24px。普通日志列表无侧览时最大 712px。侧览工作区最大约 1104px，集合列约 296px，正文目标最大 560px；显式展开阅读目标最大约 620px。

上述是默认字号下的样稿起点，不把每个比例锁死。小窗口、系统缩放和用户字号变大时先换行/堆叠/退回单页，禁止挤到看不清。

实现约束： grid 子项 min-width:0；工具栏 flex-wrap；正文 max-inline-size 与图片 max-inline-size 分别控制；公式/代码/宽表只在自身容器横向滚动；页面整体不能左右滚动。网格不用固定高度。P1 保留 window 作为原有滚动源，不提前改成所有面板独立滚动。

不做： 全局压缩 sidebar、全站字体变小、改变文章内容、为了补空白增加功能卡。

B. 页头：新增可选样式，不改公共默认

接入： 在 PageHeader 增加默认不启用的工作区样式属性/修饰类；原 normal/compact 调用不变。第一批只 opt-in TodayPage 与 JournalPage。

视觉规则： 页面位置用小标题/面包屑表达；保留可访问 h1，不用 display:none 让读屏定位消失；重复眉题/说明不在新调用里传入；日志正文标题、专题名保留。页面说明如确有必要，放到可发现的帮助，而非只剩 hover 提示。

行为规则： 今日计划、收藏夹、同步等动作仍使用原 onClick；不因为换插槽而触发新建或自动保存。窄屏时动作可以自然落第二行，不坚持“永远 56px 高”。

影响控制： 不批量替换所有 PageHeader；More、设置、备份、统计、AI/语音暂沿用原合同，后续只在已证明无回归的模式下逐页 opt-in。

C. 今天：直接突出记录，业务按原样保留

接入： 只重排 TodayPage 内的区域：紧凑动作行 → 当天日志主列，复习与目标为侧边摘要；窄屏辅助区移到正文下方或短摘要位置，不能盖住记录。

保留： 学科/模板状态、新建 await 路径、今日计划、收藏夹、云同步、今日状态/逾期提示、entry 标题编辑、当日 records。只把“最近日志”改成“今天记录”。

第一轮不改动作机制： 保持 RecordCard 复习/收藏/AI 按钮既有语义和可达性，仅局部减少占位、优化间距。V2 样稿里的三点菜单不强制第一批接入；把多种行为收进菜单会增加键盘、点击冒泡和触屏风险，收益不如控宽显著。

状态分支： 当天无记录但有复习、有记录无复习、两者均空、逾期、有自定义 entry 标题、大量当日记录均保持有用信息；不因计数为零隐藏所有新建入口，也不把历史内容伪装成当天。

D. 日志列表：改展示层，不重新设计检索业务

接入： JournalPage 现有分支、过滤和回调不变；继续使用 20 条渐进加载，标题与少量摘要/元信息先清晰呈现；RecordCard 的样式变体只能是 opt-in，不全局改动分类页/收藏夹等消费者。

保留： 全部日志/按日期、学科过滤、全局搜索、知识库入口、日期→学科子层级、批量加入复习、导出和加载更多。第一批不提前改造月历模型。

首次收益： 列表限宽，顶部少一段说明，标题可扫描；准确显示“记录日期优先”；有筛选无结果与完全无数据分别表达。

禁止： 将按日期按钮做成只有说明的占位动作；样稿可以不实现，但正式 APP 必须继续打开现有日期流程。不能把 20 条加载改成一次渲染全部来方便排版。

E. 知识库：折叠按钮移位，不扩大导航状态作用域

接入： 从知识页顶部移走现有折叠入口，由 App 的侧栏边缘在知识库工作区呈现；继续使用 knowledge.navigation.sidebarCollapsed 和 onNavigation。暂不发明全局折叠持久化。

范围： 折叠知识库导航时仍保留恢复入口；离开知识库按现有其他页面规则显示导航，不把知识库局部状态意外传给复习/AI。窄屏不出现悬空边缘按钮，继续原有底部导航/返回方式。

返回： 顶级知识库与专题返回遵守 goBack、来源栈及 knowledge-navigation-leave；按钮样式可以统一为“箭头 + 返回/来源”，不能改成固定跳到日志或更多。

保护： 大纲/导图切换仍受 editing 限制；安排复习、查找、更多保留禁用条件；只读恢复副本、同步错误与未保存节点必须可见，不能被新紧凑工具栏裁掉。

F. 图标、色彩与动效：小范围使用现有资源

复用现有 lucide 图标与主题变量，图标不代替必要动作文字；装饰 SVG 应 aria-hidden，不参与键盘焦点；禁止每条日志都出现有动效的大图。重点只在选中态、内容标题和当前主动作。

减少动效偏好必须生效。第一批不新增页面转场时长或循环动画；沿用并检查现有 PageTransition，避免同时改布局和动画引擎。

5. 日志侧览的专门设计（P4，高于纯样式风险）

5.1 初版范围必须收紧

只对日志 → 全部日志列表 → 打开记录启用宽屏只读侧览。今天、搜索结果、按日期下钻、收藏夹、知识库引用、复习、语音、Coach 的打开方式先维持现状。

侧览正文只读；只有“展开完整日志/编辑”的显式动作进入原 RecordEditorPage。原编辑页完整保留资产、引用、复习设置、导出、语音等，不把所有工具硬塞进窄面板。

这意味着第一版不同来源的展示方式可以不同，但各自的返回合同明确、可预测；“流转对等”不是强迫所有路径长得一样。

5.2 状态只有一个权威来源

推荐继续复用 journal.recordId 作为当前记录身份，附加可选的呈现方式（例如 recordPresentation: peek/full）和列表滚动锚点；不同时维护另一个容易失步的 selectedRecord 对象副本。

  • 宽屏下 peek + 未编辑：保留列表，旁边显示只读正文。
  • full 或 recordEditing：进入现有完整页；不挂载第二个可写编辑器。
  • 窄屏/空间不足：相同记录用原单页阅读，返回回同一个集合；视口变化只是呈现降级，不伪造额外历史，也不强制退出正在编辑状态。
  • 旧历史快照没有新字段：默认 full，保持旧路径含义。未知值安全回退到原完整页，不崩溃。
  • 所有新增字段同步更新 tabNavigation 的深度/页面 key/返回函数，以及 webNavigationHistory 的序列化、白名单和恢复测试；这是本阶段动手的前置合同，不允许临时散落到 localStorage。

不新增数据库表，不上传浏览位置，不把文章正文放进 history state。本阶段不承诺跨软件重启恢复新浏览状态，避免偷偷扩展持久化范围。

5.3 返回与历史操作的具体合同

  • 列表打开 A：形成可返回的 A 状态；宽屏选择 B：替换当前侧览位置，不让每次扫读都堆满 Back 栈。
  • 关闭侧览/应用内返回：先关闭侧览，恢复原列表及焦点；列表原本在什么学科、已加载多少条、选中哪个锚点都不变。
  • 浏览器 Back：按真实前一历史项恢复；Forward 可再次打开最后有效记录。显式关闭和浏览器 Back 共享状态转换规则，但不能都调用一次导致退两层。
  • 从侧览进入完整页/编辑：记录完整页来自哪个侧览；返回先回该侧览，再关闭回列表。保存或删除失败不能假装完成跳转。
  • 切换 Tab 再回来：按现有 TabMemory 保留浏览状态，不默认退回全部日志初始页。
  • 记录内引用 A→B→返回：沿用现有 referenceStack，并在完整页完成；不能用 openRecordInTab 的重置栈行为误清掉来源。
  • AI/语音/知识库动作仍走现有打开函数；该功能本来如何返回就按同一对象与来源验证，不自己在 CSS 层模拟返回。

Web 的 history push/replace/back 只由已有导航协调入口提交；Electron/Android 继续相应的应用返回机制。这里的变更需先写纯状态转换用例再实现 UI，不能靠浏览器“看起来能退回”证明正确。

5.4 滚动、宽度与只读渲染

当前列表保存 window.scrollY；侧览引入集合内滚动后，不能继续拿窗口坐标恢复侧栏。定义独立列表锚点（recordId + 相对偏移）、已加载数量和正文 scrollTop；页面/容器滚动由一个入口捕获并恢复。记录被删时回最近有效邻项，不恢复到不存在的无限偏移。

复用 RichTextEditor 的只读内容渲染链与 normalizeRecordContent，参考 KnowledgeRecordPane 的能力；首版不跨两个功能模块抽出一个巨型通用侧栏。需要确认只读渲染不会恢复/提交草稿、开启录音或执行正式写入。

有编辑草稿的记录显示“此处为已保存内容，继续编辑查看草稿”，不无声地把正式版当成用户刚编辑的版本；加载/错误/已删除/不可用都要有可恢复出口。

使用可用工作区宽度决定三栏是否成立，而不是看到 desktop 就启用。集合列、正文和内边距的最小和不满足时回原单页。默认目标约 296px 集合 + 560px 正文 + 两侧内边距/分隔；需要测量真实空间，不给 1024px 小窗口强塞三栏。首版固定合理列宽，不增加拖拽分隔条和新持久化设置。

5.5 PageTransition 与保存守卫

side peek 不能简单沿用“recordId 一变就重挂整页”的 key，否则列表位置和效果都失效。对 journal 工作区做局部稳定容器/转场分支，不改变其他 Tab 的 pageKey 语义。

检查 entering/exiting 双层期间：旧层不接收点击和快捷键，焦点不能落入退出层，异步保存不因两个副本重复执行。关闭浮层、保存中批注、离开知识库节点、编辑草稿等已有保护必须先完成/明确失败，再提交导航。

连续点击 A/B、快速换 Tab、触发 Back 后又点前进，必须让最新一次允许的导航生效，旧异步回调不能把用户拉回早已离开的记录。

6. 分阶段执行与每阶段停线条件

P0 · 基线固定与功能合同（不改 UI）

输出：相关已修改/新增文件清单、阶段回退补丁、当前关键页面截图和原有失败列表；把本方案的入口合同转成测试任务。使用隔离夹具，不连接真实账户。

只对受影响的 Today/Journal、导航/历史、知识库与前轮复习退出保护做一次有边界的基线检查。已知问题记录在案；不为本轮重跑所有历史套件。

门槛：能区分“原本就这样”和“本轮引入”；不能辨明工作树归属时先停止覆盖，不以恢复仓库解决。

P1 · 控宽与紧凑页头（低风险，可独立交付）

范围：PageHeader 可选修饰、Today/Journal 专属控宽、准确文案、局部按钮换行。原路由/数据/列表滚动不变。

验证：TodayPage.test.tsx、JournalPage.test.tsx 和新增页头 opt-in 对照；桌面/窄屏布局几何与两种主题代表截图；相关共享组件若改动，补跑其消费者冒烟。

门槛：内容宽度收敛、没有控件遮挡/整页横滚、所有动作可达；旧 PageHeader 消费者样式不变。失败只回退 P1 局部修饰，不改业务救场。

P2 · 今天的内容层级与日志行（低至中风险）

范围：日志主体/辅助复习区的结构重排，RecordCard opt-in 展示；保留当前操作机制。不要同时做新的三点菜单系统。

验证：当天状态组合、学科/模板创建、计划/收藏/复习跳转、记录/引用基础打开、日期优先与20→40加载；无匹配/空数据/长内容。复用 workspace-polish 和 journal-performance 的有效行为断言。

门槛：新建不重复创建，收藏/复习不被记录打开截获；entry 编辑、批量/导出等未被删除；两个 Tab 的返回路径与原来一致。

P3 · 知识库导航按钮与风格收敛（中风险，但限于局部）

范围：边缘折叠入口、返回视觉、工具栏换行；只沿用 knowledge state，不全球化折叠行为。将公共图标/焦点规则应用到已改页面，不重绘整个产品。

验证：知识库列表→专题→日志→返回原专题；从日志关联进入→返回原日志；折叠/恢复；窄屏、编辑禁用、离开保护、恢复副本/错误提示；大纲/导图与安排复习原入口。

门槛：来源不被硬编码成 more 首页；侧栏恢复始终可达；知识库折叠不影响复习/AI。至此第一批可以验收和交付。

P4 · 日志只读侧览（独立中高风险阶段）

先完成纯状态转换与历史恢复测试，再接入 UI；仅覆盖全部日志列表来源。修改重点为 App journal 渲染、tabNavigation/webNavigationHistory、JournalPage 与只读正文包装。

验证：本方案第5节全链路；直接覆盖20→40条后第31条打开/返回、筛选、滚动、删除/同步失效、草稿存在、快速切换、引用栈、窄屏退化与宿主返回。

门槛：路由/内容身份/保存安全任何一项失败都不可通过。通过前维持原完整详情路线作为可切回实现；不要靠破坏既有引用/返回约定强行上线。

P5 · 最终候选集中验收（不反复打包）

在代码冻结后的候选上运行一次受影响回归的并集，外加复习/语音/AI/计划/知识库跨页面核心路径。因改公共导航，tabNavigation、webNavigationHistory、PageTransition 和 review-navigation-safety 必须包含；不是只测新页面。

TypeScript 可按阶段有 TS 改动时检查；最终 npm run build 只做一次完整生产构建。若发现问题，修正后复跑失败项 + 改动影响集合，构建仅在产物确实失效时重做，不为了“刷绿”反复全量运行。

实际 Electron/Android 验收单列，不用 Chrome 窄屏冒充。只在用户明确授权且不覆盖现有安装/数据的环境中执行；无法执行时报告未覆盖宿主，不写“全平台通过”。发布、安装包、真实云账户/付费服务与推送不包含在本方案默认授权内。

7. 严格验证怎样具体落实

7.1 视觉不是只截几张图

默认字号基础尺寸：320、390、768、1024、1280、1440、1920px；包含代表性矮窗口（例如 768px 高）与真实窄屏键盘空间。断点实现后，追加断点前后 1px 的自动布局测量，防止只有整数字宽好看。

不做所有维度的暴力笛卡尔积：

  • 所有关键宽度跑当前默认主题几何断言。
  • 温润/现代 × 浅/深共四种组合，在1440与390各一次代表截图。
  • 字号最大值、正文最大字号/行距，以实际设置界限为准，在320/390/1024复核；另做真实浏览器200%缩放，不能仅用CSS transform伪造。
  • 长中文/英文标题、无空格长URL、20个标签、超长按钮文字、代码/公式/宽表/图片，作为针对性夹具，不只看短示例。

几何检查对象：页头动作、返回、折叠恢复、列表标题/菜单、底栏、浮窗关闭/主动作。断言在当前容器内，关键 hit area 无非预期相交；使用 hit-test 确认按钮没有被透明层遮挡，触屏直接点击目标，键盘顺序能到达。

允许正文内部的表格/代码横滚；禁止整页横滚。允许标题自然多行；禁止裁掉按钮文字或覆盖相邻按钮。遮罩覆盖背景属于设计预期，不能用“所有元素矩形不相交”的粗暴规则产生假阳性。

截图须等待字体、图片和页面转场稳定；静态截图使用减少动效以稳定比较，同时另测正常动效中的点击/返回/焦点，不通过关动画掩盖双层问题。自动截图差异必须人工看，不能一律更新基准。

7.2 流转逐条验收，不只断言到了某个标题

每条路径核对：来源 Tab/子页面、记录ID、筛选/搜索词、日期/学科、已加载数量、滚动锚点、焦点、编辑/草稿状态、受保护操作是否真正完成。

必测路径：

  1. 今天→新建（学科/模板）→编辑→返回今天，创建一次，内容不丢。
  2. 今天→今日计划→计划关联日志→返回正确来源；不退错到普通日志列表。
  3. 日志全部→学科→加载40条→第31条→返回，条数/过滤/位置恢复。
  4. 日志按日期→学科→记录→返回学科→返回日期；批量选择、加入复习、导出保持范围。
  5. 日志→全局搜索→结果→返回搜索，保留检索词与结果状态；不能总退到全部日志。
  6. 知识库列表→专题→节点→关联日志→返回同一节点；日志→知识关联→返回原日志同样验证。
  7. 列表AI按日期与既有单条AI入口分别验证上下文；取消/失败不留下错误返回来源。
  8. 复习卡片→语音准备→返回原卡；普通/已安排进度不重置；复习看板仍是弹窗。
  9. 切Tab、应用内返回、Web Back/Forward、Android Back分别测试；它们共用状态含义但不是同一宿主实现。
  10. Esc先关闭最上层弹窗/菜单，不能同时关闭侧览；输入法组合输入和文本编辑不触发误导航。

7.3 危险边界用注入失败验证

  • 批注保存延迟/失败时点击侧栏或返回：沿用现有等待/错误处理，不能丢草稿或误称保存成功。
  • 日志草稿写入失败、正式保存冲突、恢复锁定：视图不掩盖错误，操作不静默覆盖新版本。
  • 打开预览时记录被删除/同步移除，刷新后不存在：显示不可用并可退出，不重建记录，不从UI缓存写回旧数据。
  • 账户/知识库切换导致来源失效：关闭失效预览或提示范围变化，不跨账户恢复旧对象。
  • 快速 A→B→换Tab 与异步回调交错：旧回调不得覆盖新的选择；只有当前可交互层能触发操作。
  • 纯预览前后比较正式记录、复习状态/日志/统计和草稿写入调用：不产生隐式写入；用户明确收藏/复习则仍应按原语义产生合法写入。
  • 正在编辑/录音时缩放窗口、横竖屏变化：不得卸载工作会话而丢草稿、重开麦或结束通话。

8. 放行、修复与回退纪律

放行必须同时满足

  • 必跑断言通过，未引入新的运行时错误、布局遮挡或身份/返回错配。
  • 代表截图人工检查完成；保存/失败/删除/返回保护通过，不能只靠截图。
  • 既有能力有对应入口和行为证据；重排后没有隐藏的功能缩水。
  • 未测宿主和依赖限制明确列出，不把 skip 算成通过。

失败后的最小修复

  1. 先分类：夹具/定位问题、CSS局部问题、导航状态问题、数据安全问题。
  2. 夹具问题修正夹具，保持需求断言；不加无限重试或放宽到不可见也算通过。
  3. CSS问题优先修所在页面/组件；不加全局裁剪、全局字号降级或覆盖全部按钮。
  4. 导航问题修状态转换，补一个能稳定复现的用例；不能仅在按钮里临时多调用一次返回。
  5. 数据安全、草稿丢失、范围错配、跨库泄露风险立即停线，回到最近通过阶段；不能以“UI优化”为由继续带病叠改。
  6. 修复后只复验失败项与真实影响集合；若改到公共导航则必须扩到所有核心来源，不能仍只测日志页。

回退方式

P1–P3按局部 opt-in 类/属性与组件边界恢复，不撤回已通过的其他阶段。P4 在评审期间保留原详情分支与单一内部呈现开关，关闭侧览时把新状态安全归一到 full；不增加面向用户的“旧版/新版”永久设置。

不作数据库降级、不反向同步、不回滚真实日志、不恢复整个仓库到旧提交。回退必须以 P0 捕获的本轮起点为准，保留已有复习/语音改动。通过最终验收后清理临时开关和不再使用的样式，不留下两套长期并行UI。

9. 交付与验收材料

每阶段保留：改动文件与范围、未变功能合同、定向验证命令/结果、前后截图、发现并修复的问题、未覆盖事项、回退入口。最终提供阶段并集的真实计数，不把重复跑的用例累加成“覆盖更多”。

用户验收重点：

  • 在自己的常用窗口下，条目不再过宽，第一眼是日志而非装饰。
  • 无需重新学习按钮名称和范围，原来的功能仍能找到。
  • 连续打开/返回多个对象，始终知道回到了哪里。
  • 新建、编辑、复习、知识关联等工作不因布局变化中断。
