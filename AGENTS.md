- The 2026-09-24 post-`e0b3b09` follow-up fixes a P0 the forensic remediation itself introduced in Storage-GC judgment ②. `cleanUpUnreferencedStorage` compared `referenced.length` (left, from `collectSnapshotEntities` → `parseAndNormalizeRemoteEntities`, which keeps only docs that pass the *entity* parser) against `protectedReferenceCount` (right, raw `getCountFromServer` over each retained snapshot's `entities` subcollection). But `makeRemoteSnapshot` writes review-event docs (`review-event:` prefix, `{ id, contentHash, payload, revision, kind:"review-event" }`, no `entityType`/`entityId`) into that SAME subcollection and counts them in the commit `entityCount`, so `parseRemoteEntity` drops them and the left side is permanently short by the number of review events. Because routine auto-backup (`makeLocalSnapshot`) always passes `exported.reviewEvents` (from `recordReviewLogs`), every real snapshot for any user with review history triggered judgment ② ⇒ `cleanUpUnreferencedStorage` always returned `deferred-cost` and deleted nothing. Judgment ② is unconditional (not gated by `allowExpensive`), so BOTH automatic background GC and the manual `force+allowExpensiveStorageGc` entry were permanently, silently dead (recorded as `deferred-cost`, not `failed`, with a misleading "云端存在无法读取的同步数据" message); orphan blobs accumulate forever. Fix: `collectSnapshotEntities` now partitions each subcollection by `REVIEW_EVENT_DOCUMENT_PREFIX` (mirroring the restore path's `assertStrictCloudSnapshot`), tolerantly parses entities (`parseAndNormalizeRemoteEntities`) and review events (`parseRemoteReviewEvent`), and returns `{ entities, consumed }`; judgment ② compares `active.length + snapshotRead.consumed !== protectedReferenceCount` so both sides are same-source. `entities` alone still feeds the Storage protection set (review events reference no blob); a doc that parses as neither still shortfalls `consumed`, so the malformed-document protection is unchanged. Regression `cloudSyncWhitebox.test.ts` N2-5 (a retained snapshot whose subcollection mixes one entity + one review event, plus a true orphan) was proven red first (`expected 'deferred-cost' to be 'completed'`) then green; whitebox suite 43/43, `tsc -b` clean, bounded full suite 1906 passed / 1 failed (the known concurrent sync-integration timeout that passes alone at 1840ms). The N2-1..N2-4 cases missed this because their `seedSnapshots` writes childless parents (`entityCount:0`, no subcollection docs), so the snapshot side was 0 on both. ## Review Annotation Boundaries

- Review annotations wrap the read-only review editor and never mutate `RecordBlock.contentHtml`.
