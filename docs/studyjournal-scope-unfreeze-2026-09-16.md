## 1. 决定

`docs/studyjournal-final-freeze-2026-09-15.md` 规定的功能冻结，**在「今日计划」这一个范围内解冻**。用户于 2026-09-16 明确要求：「解冻这块范围，我需要在这里开发，然后后续可能会搬到 Exocortex」。

本文件是该解冻的正式记录。它**不修改**原始冻结文档——冻结文档是历史收口记录，按冻结文档 §8 的规定，当前基线以源码、该冻结文档与 `AGENTS.md` 的当前状态为准，因此由本文 + `AGENTS.md` 的一行指针共同表达解冻。

## 2. 解冻范围（精确边界）

**允许在本仓库新增的能力：**

- 新增 `DailyPlan` 实体（「今日计划」），含按日期、按学科列计划的能力。
- 计划与日志的关联：计划行可指向一条日志记录；日志可声明自己「来自计划」。
- 「今日计划」界面：首页「今天」页右上角入口（该入口按钮已存在于 `src/pages/TodayPage.tsx:77-86`）+ 计划列表页 + 计划历史/统计页。
- 计划完成度的确定性统计（完成率、连续完成天数、学科分布、按日分组）。**不做模型调用**。
- 上述数据参与云同步与便携备份（与 `entry` / `block` 等同级），并遵守既有墓碑、快照完整性校验与隐私剥离规则。

**允许的 schema 变更：**

- Dexie `schema 23 → 24`，**仅新增 `dailyPlans` 一张表**。
- 允许给 `RecordBlock` 增加一个可选的 `planId` 字段（用于「来自计划」的归属声明）。
- **不允许改动任何既有表的索引定义**（`blocks` 索引保持 `"id, date, type, order, updatedAt"` 不变）。

**允许的同步协议变更：**

- `CloudSyncEntityType` 增加 `"daily-plan"`，以及随之而来的快照载荷、备份载荷与实体类型清单更新。
- **不改变** `PROTOCOL_VERSION`、revision/ledger/墓碑机制、冲突解决策略。

## 4. 解冻的前置与后果

- **前置**：本解冻不改变「Exocortex 必须在新目录、新仓库启动」的规则；`docs/archive/exocortex-ai-cockpit-migration-and-enhancement-plan-2026-09-15.md` 的迁移边界继续有效。
- **后果**：本仓库的「维护冻结」状态自本日起变为**「维护 + 单一范围演进」**。除「今日计划」外的新功能提案仍然需要单独解冻。
- **回滚**：schema 24 是单向的。回装早于本次改动的 APK/桌面版会因为数据库版本高于代码版本而打不开数据（仓库当前没有 `VersionError` 处理）。因此本次改动上线后，**不支持旧版本回装**；这条限制必须在发布说明中写明。

## 5. 为 Exocortex 迁移预留的约束

用户的后续意图是「可能搬到 Exocortex」，因此本次实现必须满足：

1. **自包含**：计划能力不得依赖新的全局设置项、不得依赖 localStorage、不得写入 `settings` 的同步契约。
2. **契约显式**：`DailyPlan` 与 `RecordBlock.planId` 必须出现在 `BackupPayload` 与云同步实体清单中，使新仓库可以用同一条导入器读取。
3. **不污染既有语义**：计划能力不得改变日志、复习、评分、备份的既有含义；「来自计划」只是归属声明，不改变任何调度或评分行为。
4. **可整体摘除**：删除计划能力时，只应留下 `dailyPlans` 表与 `planId` 字段两个无害残留，不影响其余功能。
