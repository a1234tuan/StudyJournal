## 3. 本次扩大后的允许范围

在 2026-09-16 §2 的全部内容之上，新增允许：

- 计划元数据（`DailyPlan` 的 `date` / `subject` / `title` / `order`，以及由 `linkedRecordId` 派生的兑现状态）**进入 AI 上下文**，作为 `src/services/aiContextService.ts` 的一条新输入；
- 新增**版本化 prompt 与 AI 角色**，用于生成「意图 vs 兑现」的反馈文本（对齐仓库既有的角色配置、prompt 版本化与样例回放机制）；
- 计划完成度作为**元数据层分析**的输入，不与正式学习事实（决策块掌握、复习调度、延迟验证）混同。

## 4. 不因本次扩大而改变的部分

1. **产品边界**：`docs/新的方案.md:738-750` 全部继续有效。特别是「由 AI 自由决定任务优先级、正式掌握状态或延迟验证日期」**仍然禁止**；L2 的模型输出**只能是建议文本**，不得写入任何正式状态。
2. **`新的方案.md:750` 的重审条件**：将来的需求若会突破该边界、改变正式数据含义或新增正式任务类型，仍须先修改该文档并重新做产品确认。
3. **复习加入规则**（`docs/新的方案.md:107`）：计划产生的日志**不得**默认静默加入复习队列。
4. **冻结路由**：`复习 → 学习助教` 不移位；`UsageGuidePage` 的相关内容与断言不变。
5. **既有表的索引**：一律不改。
6. **同步协议**：`PROTOCOL_VERSION`、revision/ledger/墓碑机制、冲突解决策略不变。
7. **不引入新的原生依赖**（含本地通知、后台任务）；`dependencyHygiene.test.ts` 继续生效。
8. **设备本地边界**：`aiSecrets`、Provider 配置、`aiSessions` / `aiMessages` / `aiAttachments`、播客行与音频继续不进入云同步或可移植备份。
9. **既有的未关闭发布门禁**（真机、付费 Provider、真实 Firebase 账号）不因本次解冻而关闭；付费 Provider 测试仍须单独批准。
10. **仓库级分离规则**（`docs/studyjournal-final-freeze-2026-09-15.md:81-92`）不变：Exocortex 仍须在新的本地目录、新的远端仓库启动，不得在本仓库原地改名。本次只撤销「今日计划的后续搬去 Exocortex」这一条**功能级**预期，不撤销仓库级规则。

## 5. 本次记录不包含什么

- **不含实现改动。** 本文只记录范围与边界，不涉及任何代码。
- **不含设计。** L2 的输入契约、prompt 形态、输出 schema、与驾驶舱既有事实链（`记录正文 → 决策块 → 反馈 → 解读 → 训练任务 → 结果事件 → 延迟验证`）的衔接方式，以及是否需要新的持久化，**均尚未确定**。若最终需要新表或新字段，同样适用仓库既有规矩：schema 单向递增、明确区分设备本地与云同步、墓碑与隐私剥离规则照常。这些都需要单独的设计文档与确认。
- **不承诺任何数字、时间或效果。**
