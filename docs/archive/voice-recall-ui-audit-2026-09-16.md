# 语音复述界面正式审计报告

**审计日期：** 2026-09-16  
**审计对象：** 语音复述工作区及其展示、字幕、历史记录和通话控制界面  
**审计类型：** 源码级界面与交互审计  
**审计结论：** 有条件通过，暂不建议作为完全收口版本发布

## 一、审计范围

本次审计覆盖以下实现范围：

- 语音复述工作区的状态管理、通话控制和历史记录操作；
- 通话展示层、字幕展示和字幕编辑入口；
- 通话模式选择、字幕开关、输入方式和更多设置区域；
- 通话详情、发送资料范围、用量信息和时长展示；
- 模态面板的键盘操作、焦点管理和关闭行为；
- 语音复述相关样式、响应式布局、动画降级和视觉主题；
- 与当前语音上下文预算及本地数据边界相关的界面文案。

本报告仅根据当前实现状态、源码结构和已存在的界面行为作出判断，不将尚未接入的设计意图视为已实现功能。

## 二、总体结论

语音复述界面的核心 ASR -> LLM -> TTS 主链路没有发现整体失效问题，主要状态、错误态、空状态和基础无障碍标记也具备继续迭代的基础。

但当前界面仍存在影响信息准确性、知情使用、键盘可用性和交互一致性的缺陷，审计暂不完全通过。其中，发送资料范围不可见、时长信息不真实、模态行为不完整，以及字幕开关的无障碍语义错误，属于发布前应优先处理的问题。

建议先完成 P1 项，再处理 P2 项，最后清理 P3 项并执行专项回归。完成修复且通过本文末尾的验收标准后，再进行发布级复核。

## 三、问题分级说明

- **P1：** 可能造成用户误解、错误操作、数据知情不足或明显无障碍障碍的问题，应在发布前修复。
- **P2：** 影响重要交互完整性、可用性或维护可靠性的问题，应安排在本轮修复。
- **P3：** 影响一致性、完成度或细节体验的问题，可在 P1/P2 之后处理，但不应长期遗留。

## 四、审计发现

### P1-01 字幕按钮的视觉状态与无障碍状态不一致

**位置：** src/features/voiceRecall/VoiceRecallPresentation.tsx，约第 354-357 行

**现状：**

- 按钮的视觉高亮由 captionsVisible 决定；
- aria-pressed 却绑定到 transcriptEditorOpen；
- 当字幕显示但编辑器关闭时，视觉上按钮处于激活状态，而无障碍树会报告为未按下。

**影响：**

屏幕阅读器用户获得的状态与视觉用户不一致，无法可靠判断字幕是否已开启。该问题也会影响自动化测试对控件状态的判断。

**建议：**

将 aria-pressed 与字幕按钮实际控制的 captionsVisible 绑定。如果编辑器打开是独立状态，应为编辑器使用独立按钮或独立语义，不应复用字幕开关的状态属性。

**验收标准：**

字幕开启、关闭、编辑器开启、编辑器关闭四种组合下，视觉状态、按钮名称、aria-pressed 和实际行为保持一致。

### P1-02 通话进行中缺少可见的发送资料范围

**位置：** src/features/voiceRecall/VoiceRecallWorkspace.tsx，约第 1204 行；通话展示相关区域

**现状：**

当前轮次发送的记录数量、字符数量等信息只出现在“更多通话选项”抽屉内。通话进行中，主界面没有直接说明本轮向模型提供了哪些资料或范围。

**影响：**

用户在通话期间无法快速核对 AI 使用的上下文范围。对于学习内容、隐私边界和回答准确性而言，这属于重要的信息可见性缺口，也会削弱首次确认所建立的知情预期。

**建议：**

在通话主界面提供紧凑但明确的上下文范围摘要，例如已选学科、记录数量、发送内容范围和当前预算使用情况。详情抽屉可以保留，但不应成为唯一入口。展示信息应与实际发送请求保持同一数据源。

**验收标准：**

开始通话后，用户无需打开隐藏抽屉即可知道本轮上下文的基本范围；上下文发生变化时，摘要同步更新；没有资料时明确显示空范围状态。

### P1-03 通话时长没有显示真实经过时间

**位置：** src/features/voiceRecall/VoiceRecallWorkspace.tsx，约第 1170 行；src/features/voiceRecall/VoiceRecallPresentation.tsx，约第 321 行

**现状：**

传给展示层的 elapsed 实际上是“进行中”或“已暂停”这样的状态字符串，而不是由 elapsedMs 计算出的真实通话时长。展示层仍将该属性按时长字段渲染。

**影响：**

用户无法判断已经练习了多久，也无法判断暂停前后的累计时长。属性命名与实际数据含义不一致，增加后续维护和测试误判的风险。

**建议：**

使用状态机中的时间戳或累计毫秒数计算可读时长，明确区分“通话时长”“当前状态”和“模式名称”。暂停时冻结累计时长，继续后恢复累计；结束后保留本轮最终时长供历史或结果页使用。

**验收标准：**

开始、暂停、继续、结束四个阶段的时长显示连续、累计且不倒退；跨分钟显示格式稳定；暂停期间时长不继续增长。

### P1-04 模态面板声明了模态语义，但没有完成模态交互

**位置：** src/features/voiceRecall/VoiceRecallPresentation.tsx；相关动画容器和样式文件

**现状：**

详情抽屉和离开确认面板使用了 aria-modal="true"，但当前未发现完整的焦点进入、焦点陷阱、Escape 关闭以及关闭后焦点归还机制。动画组件只负责进出动画，不负责焦点管理。

**影响：**

键盘用户可能继续访问模态背后的控件；屏幕阅读器用户可能无法稳定定位当前操作区域；关闭面板后焦点位置不可预测。声明模态语义却不提供相应行为，会造成实际语义与交互模型不匹配。

**建议：**

为每个模态面板补齐以下行为：

- 打开时将焦点移入面板的标题、关闭按钮或首个可操作控件；
- Tab 和 Shift+Tab 在面板内部循环；
- Escape 关闭可关闭的面板；
- 关闭后将焦点归还到触发按钮；
- 离开确认面板应明确默认焦点和危险操作焦点。

**验收标准：**

仅用键盘即可完成打开、浏览、关闭和确认；模态打开期间背景控件不可通过 Tab 访问；屏幕阅读器能得到正确的标题和关闭反馈。

### P1-05 历史记录删除是立即且不可恢复的

**位置：** src/features/voiceRecall/VoiceRecallPresentation.tsx，约第 240 行

**现状：**

历史条目的删除按钮直接调用删除回调，没有确认步骤，也没有撤销入口。相关历史属于设备本地数据，删除后不存在云端或备份恢复路径。

**影响：**

误触会造成永久数据丢失。对于包含学习过程、复述内容和语音转写的历史记录，直接删除缺少必要的风险控制。

**建议：**

优先增加轻量确认面板；如果产品希望保持快速操作，可采用删除后的短时撤销提示，但撤销机制必须覆盖实际删除生命周期，不能只是视觉提示。

**验收标准：**

用户明确确认后才会永久删除；取消确认不会改变数据；删除成功后有清晰反馈；撤销功能若提供，应能恢复完整条目及其关联内容。

### P2-01 Push-to-talk 存在重复结束事件路径

**位置：** src/features/voiceRecall/VoiceRecallPresentation.tsx，主控制按钮；src/features/voiceRecall/VoiceRecallWorkspace.tsx，录音停止状态管理

**现状：**

按住讲话模式下，同一按钮同时绑定了 onClick、onPointerDown、onPointerUp 和 onPointerCancel 等路径。当前通过 captureStoppingRef 等状态避免重复转写，但事件模型本身仍允许指针抬起和 click 先后触发两次停止逻辑。

**影响：**

在不同浏览器、触摸设备、键盘操作和事件时序下，可能出现重复停止、重复提交、状态竞态或偶发的转写异常。当前保护逻辑降低了风险，但没有消除复杂事件路径。

**建议：**

明确 tap-to-record、push-to-talk 和键盘操作的事件契约。Push-to-talk 应使用一条主停止路径，并针对 pointer cancel、失去焦点、触摸结束和键盘释放分别测试。若保留 click，应确保它不会在 push-to-talk 状态下再次执行停止动作。

**验收标准：**

鼠标、触摸、触控笔、键盘和窗口失焦场景下，每次录音最多产生一次停止和一次转写提交；取消操作不会产生残留转写。

### P2-02 “更多设置”展开区域为空

**位置：** src/features/voiceRecall/VoiceRecallPresentation.tsx，约第 156-169 行

**现状：**

界面使用了 vr-mode-band-visible 类名，但样式中没有对应规则；同时，vr-advanced-details 只包含一行 summary，展开后没有实际内容。输入方式三选一已经在主区域完整显示。

**影响：**

用户会看到一个可展开但没有内容的设置入口，造成界面功能未完成的印象，也增加无效点击和理解成本。

**建议：**

二选一处理：删除空的“更多设置”入口；或补充真实设置内容，并确保其与现有模式选择、服务商配置和设备能力边界一致。未接入的配置不要保留可见入口。

**验收标准：**

展开入口要么不存在，要么能展示至少一个真实可用且可验证的设置项；不会出现空展开区域。

### P2-03 字幕滚动区域缺少可见键盘焦点样式

**位置：** src/features/voiceRecall/VoiceTranscript.tsx，约第 15 行；语音复述样式文件中的 .vr-transcript-scroll

**现状：**

字幕滚动区域设置了 tabIndex={0}，允许键盘用户聚焦并滚动，但样式没有提供对应的 :focus-visible 视觉反馈。

**影响：**

键盘用户无法确认当前焦点是否位于字幕滚动区域，尤其在通话中多个按钮和动态消息同时变化时，容易误操作。

**建议：**

为滚动区域增加符合当前主题的 :focus-visible 轮廓或边界状态，并确保不会被容器裁切。焦点样式应满足桌面和窄屏布局。

**验收标准：**

使用 Tab 进入字幕滚动区域时，焦点位置清晰可见；鼠标点击不产生不必要的强焦点装饰；亮色和暗色主题下均有足够对比度。

### P2-04 实时详情仍使用字符口径，未对齐当前 token 预算

**位置：** src/features/voiceRecall/VoiceRecallWorkspace.tsx，约第 401 行及通话详情展示区域

**现状：**

界面仍显示“本次发送 X/Y 字”或类似字符统计，但当前语音上下文预算已按所选模型的 contextWindowTokens 进行估算，且不再以固定字符上限作为主要约束。

**影响：**

用户看到的指标无法准确解释实际预算，也可能将字符数误认为模型上下文额度。界面文案与真实控制逻辑脱节，会削弱对上下文裁剪结果的理解。

**建议：**

将主指标改为 token 预算及其占用比例；字符数可作为辅助信息保留，但应明确标注为内容长度，不要把它当成预算上限。若预算估算存在不确定性，应使用“估算”措辞。

**验收标准：**

展示口径与请求构造使用同一预算来源；切换模型后预算上限同步变化；发生截断时明确说明截断依据和结果。

### P2-05 语音状态文案存在多套表达

**位置：** src/features/voiceRecall/VoiceRecallWorkspace.tsx，状态文案与主控制文案；相关状态复制配置

**现状：**

同一状态存在“正在听”“自动听说中”“准备自动听说”等不同说法。它们分别出现在顶部状态提示、主按钮和交互提示中，但没有明确区分状态、动作和下一步操作。

**影响：**

用户难以判断当前系统是在录音、等待输入、处理回复、播放语音还是准备下一轮。动态语音界面尤其依赖稳定的状态命名，文案不一致会放大状态理解成本。

**建议：**

建立统一的状态词表，分别定义：当前状态、主按钮动作、辅助提示和错误说明。相同状态在不同位置可以有长短版本，但核心词应一致。

**验收标准：**

所有状态均能映射到唯一的内部状态和统一核心文案；按钮文案描述将要执行的动作，状态标签描述当前正在发生的事情。

### P3-01 暗色通话主题已定义但不可达

**位置：** src/features/voiceRecall/VoiceRecallWorkspace.tsx，约第 200 行；语音复述样式中的 [data-call-palette="dark"] 及 .vr-call-palette-toggle

**现状：**

callPalette 状态固定为 bright，没有可用 setter，也没有 JSX 使用调色板切换控件。但样式表已经包含暗色配色和切换按钮样式。

**影响：**

代码和样式之间存在不可达功能，增加维护成本，也会让后续开发者误以为暗色主题已经可用。

**建议：**

如果暗色通话主题属于当前产品范围，应补齐切换入口、持久化边界和无障碍状态；如果不属于当前范围，应删除不可达状态和未使用样式，避免半成品继续扩散。

**验收标准：**

暗色主题能够从可见入口启用并在刷新后符合既定持久化策略；或完全移除不可达实现，并通过静态检查确认无死代码残留。

### P3-02 reduced-motion 状态没有实际来源

**位置：** src/features/voiceRecall/VoiceRecallWorkspace.tsx，约第 203 行；src/features/voiceRecall/VoiceRecallPresentation.tsx，波形组件参数

**现状：**

reduceMotion 固定为 false，但样式层已有系统级 prefers-reduced-motion 兜底，波形组件也接收该参数。

**影响：**

当前不一定造成明显功能错误，但组件参数表达的控制能力与实际行为不一致，容易导致未来修改时误以为应用层已经正确读取用户偏好。

**建议：**

明确 reduced-motion 的单一来源：要么由媒体查询或统一 Hook 提供真实值，要么移除无效参数并完全依靠样式层。保留两套机制时，应定义优先级和测试边界。

**验收标准：**

系统开启减少动态效果时，波形、过渡和动态提示均符合预期；系统关闭时不影响正常动画；组件参数和实际行为含义一致。

### P3-03 “新消息”提示可能随字幕内容滚走

**位置：** src/features/voiceRecall/VoiceRecallPresentation.tsx；相关语音复述样式中的 .vr-new-messages

**现状：**

新消息提示位于字幕滚动容器内部，并使用 align-self: center 定位。随着字幕内容增加和容器滚动，提示可能跟随内容一起滚出可视区域，而不是保持在用户可发现的位置。

**影响：**

用户可能错过“有新消息”的提示，尤其是在手动查看旧字幕时。提示的定位行为与其作为导航辅助控件的预期不一致。

**建议：**

将提示放在滚动容器外层并采用稳定的覆盖定位，或在明确的滚动锚点区域显示。需要同时处理窄屏、底部安全区和键盘出现时的布局。

**验收标准：**

用户滚动离开底部后收到新消息时，提示始终可见且可操作；点击提示可以回到底部并清除提示；用户已经在底部时不显示多余提示。

### P3-04 start 视图使用了不属于语音复述体系的全局提示样式

**位置：** src/features/voiceRecall/VoiceRecallPresentation.tsx 的 start 视图；src/styles/components.css 中的 .status-message

**现状：**

start 视图使用全局 .status-message，而语音复述其余界面主要采用 vr-* 前缀的局部样式体系。

**影响：**

在主题、间距、响应式行为或错误展示策略发生变化时，start 视图可能与语音复述其他状态产生不一致。全局样式还可能受到其他页面规则影响。

**建议：**

将该提示迁移到语音复述专用样式命名空间，或确认全局样式确实是跨页面稳定契约，并为其添加针对语音复述状态的回归覆盖。

**验收标准：**

start 视图在亮色、暗色、桌面和窄屏下与其他语音复述状态保持一致，且不受无关页面样式变化影响。

## 五、问题汇总

| 等级 | 数量 | 主要风险 |
| --- | ---: | --- |
| P1 | 5 | 知情使用、真实信息展示、数据删除、模态无障碍 |
| P2 | 5 | 事件竞态、空交互、键盘反馈、预算口径、状态理解 |
| P3 | 4 | 不可达功能、配置一致性、提示定位、样式边界 |
| 合计 | 14 | 需分阶段修复并回归验证 |

## 六、建议修复顺序

1. 修复字幕按钮的 aria-pressed 绑定，确保视觉和语义状态一致。
2. 在通话主界面展示实际发送资料范围，并与请求上下文使用同一数据源。
3. 接入真实累计时长，覆盖暂停、继续和结束场景。
4. 完善详情抽屉和离开确认面板的焦点、Escape、焦点归还和键盘循环行为。
5. 为历史删除增加确认或可验证的撤销机制。
6. 统一 Push-to-talk 的事件路径，并补充鼠标、触摸、键盘和失焦回归测试。
7. 修复 token 预算文案和状态词表，避免界面继续使用过时或含义不清的口径。
8. 删除或补全空的“更多设置”入口，补充字幕滚动区焦点样式。
9. 处理暗色主题、reduced-motion、新消息提示和 start 视图样式边界。

## 七、专项回归验收

### 7.1 状态与通话控制

- 自动模式、点按录音、按住讲话三种模式均可开始、暂停、继续和结束；
- 每次录音只产生一次停止事件和一次转写提交；
- 指针取消、触摸结束、键盘释放、窗口失焦不会产生重复提交；
- 通话时长在暂停期间冻结，继续后正确累计；
- 通话结束后最终时长、转写内容和回复内容保持一致。

### 7.2 上下文与预算信息

- 通话主界面能够看到本轮资料范围摘要；
- 详情区域与主界面的资料范围来自同一状态源；
- 切换模型或资料范围后 token 预算同步更新；
- 发生上下文裁剪时，界面明确说明估算、预算和裁剪结果；
- 不存在把字符数误显示为模型预算上限的文案。

### 7.3 无障碍与键盘

- 字幕开关的视觉状态与 aria-pressed 始终一致；
- 所有可聚焦控件都有可见的 :focus-visible 状态；
- 模态打开时焦点进入面板，Tab 循环在面板内部；
- Escape 对可关闭面板有效；
- 面板关闭后焦点回到触发控件；
- 屏幕阅读器能区分当前状态、可执行动作和错误信息。

### 7.4 历史与删除

- 删除历史前有明确确认；
- 取消删除不会修改数据；
- 删除成功有反馈；
- 若提供撤销，撤销可恢复完整历史条目，而不是只恢复列表标题；
- 本地历史数据边界在界面上不会被误认为已同步或已备份。

### 7.5 响应式与视觉一致性

- 桌面和 Android 窄屏布局均无按钮、字幕、提示和键盘区域重叠；
- 新消息提示在用户离开底部时保持可发现；
- start、通话中、暂停、错误和结束状态使用一致的语音复述样式体系；
- 暗色主题若保留，入口可达且状态清楚；若不保留，不应留下不可达样式和状态。

## 八、最终审计结论

当前语音复述界面具备继续使用和修复的基础，但在信息透明度、时长真实性、删除保护、模态无障碍和状态一致性方面仍有明确缺口。

本次审计结论为：**有条件通过，暂不建议作为完全收口版本发布。**

完成全部 P1 问题修复，并至少完成 P2-01、P2-04、P2-05 的专项回归后，可进入下一轮发布级复核。P3 问题应在后续维护窗口中完成清理，避免半成品状态继续扩大维护成本。
