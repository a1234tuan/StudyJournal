## 按优先级落地

### P0 / F-2：计划回收不得覆盖新状态

- storageAdapter.reclaimEmptyPlanRecords 的计划扫描、候选计算、日志判空、删除及关联修正全部在同一 Dexie 读写事务中执行。写回不再使用事务外的计划副本。
- 保留已删除计划的删除标记与现有字段；回收前关联已改变时不能清空新关联或覆盖新标题。
- 保留 skipRecordIds、草稿、有效复习与内容判空保护；业务写入和 mutation 回滚仍为原子操作。
- 回归包含两个独立命名数据库/独立 ledger 的双向同步、进入回收事务前拉取删除、重关联/改标题以及写回失败回滚。修复前独立复核已复现删除复活和新关联被覆盖。

### P1 / F-1：普通保存不能隐式恢复删除计划

- saveDailyPlan 在事务内读取到已删除行时拒绝保存。拒绝不改时间戳、不增 mutation、不产生上传。
- 当前页面没有既有计划的编辑保存入口，因此不沿用原报告描述的页面复现；这是存储接口边界防护，不新增编辑/恢复功能。

### P1 / F-3：过期保存和草稿失败必须给出真实指引

- 普通日志与决策块日志事务均抛出 StaleRecordError，保留 stale-record 语义及原有严格版本校验。
- uiError 仅为该已知错误渲染固定中文指引，不透传底层异常消息；编辑器 catch 仍通过 formatUiError。
- 草稿 flush 返回实际写入结果。失败/未写入不再宣称已存于本机草稿，而提示勿关闭页面、先复制保留内容。
- 页面测试覆盖事务级拒写后保留原 baseUpdatedAt、不删草稿、草稿补写失败以及错误消息不泄露。提前检测到远端变化的既有保护继续保留。

### P1：修复白盒测试自身的假通过

- W-07 改为结构化查询记录，head+1 负对照与修订缺口两次 limit(1) 查询正对照共同断言。旧字符串过滤条件无法识别实际查询，不能作为开销证明。
- W-01 的首个断言修复后暴露出此前未执行到的错误期望：A 尚未拉取人工放入远端的三个实体，首次 downloaded 应为 3，不是 0。现在在 A/B 都接收后断言连续同步零上传/下载且没有新增写入或查询。
- W-25 从未经确认的自动自愈期望改成明确的拒写契约，并新增公共恢复入口拒绝损坏快照、有效备份修复本地损坏、正常删除级联清理验证。

### P2：低风险防御与维护

- 普通实体 deleted=true 时，仅保留含 id 和非空（去空白后）deletedAt 的软删除载荷；空删除标记不能被恢复为存活记录。有效软删除与 bare tombstone 语义不变。正常客户端产生空标记的路径仍未证实。
- 删除 persistLedgers 未使用的 revision 参数；保留实体自身 revision、完整数据集进度与实际拉取游标三者区别，定点核对不推进拉取游标。
- 删除过时的“下一次自动重新上传”注释。没有删除元数据开始前的超时保护。
- F-4 的生产拒写行为未改变，不引入自动清理正式验证链。

## 原报告勘误

1. 原报告列出的 47 + 162 + 42 实际是 251 项、246 通过、5 失败，不是 209 项、204 通过、5 失败。
2. F-3 实际编辑器使用 formatUiError；原先两种错误都会变成通用提示，单改 ActionableError 不足以修复。
3. F-4 不等于没有任何恢复入口：非法快照在写入前被拒绝，正常日志删除会清理关联验证，有效备份可替换已损坏的本地关联。没有确认正常业务产生该悬空状态的路径。
4. W-10 所称元数据开始前超时“不可达”错误。大文本/附件 Storage 检查或上传位于 metadataStarted=true 前；新增大文本检查超时桩验证 metadataBatches=0 且操作仍进入 uploading/unknown。该保护不可删除。
5. W-02 的实测是指定 null/缺失载荷没有阻断有效记录拉取，原报告“证明一旦发生就会失败”的句子与其通过结果相反。
6. W-05 只验证特定旧操作核对场景，不证明所有异常远端状态/并发下账本绝不回退。
7. F-5 用例使用完整记录载荷，不证明会出现没有标题的空记录。旧客户端产生这类载荷也未有样本。
