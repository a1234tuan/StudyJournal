# Android UI/UX 重构方案：恢复移动阅读感，隔离桌面工作台

日期：2026-10-10。状态：分析与建议，未实施，等待方案确认。

实施更新：用户随后批准实施，代码与定向验证、候选APK已完成；实际范围和未完成的真机门禁见同目录 android-ui-ux-implementation-2026-10-10.md。下文保留为批准时的方案，不作为当前完成状态。

## 1. 决策与范围

采用「旧版移动视觉择优恢复 + 移动表现层独立重构」。不整库回退，不另造一套业务，不改已验收的 Desktop 外观。

这不是把现在的页面全部缩小，也不是只换陶土色。恢复的是旧版干净底色、明确分组、克制导航、阅读比例；重构的是手机的信息次序、任务工具栏、底部操作和系统栏边界。

保留全部现有业务：日志/草稿/附件、普通与已安排复习、评分与进度、批注、学习助教、语音、知识库引用、AI 问答、备份与同步。不得改数据库、云协议、评分算法、学习事实、账号、应用标识或生产安装数据。

本轮只读取源码、历史与用户截图，新增本方案；未修改业务或样式，未运行测试、构建、安装或提交。

## 2. 证据与根因

### 2.1 已确认：桌面表现规则直接影响安卓

`src/main.tsx:13` 起导入共享样式，其中 `visual-v2.css`、`content-first.css`、`workspace-layout.css` 全平台加载。并非所有规则都不区分屏宽，但平台边界主要依赖媒体查询，未建立完整的移动表现契约。

桌面内容优先设计本身没有错；把同一空间分配方案折行后用于手机，才是问题。UI 服务于宽屏浏览和触屏单任务时，应共用业务而非强求同一布局。

### 2.2 已确认：今天页是桌面右栏直接下放为双列

`src/styles/content-first.css:49` 为桌面学习侧栏，`:92` 在窄屏改为下方两列。复习摘要和目标日期因此并排，占据各一半手机宽度。目标区 `:60` 本身还是网格。

截图直接表现为：上方新建/下拉/计划/收藏挤在一起，中间空状态面积大，下方复习文案拥挤而日期纵向散开。目标区自动拉伸是值得在真实 DOM 中测量的原因，具体高度还没有浏览器复现确认。

结论：不是简单「字太大」或「留白太多」，而是重要内容被挤窄，低价值区域反而占空间。

### 2.3 已确认：底部导航是新旧样式叠加

`src/styles/components.css:361` 设置胶囊圆角，`:369` 给选中项内描边阴影；`src/styles/visual-v2.css:443` 只将选中背景变透明并改颜色，没有清掉内描边。于是截图出现大椭圆轮廓，不能简单归因于手机系统绘制。

这也说明继续在文件末尾零散覆盖会反复产生残留：一条规则清背景，另一条留下阴影、圆角、固定高度。

### 2.4 已确认：普通复习未进入现有沉浸任务态

`src/App.tsx:2065` 的沉浸态包含已安排卡片、编辑、部分助教任务及语音通话，但未包含普通日志复习队列。`src/styles/layout.css:24` 已具备隐藏全局导航的沉浸能力，所以不需要再造一套沉浸框架。

`src/styles/workspace-layout.css:62` 将非沉浸复习评分/批注条抬到全局底栏上方；`:71` 又将窄屏工具与进度分行。截图因此同时存在四模式 Tab、会话动作、进度、正文标题、评分栏、全局导航和系统导航。

每一块都可工作，但它们同时存在时，阅读区被夹在中间。仅压缩间距无法根治。

### 2.5 已确认：主题与系统外壳没有完整联动

`src/styles/visual-v2.css:1` 起定义的新视觉 token 与阅读字体影响多端。暖灰底、绿色、细边线和紧凑控件在桌面成立，不等于手机也成立；阅读衬线不应无差别覆盖导航与工具。

`android/app/src/main/java/com/noteproject/study408/MainActivity.java:9` 的启动逻辑固定系统栏颜色为 RGB(247,244,238)，固定浅色背景对应的图标模式，并调用 `setDecorFitsSystemWindows(true)`。这里未按应用主题同步，存在深色/现代主题外壳不一致风险。不能据此断言所有设备都发生遮挡，也不应为了外观直接关闭系统安全区处理。

### 2.6 已确认：窄屏浏览器验证不能替代 APK 验收

`playwright.config.ts` 的 `android-narrow` 是 localhost Chromium 的 Pixel 7 设备模拟，不是 Android 原生 WebView。它能验证页面尺寸与交互，但不能证明系统栏、中文输入法、Android 返回和真实字体观感合格。

之前的测试通过不等于本轮手机设计已经验收；无溢出和按钮能点也不等于布局舒适。

### 2.7 证据边界与历史参考

用户提供的当前截图覆盖今天、复习；三张旧拼图覆盖更多、主题、计划、知识播客、语音、助教、日志阅读、设置。不能据此声称逐页检查过所有当前 Android 界面。

旧图内的日期不能证明安装包版本。`fc723af`（2026-09-26）与 `04bd021`（2026-09-27）可作为历史样式检索候选；新工作台主要相关提交包括 `91867d0`（2026-10-10）。它们只用于只读比较，不执行整体 revert，也不把旧目录覆盖到生产。

新旧截图的像素尺寸、字体设置和设备可能不同，字号结论必须同设备、同系统/APP字号、同数据复核，不能按拼图像素比较。

## 3. 移动视觉方向

### 恢复

- 明亮暖白/中性白底，内容与分组有轻层次，而非大面积灰米色铺满。
- 更多、设置、任务选择采用分组行或轻卡片。卡片用于归组，不给每句话都加框。
- 克制的图标、色彩与选中标识，去除底部大椭圆描边，保留文字标签与既有新建入口。
- 日志以正文为中心，标题有层次但不挤走首段；公式、代码、图片、折叠块沿用真实渲染能力。
- 安卓温润阅读恢复暖白与陶土强调的辨识度，清爽现代保留中性底与绿色；仅调整移动表现，不改 Desktop 主题。

### 不恢复

- 每页的大英文眉题、大说明段和重复标题。
- 旧版所有控件、所有路由或过时操作入口。
- 整屏装饰插画、营销式欢迎区、模拟数据、无行为的样稿按钮。
- 通过缩小所有文字、降低触控面积或禁用字体缩放来塞内容。

### 基础规格（设计起点，需真机校准）

- UI 工具与导航统一无衬线；阅读区保留阅读主题与用户字号设置。
- 单列主内容，横向留白初拟 16–20 CSS px；行距按正文与工具区分开设定。
- 轻卡片初拟 12–16 CSS px 圆角，单个图标图形较小而可点区域充分；主要触控区初拟不小于 48 CSS px，需结合 WebView 缩放与系统字号实测。
- 页面标题通常融入一行应用栏；详情展示返回，一级入口不凭空增加返回。
- 同一任务底部仅一个主要操作区，统一管理导航、安全区和键盘占位。
- 不把这些 CSS 数值视作物理 dp 认证；最终以目标设备可读性、误触和安全区结果为准。

## 4. 页面落地策略

### 今天

推荐顺序：轻量应用栏 → 紧凑记录入口/今日计划 → 有待复习时的单张复习摘要 → 今天日志列表。目标日期降为一行弱信息，不再与复习组成两列。

新建学科入口继续使用现有选择与创建逻辑；收藏、搜索、同步不删除，但不都做成同权重大按钮。复习摘要合并重复到期/逾期文案，保留真实数量和开始入口；没有待复习时不强行占据首屏。空日志状态短而可操作，不留一张无内容大卡。

### 复习

明确区分「选任务」与「正在做任务」：

- 入口/卡片库：保留四模式的发现路径与全局底部导航，允许适合触屏的选择布局。
- 普通复习会话：顶部返回/会话名称/更多，紧邻一行简要进度；正文居中；底部单层评分区。
- 手机会话中收起常驻四模式 Tab 和全局导航；模式切换在明确入口中仍可到达，退出与切换调用原有守卫，不直接清空队列或批注。
- 批注为会话内主要动作，看板进入更多；批注模式替换评分区，不再叠加第三层工具。大字号可合理换行，不能裁掉按钮。
- 普通与已安排分别绑定原来的评分/勾选语义，不能为了统一视觉把两者合并。
- 若未提交批注或编辑存在，返回键和模式切换仍必须确认；不能因换布局绕过保存。

这是一项有交互影响的表现层调整，必须单独验证；不是只加 `display:none` 就算完成。

### 日志与编辑

手机采用单列索引；顶部简洁搜索/筛选，低频筛选在现有交互基础上收进面板。日期与全部日志切换保持工具栏位置一致，保留选择条件与滚动状态。

阅读使用单页内容视图，不复制 Desktop 三栏。手机打开日志不应还剩一条狭窄预览正文；返回回到原索引位置。编辑复用原编辑器和保存/离开守卫，不同时挂载两份编辑器或两份草稿状态。长公式/代码在自身容器中横向滚动，不带动整页横溢。

### 知识库

手机导图优先保留画布，工具少量浮置，低频项进入菜单。关联日志先用可展开的移动预览面板，短内容可直接查看；长文可明确进入现有完整阅读页。返回应恢复原节点、缩放、位置和来源状态，不把桌面固定宽度侧栏硬塞进手机。

面板与导图手势需分区域，避免上下拖动误触节点；复杂内容优先全高阅读，不堆叠多个底部面板。不改知识图谱模型、关联事实和引用身份。

### 更多、设置、计划与辅助页

更多/设置恢复按任务分组的图标行，设置值清楚，不用横向桌面按钮墙。计划保留真实任务卡和完成动作，新增区域不长期占满首屏。分类、录音、模板、统计、搜索、收藏、备份和同步等逐一纳入页面清单，不能因不是主页面而遗漏。

### AI、语音与学习助教

AI 手机主界面以对话和输入为主，历史列表按需打开；仅桌面保留常驻历史侧栏。用户文字清晰，触屏的复制通过明确菜单/既有可访问操作到达，不依赖 hover。输入法弹出后最后一条消息与输入区可见。

语音区分准备、通话、恢复状态；保留已有合法恢复判断，不无条件露出「继续通话」。助教以当前任务为核心，播客以可播放条目为核心。所有流式输出、录音、媒体后台行为与 provider 调用保持不变；布局验收不自动触发付费服务。

## 5. 技术接入：独立表现，不复制业务

1. 复用 `src/lib/platform.ts` 的宿主判断。分别表达宿主（Android/Desktop/Web）与布局能力（窄屏/宽屏/触控），不用 UA 字符串，也不把所有小于 920px 的窗口视为 Android。
2. 启动首屏前建立稳定的表现标记，避免先出现桌面再切手机；Android 平板保留触控规则，窄 Electron 仍保留桌面宿主外壳，手机 Web 则复用适合它的紧凑布局。
3. 保留共用语义 token、阅读渲染与控件行为；新增明确移动主题/壳层/页面规则，并逐页把桌面专属规则限定作用域。不是一次禁用整个 `visual-v2.css`，否则公式、阅读、弹层也可能退化。
4. 必要时拆移动工具栏/面板等小型呈现组件，共用回调、数据与路由。不要通过隐藏两套大 DOM 来实现平台分离，以免重复订阅、请求、焦点和保存。
5. 显式处理残留 CSS 属性，包括阴影、圆角、边框、min-height、grid、position 与底部偏移；避免继续堆叠无归属的覆盖和 `!important`。
6. Android 系统栏颜色/图标由主题统一协调；系统 inset、Web safe-area、底栏和键盘高度应各有单一责任来源，先测量再改，不盲目叠加 padding，也不为视觉直接改 edge-to-edge 策略。
7. 路由、退出守卫、回到来源和焦点恢复列入表现组件契约。宽度/旋转变化不得销毁编辑草稿、复习进度、导图位置或语音会话。

## 6. 分阶段实施与门禁

### P0：锁定基线和行为清单

产物：同设备、同字号、同数据的今天/复习/日志/设置新旧对照；现有页面及入口清单；Desktop 已验收截图基线；历史样式可恢复项映射。记录 Android/WebView、导航方式、主题和字号。

验证：所有入口归属和任务状态覆盖明确；设计稿使用真实组件/隔离测试数据，不增加假功能。此阶段不打包、不跑全量，不碰用户正式资料。

### P1：隔离移动表现与基础外壳

实施：平台/布局标记、移动 token、应用栏与底栏、字体分层、弹层基础规范、系统栏与键盘边界。

验证：定向平台/壳层测试、主题截图、Desktop 关键截图；在可用隔离 Android 测试实例上做一次原生调试冒烟，提前确认安全区/输入法/返回键。无实机条件必须记录缺口，不以浏览器模拟冒充通过。不得覆盖用户正式安装或资料。

### P2：今天与复习先形成移动基线

实施：今天改单列任务流，复习做入口/专注态分离，整合重复摘要与操作层。

验证：空/非空日志、0/78条待复习、长标题、长公式、大字号；评分只写一次、退出恢复、批注守卫、看板、模式切换、普通/已安排不混淆。对照真实移动截图检查首屏主内容，不只检查 scrollWidth。

### P3：日志、阅读、编辑与工具页

实施：列表筛选、单页阅读、移动编辑工具，更多/设置/计划/分类/资源等分组布局。

验证：列表定位恢复、搜索筛选保持、编辑保存和取消、未保存返回、附件/公式/折叠块、键盘遮挡；按本阶段改动执行一次相关组件与浏览器测试。

### P4：知识库、AI、语音与助教

实施：移动画布与引用预览、对话历史入口、键盘输入区、语音准备与通话层次。

验证：导图手势、打开引用后原位恢复、预览到完整阅读再返回、消息复制、流式渲染、录音权限/状态、返回守卫。使用 mock 或隔离数据；付费 provider 与真实账号不因 UI 验收自动调用。

### P5：集中验收与一次候选包

验证：一次与改动范围匹配的集成回归、类型检查和生产 Web 构建；基于同一收敛版本产出一次 Android 候选 APK，再做真机截图与关键流程验收。原生调试冒烟与发布候选各有目的，不在每阶段重复发布打包。Desktop 做关键路径/截图对照，不反复构建 Windows 安装包。

若出现问题，只修失败对应的表现层并重跑相关集合；仅当共用边界改变或发现更大风险才扩大回归。阶段门禁失败不继续向其他页面复制设计。用户最后验收的是 APK 真机效果，不是桌面浏览器样稿。

## 7. 集中验收清单

- 主要手机宽度 360/390/412 CSS px；320 窄屏、横屏及平板作边界测试。默认字号、放大字号及当前支持上限；两种主题的明暗表现与跟随系统。采用代表性组合，不做无意义全排列。
- 当前截图的78条待复习、空日志、长标题、日期、长公式、代码、附件、大量条目、离线和恢复态均有隔离样本。
- 无按钮错位、文字重叠、误裁剪、整页横溢或固定区遮住最后一段；控件看起来可以点击且实际可触达。
- 今天首屏能理解并执行主要任务；目标日期不占半屏；普通复习没有评分与全局导航双层挤压；不同模式工具栏不无故跳位。
- 手机返回/系统返回按既有语义退出，弹层先关闭，未保存有守卫；日志、图谱与筛选恢复原位。
- 中文输入法、手势/三键导航、主题切换、旋转与辅助阅读标签至少做真实宿主代表性验证；不能只凭截图判定这些行为正常。
- Desktop 的侧栏图标轨道/拖宽、三栏日志、知识库画布、复习和主题外观不被改变。
- 所有迁移或隐藏的入口都有明确替代位置；没有伪按钮、同一业务重复提交、取消原来能力或写错学习事实。

## 8. 风险和回退

最高风险不是调颜色，而是隐藏导航导致退出丢失、重挂载导致编辑/会话状态丢失、系统栏与键盘双重占位，以及全局 token 再次污染 Desktop。以上在对应阶段增加断言，不等最终 APK 才发现。

每阶段仅包含可独立审查的表现层变化。需要回退时撤销该阶段的移动 UI 修改；不回滚数据库、协议或10月已接受的功能修复，不向用户恢复旧数据备份。必要的原生系统栏变更独立成组。

本方案仍待用户确认，尤其是「安卓暖主题恢复陶土强调」「普通复习会话收起全局导航/四模式常驻栏」两项。当前无实现完成或真机验证通过的声明。
