## 当前产品约束

- 主链路仍是阿里云 ASR → 用户配置的 LLM（目标 DeepSeek）→ Fish Audio。豆包保持候选，未扩大接入范围。
- 桌面与 Android 使用宿主传输。Web 的能力限制不变；本轮没有建设中继服务。
- 手动结束录音 → 真实累计转写 → 用户校对确认 → LLM → 句级 TTS。默认点击录音，保留按住讲话；旧 auto-half-duplex 会话按手动模式恢复，不删历史。
- 90 秒提示、120 秒结束并进入转写，不自动提交 LLM。静音停止采集并保留之前的片段，取消静音不启动录音；打断只停止旧回复，不自动开麦。
- 用户保留的摘要不再按 200 条淘汰；savedAt 与 id 倒序稳定分页，每页最多 50 条。旧版本已删除的数据无法恢复。
- schema 21 的表和索引定义没有改变。仅增加可选本机字段；语音与批注继续不进入云同步、备份、知识导出或记录转移，不自动写入 FSRS。

## R1–R15 对应处理

- R1：teacherPrompt 接收 confirmedText，在历史之后追加唯一的当前用户消息，维持不可信学习内容标记。材料截断明确提示；短回复预算及关闭 thinking 保留。
- R2：Aliyun final 保留句子位置并去重；适配器输出累计文本，管线兼容旧的非累计事件。正式轮次分开保存 Provider 原文、用户确认文本及编辑标记。
- R3：运行时统一取消请求、采集与播放，操作代次使迟到回调失效；正式提交在事务内检查取消。取消后保留可编辑文本，未完成轮次不写为正式结果。
- R4：静音接通底层停止；Web 迟到授权释放轨道。Android 权限请求可取消，采集携带所有权标识，避免旧停止请求影响新录音。
- R5：生产管线由运行时持有；同进程重挂复用，运行时替换后以持久化服务身份与本机凭据重建。缺少身份、来源失效、凭据缺失或配置变化时阻止恢复，不换供应商；恢复保持暂停。
- R6：WebSocket 建连、task-started 分别 10 秒；finish-task 后最终结果 30 秒。失败、取消、异常关闭终止等待，中途失败不因已有 final 被视为成功。普通语音请求不自动重发。
- R7：评分清理在事务中递增 writeGeneration，保留空标记而不是 750ms 后删除。旧代次保存拒绝；撤回后打开空草稿，允许新笔迹。跨标签页及数据库重开已加入测试。
- R8：Electron 保留 string / Uint8Array；Android 显式 text / binary。发送失败可见，迟到打开会关闭，监听器先就绪再建连。桌面共享宿主发送函数与 Android 共享 OkHttp 发送函数分别通过本地真实 WebSocket 服务端帧类型测试。
- R9：教练生成、继续、提交答案传递真实 AbortSignal；任务切换和卸载中止，StrictMode 重挂新建 controller。回答与结果仍原子提交，事务中取消整体回滚。
- R10：新增 ASR 本机密钥输入与状态；LLM 与用户新建 Fish 配置按实际 profile ID 找凭据。相同 default 槽位歧义要求新建独立配置，不删除旧钥匙。异步密钥加载不覆盖编辑；服务身份变化重新披露。当前句级 TTS 不支持自定义端点，填写非官方端点会明确阻止启动，而非静默忽略。
- R11：用量按 operationId 保存累计观测快照，重放不重复相加；失败前已观测用量保留。会话、正式轮次、历史使用可选计量字段；旧零值无来源时显示“未记录”。ASR / LLM 报告值与 TTS 本机字符估算分开标记，字符估算不代表实际账单。
- R12：AI HTTP、原生错误、JSON/schema、配置及背景不足按可重试属性处理；只有明确可重试错误进入有界退避，支持可用的 Retry-After，取消打断等待。材料与评论截断标记明确，不把部分输入称为完整分析。
- R13：生成、质量审查、答案评估分别读取角色 timeout；请求参数与 signal 有正式测试。
- R14：移除主动保留历史的数量删除逻辑，新增稳定游标分页并测试相同时间戳下超过 200 条的无重复、无丢失读取。临时会话清理规则不变。
- R15：生产入口不再展示停顿自动发送；按住模式提示松开转写后确认。录音时限只触发转写，TTS 明确为句级合成播放。

## 本机配置与安全

1. 先在各供应商后台吊销并轮换曾贴入聊天的凭据。本轮没有执行账户操作，也没有使用这些凭据。
2. 在语音开始页填写轮换后的阿里云 ASR 密钥，保存到本机 voice-asr-aliyun 槽；“已配置”不等于已验证账户权限。
3. 在 AI 设置选定 DeepSeek profile 并保存该 profile 的密钥。在 TTS 设置新建或选择独立 Fish Audio profile，保存该 profile 的密钥、模型和音色。
4. 若 AI 与 TTS 都沿用同一个 default ID，必须为 TTS 新建独立 profile 并重新填写密钥；旧密钥不会被自动删除或盲目兜底使用。
5. 新密钥不得写入源码、测试、文档、日志、聊天、备份或同步数据。更换服务或外发配置后重新确认披露。
6. 本轮所有测试使用确定性假数据或本地服务器，live 测试显式排除；没有任何付费 Provider 验收授权。
