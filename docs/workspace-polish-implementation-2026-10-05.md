## 阶段一：普通复习进度与本机续接

### 行为

- 普通队列默认纳入全部当前到期记录，不再隐式截取前 20 条。
- 开始后固定本轮记录集合；后续出现的范围外到期记录通过“继续处理剩余”明确加入。看板选中范围仍单独成轮。
- 显示当前条目序号和已完成数量，填充比例使用已完成数，不再打开最后一条就满格；未完成时不会因四舍五入提前达到 100%。
- 独立已安排轮次也使用正式轮次事件计算已完成数，条目顺序不再充当完成比例。
- 普通本机断点仅保存版本、日期、记录 ID 集合、当前位置 ID 与选中范围标记。key 为 `studyjournal-ordinary-review-checkpoint-v1`。
- 恢复时从正式 review state 的当前本地日期评分事实重新计算完成数，按原始集合顺序续接第一张未完成卡片。未提交的乐观 UI 跳转不能伪造完成数。
- 损坏版本／重复 ID／过期日期断点不使用；恢复时移除已删除、退出复习或不再属于本轮有效状态的卡片。
- 已完成本轮可以在同一天重启后仍显示完成数。跨天开启新一轮。
- 评分撤销栈保持 App 内存语义，不写 localStorage、Dexie、备份或同步。跨重启不恢复旧撤销令牌。
- 本机读写失败显示说明，不把正式评分失败和导航断点失败混为一谈。
- App 订阅现有恢复锁：进入受该锁保护的备份恢复时，同步清除断点和内存队列。普通实时同步未改协议；重启恢复仍以实际正式 review state 为准。

### 恢复时序回归

集中浏览器检查发现，`PageTransition` 会短暂持有旧 props；局部 ready 状态先变为 true 时，旧 props 会把刚恢复的集合重新初始化成“剩余队列”，出现 25 条评分一条后重启显示 0/24。

最终实现等待恢复的运行状态回传，并在初始化缺失进度时纳入已恢复的完成集合。新增真实 `PageTransition` + `StrictMode` + 受控父状态单测；桌面和 Android-narrow 的 25 条、评分、撤销、再次评分、reload、同卡续接与恢复锁失效用例均通过。

这里恢复的是条目进度，不新增学习时长计时器，也不保存浏览器关闭期间的时间。

## 阶段二：专题导图全屏

- 原“查看全貌”拆分为“适应画布”和“全屏显示／退出全屏”。
- 全屏为应用内工作区全屏：隐藏全局导航、知识库页头和底部上下文栏，画布占满 viewport。
- 不调用 OS／浏览器原生全屏 API，不隐藏系统窗口标题栏。
- 保持同一个导图实例、缩放、选中节点与折叠状态；调整容器大小时仍保留原有节点可见性校正。
- 显式退出、Esc 和 `knowledge-back` 返回链路都可退出。编辑、弹窗、日志预览、详情等更内层状态仍优先按原规则处理。
- 切换专题／知识库／视图时退出全屏，不把该显示状态写成知识库事实。

## 阶段三：AI 问答工作区

- 桌面聊天页使用自己的历史侧栏替代全局导航，提供返回学习日志、新建问答、会话切换和独立删除按钮。
- 窄屏仍使用历史抽屉；其他页面的全局导航不变。
- 用户气泡删除“你”、头像和常驻“复制”文字；用户文本按原文和换行显示，已有图片附件保留。
- 鼠标 hover／键盘 focus 显示用户复制图标；触屏始终提供可操作的图标入口。
- 用户气泡背景及正文使用主题变量，不再继承旧蓝底方案的白字。
- AI 回答使用无气泡正文区，保留 Markdown、公式、代码高亮／代码复制和整条回答复制。
- 移除页面外框与上下分隔边框；回答和输入框共享居中阅读宽度，顶部操作区保持轻量。
- 会话列表复用已有存储，不增加新的聊天数据表。异步读取通过 generation 防止快速切换时旧读取结果覆盖新会话；生成期间禁用历史切换／删除入口。

## 用户验收

1. 专题切到导图，使用右下角全屏和适应画布；检查退出后仍在原专题／选中节点。
2. 用超过 20 条的普通到期队列，评分数条后关闭并重新打开；检查本轮总数、已完成数和下一张卡片。单独检查撤销后重启，不能把撤销的评分当成完成。
3. 打开 AI 问答：检查桌面左侧历史、用户字色和悬浮复制，以及 AI 正文的视觉占比。窄屏检查历史抽屉、输入键盘及复制操作。

自动化数据全部为隔离浏览器／测试数据库夹具。reload 和模拟返回事件不等同于 Electron 进程重启、Android 强杀恢复、物理返回键、真实键盘／IME 验收；这些仍需实际用户设备确认。当前已安装应用没有被替换。
