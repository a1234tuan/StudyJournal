# 工作区布局稳定性：根因定位与优化方案

日期：2026-10-10。状态：方案已实施并完成本轮定向门禁，等待用户体验验收；实施记录见 `docs/workspace-layout-stability-implementation-2026-10-10.md`。下文为实施前根因与计划快照，原生栏判断的更正见实施记录第2节。保持已认可的纸白/灰绿视觉，不回退重做，不改数据、同步、复习调度与 AI 业务。

## 1. 本轮证据与边界

使用临时隔离 Chrome 上下文、stage3 测试数据，在 1440×1000 与 390×844 观察实际页面；阻断外部 HTTPS。未使用真实账户、安装目录或学习数据，未重新构建、未跑全量测试。截图与测量在 output/layout-stability-audit-2026-10-10/。

测量在页面转场完成后读取 DOM 矩形；不是只根据 CSS 猜测。这里的窄屏是 Web，不能冒充 Android 原生状态栏验收。本轮未覆盖所有页面/字号/主题组合，未见问题的页面不能据此全部判定无问题。

上一轮的按钮可点击、目的页面唯一、前进后退可达等功能门禁，不包含跨页面共同锚点、首屏滚动归零和页头高度稳定断言。功能回归通过与这些体验缺陷可以同时成立。

## 2. 已确认根因

### R1：知识库抓手绑定错误的坐标与视觉形状

- src/features/knowledgeLibrary/knowledgeLibrary.css:2 固定 top:96px、left:186px；并没有相对可用工作区垂直居中。折叠后仅 left 变为 0。
- 1440×1000 下抓手中心 y=118，而屏幕垂直中心为 500。
- 按钮点击区 44×44；伪元素绘制约 28×34 的有框小面板，内部用 18px PanelLeftOpen/Close 图标。柜门感来自面板图标与外框组合，并不是点击区域本身应全部缩小。
- KnowledgeLibraryPage.tsx:387 将按钮 portal 到 document.body；它不会自然跟随导航布局边缘，需要统一外壳提供定位锚点。

### R2：日志二级 Tab 实际在切换两种外壳

- JournalPage.tsx:176 只在 libraryMode 时添加 journal-library-workspace。
- content-first.css:102 将这个模式设为 width:100%、max-width:none、height:100dvh、内部滚动；按日期模式退回通用 .page 的限宽及页面滚动。
- 桌面全部日志页头 x=208、宽1232；按日期 x=264、宽1120；标题和 Tab 同向横移56px。测量时滚动条占宽为0，不应把这次横移归因于滚动条。
- 窄屏学科筛选仅在全部日志模式挂载，flex-wrap 导致工具栏高121px；按日期为69px，内容起点相差52px。换成同样的外框宽度仍不能单独解决这一项。

### R3：共享 PageHeader 只统一了部分外观，没有统一页面外壳

- content-first.css:22 定义65px工作区页头，但 :30 特意让非今天/日志页头变成透明背景、横向padding为0，仍处于各页自己的限宽和留白之内。
- 更多页桌面页头起点(374,36)，今天(208,0)；知识库又是独立的 knowledge-header，起点(232,16)、高48。
- CategoriesPage.tsx:303 仍使用 section-header、英文眉题及大标题；设置使用紧凑 PageHeader。相同导航层级并未采用一致的标题层级和留白。
- 样式规则分布在 styles.css、layout.css、pages.css、visual-v2.css、content-first.css 和知识库样式内。现存通用规则、页面特例和后续覆盖共同决定结果；继续追加覆盖只会加重不确定性。

### R4：返回控件有多个所有者，并改变正常文档流

- App.tsx:2084/2160 按平台、页面深度和例外名单决定是否在 PageTransition 前额外插入 web-navigation-back-row；知识库、编辑器等又自己渲染返回控件。
- 设置页在桌面额外插入56px返回行，页头从更多的y=36变成y=92；390 Web 下插入54px，设置页头文档坐标y=78。
- 分类详情返回在自己的右侧动作区；知识库返回在左侧页头；复习返回放在session chrome。位置、边框、留白和点击尺寸来自不同选择器。
- 原生平台不显示这条 Web 返回行。因此既有Web桌面差异，也有Web/原生端差异；不能只测试一端后宣称统一。

### R5：复习的同级视图切换隐式切换任务布局

- ReviewPage.tsx:943/1037 在有当前复习卡的queue模式同时卸载页头和四个视图入口，改用review-session-chrome；卡片库再次挂载页头和Tab。
- visual-v2.css:443 将常态宽度设为980，:478附近将桌面复习会话宽度改为1040。
- 桌面卡片库正文左边界374、宽900；复习会话左边界344、宽960。切换本身带来30px横移，并且顶部结构也被更换。
- 390下卡片库页头高约66.8、Tab高81、列表起点约193.8；进入队列后只剩y=12、高48的会话栏。窄屏还进入既有沉浸态，底部导航消失。它不是普通的内容换页，而是多个布局状态同时翻转。
- motion.css 的页面前进/后退横移、正文section-enter的8px纵移会放大突变感，但不是宽度与页头变更的根因。不能用更长动画遮盖结构问题。

### R6：前进导航继承上一页的滚动位置

- App.tsx:438 的默认nextScrollY是window.scrollY；:521的openMoreSubRoute没有显式设置scrollToTop。
- 在390宽的更多页滚动到200再点击设置，设置稳定后scrollY=137（被新页面可滚动高度截断），h1顶端=-37.1px；等待1秒仍不恢复。标题实际跑到可视区外。
- 必须区分：首次前进到新工具页从顶部开始；返回列表恢复之前位置；已有Tab内状态及日志侧览保持。不能全局加无条件scrollTo(0,0)，否则会破坏已验证的返回与侧览体验。

### R7：原生系统栏与页面工具栏属于不同层

- Android MainActivity.java:23–28 固定浅米色系统栏和深色图标，并使用decorFitsSystemWindows。未发现按业务路由动态改变系统栏的实现。
- 页面工具栏的不同背景/留白已被实测确认；深色主题下原生栏颜色不跟随是源码层面的待核实风险，不应声称已复现Android刘海栏路由闪烁。
- Web中的safe-area与原生已消费的insets需要分别核对，禁止为所有页面重复加顶端安全区。

## 3. 建议采用的统一契约

不是把所有内容做成一样宽，而是让外壳固定、内容按任务适配。

### A. 抓手

- 展开时锚定侧栏右边缘，折叠时锚定内容左边缘；相对可用工作区垂直居中，随窗口高度更新，不再用96px/186px魔数。
- 可见部分改为约4×28px的低对比竖条，悬浮/键盘聚焦时增强对比并提示“收起导航/展开导航”；去掉柜门形SVG和面板外框。
- 保留44×44的透明点击区及aria-expanded、键盘操作；不因视觉变细而变得难点。弹窗/全屏时隐藏或降层，避免抢焦点及遮挡操作。
- 折叠后的点击区靠左但不得截断，也不能遮挡节点或编辑控件；真正导图全屏仍是独立行为。

### B. 稳定页头和内容边界

- 建立单一工作区页头契约：沿用已验收的65px基础行高、纸白/深色对应背景、细分隔；桌面水平间距统一24px，窄屏16px。具体参数可在实施首阶段成组确认，不逐页漂移。
- 左侧固定返回槽/当前位置，右侧动作槽；没有返回的根页面不显示假按钮，不用额外空白行占位。
- 页头铺满内容外壳，正文可以分别限宽：阅读页约900–960、设置表单更窄，知识库/日志工作区充分利用剩余宽度。限制正文不再连带挪动页头。
- 一级标题与按钮使用同一字号/图标/点击尺寸。标题过长截断并可查看完整名称；不靠任意换行改变整个顶部高度。
- 常规字号下稳定65px；大字号/缩放下允许受控增高，绝不为了固定高度裁掉内容。布局测试比较同一字号下的稳定性。
- AI、完整编辑器、真正全屏导图保留任务专属布局，只适配顶部/返回契约；不强迫全部套普通表单模板。

### C. 返回按钮

- 用一个轻量返回控件接管视觉，左箭头加“返回”或既有明确目的地，统一左侧槽位、图标16–18px、点击区至少44px；避免额外有框大返回行。
- PageHeader可接收现有返回回调或slot；知识库独立工具栏复用该控件。不另写一套“所有页面都返回更多”的路由逻辑。
- 每次迁移一个页面后才移除其全局返回行；旧页面保留兼容路径，最终仅在已迁移工作区清除冗余入口。
- 浏览器Back、Android Back、编辑离开保护、知识库来源返回都必须继续走现有导航契约。

### D. 日志与复习Tab

- 日志两模式共用同一外壳、页头、Tab坐标和工具栏基础高度；日历的阅读限宽只放到内部，不再缩整页。
- 窄屏保留一行稳定Tab与主要操作；全部日志的学科下拉收为“筛选”按钮弹层，日历的月份导航留在日历内容区。保留筛选能力与记忆，不为对齐放假控件或大块空白占位。
- 复习默认工作区内的日志复习/卡片库/助教共用顶部与同一正文最大宽度；切Tab只更换下方面板，不再自动卸载整个导航框架。
- 复习卡正文仍享有主视觉，进度及评分保留各自位置。已有独立训练、语音任务和导图全屏是另一种明确任务状态，不与同级Tab混同；本轮不新增专注模式功能。
- 队列页不因条件挂载而失去回到其他视图的稳定入口；窄屏是否保留底部导航按“普通工作区/独立任务”判定，不按“当前是否恰有卡片”随意跳变。
- Tab换页不做横向位移；先固定几何，再仅对内容做轻淡入。返回/前进的动效不带动共享页头，尊重减少动态效果设置。

### E. 滚动与原生栏

- 将导航的滚动意图明确为首次进入置顶、返回恢复、原位保持。只修首次进入更多子页的默认错误；保持浏览历史、日志筛选/列表/侧览、知识库缩放及复习状态。
- 避免把所有页面一次改成内部滚动；先按既有滚动容器做局部适配。日志同级模式共享的框架与滚动恢复需一起验证。
- 原生状态栏按主题和宿主能力处理，不跟每个业务页面重复切色。安全区由一个明确层级消费，宿主适配单独门禁，不以Web模拟代替。

## 4. 最小风险实施顺序（待授权）

### 阶段1：抓手与日志稳定性

改知识库抓手定位/形状、日志共享外壳和窄屏筛选布局。保持侧栏折叠状态、日志业务和预览历史。集中补验抓手居中、两Tab锚点/工具栏高度、筛选保留、列表→侧览→完整编辑→返回及无溢出。

### 阶段2：公共页头与返回收口

先将更多、设置、分类管理接入，再适配知识库和复习。统一页头几何与返回槽，移除对应页面外置返回行及相冲突旧CSS。只改变呈现组件，回调/源页面/历史栈不改。

### 阶段3：复习切换与滚动契约

固定复习工作区页头、Tab和内容边界；清晰区分普通视图与独立任务。修首次前进继承滚动，同时保留返回恢复与离开守卫。针对有到期卡、空队列、最后一张、助教、语音、安排复习、未保存注释等状态补验。

### 阶段4：宿主边界及集中收口

核对Web/Electron/Android顶部归属与安全区。原生栏若需修正，独立小改并做实际宿主检查；无法运行真机时明确未验证，不宣称通过。最后统一跑一次相关回归和一次生产构建，不循环全量测试或反复打包。

## 5. 新增验收标准

- 同一工作区的Tab切换，共享页头/Tab/正文框架横坐标变化≤1CSSpx，常规字号基础工具栏高度不变；不要求不同内容本身等高。
- 抓手中心相对可用工作区垂直中心误差≤1CSSpx；展开、折叠、窗口缩放和全屏的锚点正确。
- 更多滚动后首次进入设置等工具页，首屏标题可见并从顶部开始；返回更多恢复原滚动；浏览器前进后退与应用内返回均实测。
- 返回控件每页只有一个当前主入口，键盘焦点可达、禁用状态正确，返回目的地不变；保护有草稿/注释的离开流程。
- 默认主题重点验证1440与390；对920断点两侧、1024和320做几何专项，不笛卡尔积重跑全部业务；补深色、长标题及字体放大。
- 测稳定帧与转场中间帧；既验证不重叠、不横向溢出，也验证没有结构跳变。单纯“按钮能点击”或最终截图不够。
- 验证仅使用隔离数据。每阶段改动收敛后跑对应小集合；失败只针对修复影响补验，最后只做一次整合构建。无提交/推送/安装/生产部署的隐含授权。
