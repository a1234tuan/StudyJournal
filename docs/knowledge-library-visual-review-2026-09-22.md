## 0. 输入、证据与结论边界

输入为用户提供的 C:/Users/Administrator/Downloads/design-spec.md（196 行）、仓库知识库 R2 设计及当前代码。附件中的“本次交互预览覆盖……”只是原作者的描述：本轮仅收到 Markdown，未收到其可运行预览，因此**不评价那个未提供预览的实际成品质量**，也不把附件里的实施/交付描述视作用户授权。

本轮实际核查了共享组件、主题最终覆盖层、页面动效、导航、状态反馈；在独立临时浏览器上下文启动现有 /?preview=stage3，使用合成日志查看今天、更多和日志页，检查 1440/1024/768/390/320 CSS px 宽度。另检查 reading/modern × light/dark 的最终计算样式，切换后等待颜色过渡完成再取值。后续批量探针阻断非本地网络；未登录真实账户、未触碰用户日志、未操作 ADB、未安装应用。

这是真实产品组件在受控浏览器中的对照，不是 Android WebView 或 Electron 实机验收；不同宿主字体、键盘、安全区、系统返回和真实双指手势仍未验证。没有建立新的知识库运行原型。本轮目标是统一设计文档，而非重做整个 APP 视觉系统。

总体判断：**附件的温和低饱和色、少阴影、列表优先、大纲主路径和显式整理模式符合现有 StudyJournal，比另做彩色白板或仪表盘更合适。** 但部分 UI 术语仍针对旧位置模型，批量状态过于二元化，主入口偏隐蔽，组件复用与可访问性有未说清的工程边界，不能原样冻结。

统一结果见 knowledge-library-v1-design-r3-complete-2026-09-22.md：完整保留 R2 的数据/同步/恢复合同，合入经修正的前端设计；不另留两份互相争夺最终解释权的规格。

## 1. 基础主题：采纳方向，不另开皮肤

附件列出的七种阅读浅色、现代浅色配色与 visual-v2.css:1、35 的 token 对得上；dark 与 system 分支也已有定义。visualTheme.ts:1、4、9 将阅读/现代保存在设备本地，默认阅读主题。知识库继承它们，不能新加会同步的“导图主题”。

审美上，暖纸色/陶色及中性绿都是现有界面的延续；浅底分区、细分隔线、少量强调更适合长时间读日志。拒绝新增彩虹分支、渐变大底、发光选中、玻璃层层叠加或无关统计卡。低饱和不意味着把重要状态淡到看不见，选中、搜索命中、错误与拖拽目标必须各有非颜色标记。

## 2. 深色按钮：警告属实，已经能从现有界面测到

components.css:90 的主按钮使用 primary 底色和白字；visual-v2.css:56、73 的深色 primary 变成浅陶/浅绿。浏览器等待 400ms 后测得：浅阅读 #a45135/白字、浅现代 #14735a/白字；深阅读 #e0a085/白字、深现代 #84d4b7/白字。

按 sRGB 相对亮度计算，这四组对比约 5.52、5.79、2.20、1.74。最后两组明显弱，附件不是无依据挑毛病。深色改配深文字 #191816/#171a19 后，静态配色分别约 8.06、10.08；这只是候选配色计算，不等于全部按钮状态已验收。

R3 要求新的知识控件采用语义 on-primary 前景色，正常/hover/pressed/disabled 和 system-dark 都检查。暂限定知识库根与其 portal scope，不本轮顺手改全站。统一修复旧共享按钮应作为独立维护补丁评审，不能以“复用旧组件”为理由复制已知低对比，也不能借新功能悄悄全站改色。装饰边框可浅，必要连线、焦点和输入轮廓不能只靠极淡 border token。

## 3. 圆角、字号和密度：大体合理，不能硬编码成全局重设计

6px 控件/卡片与 8px 容器符合 visual-v2.css:29 的现有 token。共享 PageHeader 字号是自适应值，实测窄屏 h1 约 21.6px、1440 下 28.8px，而非严格 24–28px 区间。无需为知识库强制纠正原 APP。

附件 14–15px 大纲标题适合 desktop 紧凑视图，但不应成为手机默认。R3 默认正文/节点文字 1rem 左右、desktop 可局部略紧凑；标题最多两行，大纲行高随字号/换行增高，52–56px 是单行密度目标而不是裁切高度。12–13px 仅给辅助元数据，不用来放必须读懂的按钮或冲突说明。手机命中区设计至少 44px，不代表当前共享按钮的 40px 已满足这个新目标。

## 4. 组件复用：采纳样式，但有两个实质性陷阱

ui.tsx:70 的 ListRow 自己就是 button，trailing 还被 aria-hidden。若把展开箭头、勾选、更多菜单按钮直接塞进去，会形成嵌套按钮或隐藏可操作内容。知识树行必须以非按钮容器承载相邻的独立 button/checkbox，复用视觉 token，而不是机械复用 ListRow DOM。

MotionPresence.tsx:26 负责挂载、portal、出场惯性及 exiting 的 inert，不提供完整焦点约束和触发点恢复。“用了现有弹层样式”不等于已有可访问的 dialog。R3 明确模态层的焦点、背景隔离、关闭保护与返回恢复，非模态 desktop 详情则不锁全页焦点。

## 5. 入口：只放更多里太隐蔽，保留 R2 的近场入口

现有 MorePage.tsx:74 已按工具/应用/系统分组，加入“应用 → 知识库”合理；但用户想日常整理日志，只埋在更多会增加频繁跳转。

R3 保留“日志页知识库文字入口 + 更多 → 应用 → 知识库 + 日志详情加入专题”，不替换分类、不增加底部主标签、不改变中央 + 新建日志语义。只读日志里的入口为次级动作，不挤掉保存、复习或收藏。

## 6. 首页信息架构：简洁可取，但不能把不同概念伪装成一种筛选

“专题/待整理/归档”可成为首页栏目；标题统一为“专题”而非含糊的“全部专题”（否则用户会问是否已经包含归档）。“待整理”是日志工作列表，不是另一类专题，切换后主动作必须变成加入专题，不能一直挂“新建专题”当唯一动作。

回收站、待处理、当前库身份/恢复副本仍须有可发现入口，不因追求极简把安全能力塞到找不到。专题行的“节点数、日志数”分别定义为有效可见节点与去重日志，避免将同一日志十个引用计成十篇。不添加 AI 建议、完成率、知识得分等超范围面板。

## 7. 桌面列数与手机高度：方向正确，补成可测布局

实测今天页默认 .page 的可用内宽：1440→1040、1024→约722.56、768→736、390→358、320→288px；更多等页面有自己的最大宽度，这些值不是所有页面共有。全局侧栏为 240px，并在 920px 左右切换壳结构。因此 1024 不能按“桌面”就塞目录、导图、详情三栏，768 反而可能比 1024 有更多内容宽度。

R3 以可用内容宽度定详情布局，初始约 840px 才允许并列正文与 300–340px 详情；不足用详情页/覆盖层。专题简介默认折叠，提示条仅异常出现；手机不要常驻返回、状态、标题、长简介、页签、搜索、警告六层高栏。60% sheet 只是初始建议，不能屏幕/键盘变化仍固定百分比。所有数字均是新 UI 待验证预算，不是已测出的知识库布局。

## 8. 节点详情和删除：必须撤回“移除位置后子项回顶层”

附件 §3.3、§4.3、§8 仍用“移除位置”，并提到示例移除后子项回顶层。R2 已明确取消 Placement：这不是视觉占位能随意决定的细节，会影响用户组织结构及并发冲突。

R3 全部采用“移除引用 / 分支移入知识库回收站 / 专题归档”三个清晰动作。分支根墓碑保留后代；不自动将后代改父级，不提供“保留两处”解决移动冲突，不在知识库永久删除原日志。确认页说明节点/引用影响范围与原日志不会删除。

## 9. 大纲、导图和拖拽：采纳主路径，防误触需要完整状态机

采纳大纲可完成全部任务、导图只作结构投影、浏览态不拖节点、把手启动、移动到可替代。不能用普通 onClick 处理所有触摸收尾；双指开始、滚动超阈值、拖出区域、后台切换都要取消点击候选。

导图空白单指平移，节点拖过阈值在浏览态也只平移；整理态从明确把手拖，预览/待提交/失败/冲突不同。候选合法目标、选中节点、搜索命中分别表达。节点位置移动后保留视觉锚点，不因每次选中/搜索重排整张图。

## 10. 批量操作与保存：不能只有“全部成功/全部失败”

附件的“失败保持选择、显示未添加成功”原则有益，但与 R2 有界独立命令不完全一致。添加 N 篇或批量移动可能部分成功；泛称失败再全量重试会误导。

R3 显示本机已提交 N、待确认 M、失败 K；成功项标记，失败项保留选择，仅重试失败/待核对命令。创建/保存的成功界限是本地事务，不等网络；“保存中”“本机已保存”“云同步中”“结果待确认”分开。提交后关闭弹层不能伪称取消数据库事务。节点文字编辑失败保留原始输入与固定基线。

## 11. 待处理中心：保留入口，不能将所有暂缺日志算冲突

附件把“日志暂不可用”与文字/位置冲突并列，容易把两个通道尚未到达的数据写成永久冲突。R2 明确未知引用是派生状态。

R3 将“需你决定”的持久候选与“等待同步/资源状态”的动态信息分组，未加载齐不进入冲突数；有永久删除证据才用相应词。冲突候选可超过两份，不把 UI 锁死成左右两个版本；desktop 按候选选择比较，手机逐份全文，已看版本集合变化时保留合并输入并重新确认。

## 12. 跳转与 Back：采用既有动效，不另造一套路由

motion.css:31 有 tab/replace 的 140/120ms，forward/back 的 180/150ms；PageTransition.tsx:25 的 200ms 是层清理周期，不能误把它都当视觉动画时长。附件约数总体合理，但实现应复用真实 motion 类，不再建页面动画队列。

“返回知识库”只适合直接来源；如果从日志再进入另一个专题/日志，要回到上一有效来源，而非固定按钮把栈清空。大纲/导图是同页视图切换，不压入新页面历史。模态层/搜索/整理态与来源栈的返回优先级在 R3 统一，不叠两个系统消费同一次 Back。

## 13. Hover、点击、选中与提醒：温和不等于没有反馈

附件不跳动的 hover 合理，visual-v2.css:389 已取消记录卡 hover 位移，树行更不能整体缩放造成误判。Hover 仅在 hover-capable 设备启用，触屏用 pressed/selected；选中不等于多选，键盘 focus 不等于选中，拖拽目标必须另有轮廓和说明。

每次选中/展开不弹 toast；本机保存的稳定状态就地显示，大批量操作或移动可有合并的成功通知。错误和 uncertain 不能 4 秒自动消失，但可关闭瞬时通知，持续状态仍能在固定入口找回。撤销不能只在一个短暂 toast 内可达；本会话最近操作入口提供同一有条件撤销，不扩展成跨设备历史回滚。避免叠在已有复习 toast、同步通知和底部工具条之上。

## 14. 检索与空态：采纳，补齐异步与权限边界

采纳原位搜索、Enter 导航、折叠分支参与、正文/OCR 明确开关及 IME 保护。补充扫描未结束不能显示精确总量、旧查询结果不能覆盖新查询、无结果不等于空专题、未绑定云库不等于数据丢失；默认不含草稿、删除内容和冲突候选。

搜索内各命中独立用强调标记，节点选中背景不要变成同一颜色让用户分不清。输入框、编辑器优先处理自身快捷键，关闭搜索保留期间主动展开/移动视口。

## 15. 无障碍：要求合理，但不能只列名词

原生嵌套列表配独立展开按钮足以实现首期，不为视觉像树就半套 ARIA tree。必须给按钮可访问名称、展开状态、加载反馈、焦点归还；模态手机详情的背景不可点，但 desktop 非模态详情不能锁住大纲。

R3 将字号放大/长中文/200% 缩放、四主题、粗指针、reduced-motion 作为待验收项；普通文字静态对比目标至少 4.5:1，必要图形边界/焦点至少 3:1，作为本项目验收目标而非宣称目前已全站达标。本轮计算和少数页面观察不足以证明符合完整无障碍标准。

## 16. 最终裁定与未做事项

采纳视觉方向，不推倒重来；修正模型不一致及不完整反馈，收敛桌面栏数、手机常驻高度和首期配置量。无需增加独立密度设置面板、自由配色系统、可拖动多级 sheet、首屏仪表盘或新的全局动画框架。

已交付统一 R3 文档；旧 R2 保留历史，使用流程/范围/AGENTS 指向 R3。本轮仅文档及隔离页面观察，不实施 UI、不改全站按钮、不跑 Firebase/付费服务/真机测试。既有 SJ-AUD-01 代码及测试文件须保持原样。仍需用户验收修复、评审冻结统一设计、明确授权后才能开工。
