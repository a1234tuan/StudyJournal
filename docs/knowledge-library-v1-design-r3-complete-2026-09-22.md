## 1. 用户会怎样使用

### 1.1 主流程

1. 从日志页的“知识库”入口或“更多 → 知识库”进入；不新增底部导航主标签，不挤压既有入口。
2. 新建专题，如“数据结构”，创建“树”“图”等节点；也可从日志详情“加入专题”，批量加入已有或新建节点。
3. 在“待整理”查看尚未进入任何有效、未归档专题的日志；也可切换成“尚未加入当前专题”。学科、标签、日期、收藏、资源类型用于筛选。
4. 专题默认大纲，可切换导图。节点能有标题、说明、多条日志引用及子节点，也能是纯文字节点。
5. 选中节点看详情，点击具体日志链接进入原日志浏览；编辑仍走原日志编辑器与正式保存保护。
6. 返回专题时恢复路径、选择、展开、搜索和视口。日志详情的“所属专题”显示反向引用，可跳到另一位置。
7. 点击现有同步入口后，分别看到“日志”和“知识库”的状态；有冲突则进入“待处理”，不是提示同步成功后悄悄丢弃另一端。

同一日志可被多个不同节点引用，正文始终只有一份。v1 **不支持同一节点/子树的多位置别名**；需要多处组织时新增节点并引用同一日志，各处说明与备注独立。

### 1.2 浏览、整理、输入三种互斥状态

- 默认浏览：单击节点只选中；画布拖动只平移；双击、长按不直接修改文字或结构。
- 显式“整理”：显示拖动把手、移动到、编辑和删除。从把手开始拖动，超过阈值后抑制点击；松手仅提交一次，目标不明确则取消。触屏有等价的“移动到”操作。
- 显式“编辑”：输入框接管触摸、选区、快捷键和 IME；拖拽失效。Android Back、切后台、pointercancel 或失焦不隐式保存结构操作。
- 导图支持双指缩放、二维平移、缩放按钮、100%、聚焦分支、查看全图；desktop 支持拖动画布及明确的缩放手势，不抢输入区滚动。
- 使用紧凑圆角矩形，标题最多两行，附引用数/子节点数/备注标记。长文字在 desktop 侧栏、Android 底部详情或详情页阅读，不把全文卡片堆到画布上。
- “全图”展示结构概貌，不保证一千个节点同屏文字全可读。依靠折叠、分支聚焦和搜索，而不是无限缩小字号。

### 1.3 编辑合同

v1 节点说明和引用备注为**纯文本、多行、显式保存**；不增加独立富文本编辑器、附件、图片上传或 Markdown 执行规则。标题单行。初始工程预算：标题 UTF-8 512 字节，说明 16 KiB，单条备注 4 KiB；界面提前给出剩余量，不静默截断。预算须在实现前用中文/emoji 验证，不是当前产品已有上限。

编辑打开时固定目标字段版本。保存必须在写事务内比较该版本；其他独立字段改变不阻止保存，本字段或目标生命周期变化则提示重新比较，保留本机输入。失败、离线、取消、切后台不丢输入；本机恢复草稿保留原基线，按账号/库/实体隔离，不参与检索、云同步和正式备份。成功提交后清理对应草稿。

IME 组合输入期间 Enter 不保存、不跳搜索结果。连续点击保存复用命令 ID，不能重复创建引用。离开未保存输入时明确选择保留草稿、放弃或继续编辑；远端删除后不自动复活节点，可把草稿复制到新的文字节点。

## 2. 关键取舍与实体模型

### 2.1 单位置树，日志多引用

取消 v1 的 KnowledgePlacement 实体。每个节点只有一个正式父级，引用直接归节点；移动节点不复制节点、引用、说明或子树。

- **KnowledgeLibrary**：本地知识库身份、ownerScope（account(uid)/deviceGuest）、独立云绑定与恢复副本状态。每账号首期一个默认云库；本机可有多个副本。未绑定同步不等于任何账号可访问，也不是第二份日志数据库。
- **KnowledgeWorkspace**：专题；稳定 id、libraryId、标题、说明、归档及软删除状态。
- **KnowledgeNode**：稳定 id、workspaceId、标题、说明、生命周期，以及一个结构单元 position = { parentNodeId 或根, orderKey }。workspaceId 在 v1 不可修改，跨专题子树移动后置。
- **KnowledgeRecordReference**：稳定 id、workspaceId、nodeId、recordId、备注、顺序与生命周期。nodeId/recordId 在创建后不变；改变归属用明确的移除/新建。引用正式 id 为 ref-v1 + SHA-256(canonical({nodeId, recordId}))，完整身份还受所属库隔离；同一对只有一条正式行，不只是 UI 去重。并发备注保留候选；删除与未见add/edit并发时保持隐藏，再加入必须显式恢复同一id并保留备注/候选，详见最终方案 D11/C2。
- **KnowledgeRevision / ConflictEvidence**：小单元的不可变版本及未采纳内容/结构意图；用于共同基线、候选比较、幂等确认与冲突处理。UI 的“有冲突”由候选推导，不另存可随意覆盖的 conflictState。

本节是逻辑模型；具体存储名和计划 schema25 已在最终开发方案 D06 选定，实际代码仍为 schema24，开工需核对版本占用。正式实体不得混入画布坐标、搜索缓存、缩放、临时展开、远端游标、租约或设备凭据。

### 2.2 合并单元与身份

节点标题、节点说明分别是文字单元；parentNodeId 与 orderKey 是**不可拆分的结构单元**；引用备注、引用顺序各自为单元；生命周期独立但与删除/编辑交叉校验。专题标题与说明同理。稳定身份及所属库/专题不可被普通 patch 修改。

同一字段不做逐字自动合并。不同字段可合并，不等于不同节点移动永远能合并。删除与编辑必须结合双方的实体版本向量/单元版本集合判断，不能仅比较 deletedAt。

orderKey 同值按稳定节点 ID 排序。重排也属结构写入，有基线和命令边界；不能一次保存整专题来重排。排序编码、唯一段和 4096 字节单键预算已由最终开发方案 D04 选定并在 P0 做性质测试；首期不后台全树重排，超限拒绝本次移动且保留原位置，不无限增长或偷偷拆成部分重排。

### 2.3 树必须始终可遍历

每专题是无环森林，多根由虚拟根展示。正式父级只能是同专题中存在的节点；自引用、成环、跨专题父级和不存在父级不能进入正式树。软删除/归档祖先造成的不可见节点进入恢复投影，不被物理删除。

本地命令提交时验证；远端合并后再次对完整受影响专题验证。特别覆盖 P→Q 与 Q→P 各自在离线端合法、合并成环的反例。正式树保留已提交合法结构；后来无法接受的移动保存为候选意图，不复制子树、不自动猜父级。无法满足约束的候选不必被伪装成一棵合法树。

索引、渲染和备份检查还要有 visited 集合与缺失父级兜底。损坏或未知版本数据放入“结构待修复”，不能死循环、无限递归或悄悄丢节点。

## 3. 本地命令与并发合同

### 3.1 一个事务完成一次真实修改

repository 是知识库唯一正式写入口。命令含稳定 commandId、账号/库上下文、dataGeneration、目标单元、expected 版本、明确 patch；不允许把旧 UI 对象整行 put 回去。

同一 Dexie 写事务内完成：读取当前行 → 验证身份/基线/生命周期/树约束 → 应用 patch → 写不可变版本、待上传命令、知识库 mutation 标记及持久化备份 dirty 标记。任何一步失败全部回滚；无变化操作不制造版本、epoch 或备份任务。

撤销是检查当前基线的新命令，不是回写历史整图。删除、恢复、重复加入也走相同入口。OCR 结果只触发关联日志检索失效，不改写知识节点或冒充知识库编辑。

### 3.2 版本与冲突的可执行语义

每次被修改的小单元有不可变 revisionId（commandId + 单元身份）、父版本 ID 集合、规范化内容与 hash。hash 不包含 updatedAt、本机视口或协议游标；规范化需区分“缺字段”“空值”“删除”，对象键序确定。时间戳只展示，不决定胜负。

- 基于已知版本修改，且当前 head 仍是该版本：采用新值。
- 不同单元修改：逐单元比较；随后统一检查生命周期与树约束。
- 同单元并发且内容相同：合并因果父版本，不生成内容冲突。
- 同单元并发且不同：保留已提交正式值和新的候选值；双方版本都持久化，不能用后到时间淘汰先到内容。
- 找不到可信共同基线：不猜三方合并，进入“基线不足”候选，提示比较或重新同步。

冲突证据按库、实体、单元与本次分歧版本确定稳定身份，原证据不改写，UI 按实体/单元聚合。解决命令改用最终方案 D11/C3 的固定大小 group generation/setToken、当前正式版本和本批至多4个所选候选，不传无界全部heads。事务检查完整集合令牌未变，但只消费所选候选；第三分支/另一解决者改变token时拒绝陈旧批次并保留输入，未选候选始终保留。

部分解决形成父版本数量有界的新revision（先前累计正式版本+本批候选），通过不可变解决记录、父链及候选投影保留覆盖关系，不将全部历史塞进coveredIds数组。10个候选处理3个后其余7个仍活跃；最新token下count为0才可显示该组解决。重传已覆盖祖先不复活旧冲突；基于祖先的新修改仍须呈现，同一解决命令重试无副作用。

v1 不实现通用 CRDT、文本协同或任意多位置别名。只要求相同已提交历史最终收敛，不声称不同服务端提交顺序必得相同“默认保留位置”。版本、墓碑和冲突历史首期不自动 GC；必须可查看占用、导出，不能无限增长而不提示。

## 4. 云同步：独立通道，不混入普通日志账本

### 4.1 隔离决定

本稿唯一方案是独立 Knowledge channel；移除“先混入普通实体列表再靠 capability flag”的备选。现有客户端无法遵守后来新增的前端开关；现有普通账本缺行推导删除也不适合承载未知知识类型。

- 独立 Firestore 顶层命名空间，建议 /knowledgeUsers/{uid}/libraries/{libraryId}/…；**不放在当前 /users/{uid}/… 的递归放行规则下**。认证仍复用，但新命名空间必须有单独规则及协议校验。
- 独立本地 remote mirror、ledger、pending commands、cursor、epoch、恢复代际和状态；不得调用普通同步的删除推导或普通 epoch 表示知识库变化。
- v1 只存有界纯文本与结构，**不创建 Knowledge Storage 对象**。未来超大内容必须另立 Storage 根与 GC；不能借用普通 documents/assets 根。
- 自动备份 dirty 与普通云 mutation 分开，按最终方案 D11/C5 的ownerScope覆盖该身份全部本机知识库（包括恢复副本），不取所有账号也不只取当前库。独立保存scope/membership代际和目的地授权，事务写dirty、提交调度与启动补偿；恢复暂停和账号切换均不能丢dirty或串写别人的目的地。
- 普通同步旧行为不整体重写。入口仅编排两个结果；“日志成功、知识库失败/待处理”必须分别呈现，不能合成“全部完成”。

### 4.2 首期用有界原子命令，不自造跨批次事务

云端每个库一个提交序号 head。客户端用某个 head 的一致镜像准备合并结果并验证结构，再在事务内读取并比较 head、涉及单元版本、幂等 receipt；不匹配则重新拉取/计算。事务内一并提交实体变更、不可变版本、冲突证据、完整 commit 记录/receipt 与新 head。

这把“结构检查时看见的图”与“实际提交的图”绑定，避免图在事务外验证后已变。云端序列化的是**小命令**，不是上传整库 JSON；不维持长时远端锁，不需要首期另建租约、跨批次 staging 或分布式事务协调器。库级串行会有重试与吞吐代价，对本期单用户少设备规模先接受，不包装成无限扩展协议。

初始预算：一个命令序列化变更不超过 64 KiB、事务总写文档不超过 20（含版本/证据/head/receipt），最终以 SDK 与安全规则测试为准，**不是声称供应商实际限额就是这些数值**。超限在本地提交前阻止；批量加入拆成可见的独立小命令，显示逐项成功/失败，不承诺整个大批次原子。一个冲突解决不可拆半提交；大量候选以固定组令牌和有界批次部分处理；未选候选不动，原文单份存revision，commit/receipt通过稳定引用取齐后重放，不能丢候选以压缩请求。

稳定 commandId 的 receipt 绑定完整命令 hash。重复请求同 ID 同 hash 返回原结果；同 ID 不同 hash 拒绝。离线只进本地 pending；重连后重算云合并。事务回调允许重试，不得生成新的 ID 或产生事务外副作用。未知结果先查指定 receipt，再决定重试，禁止重新分配 ID。

安全规则必须验证 UID、库归属、协议版本、不可变记录和 head/receipt 的合法关联；应用层树合法性仍需受支持客户端共同遵守。恶意持有同账号凭据的自编客户端不在“防双端误覆盖”保证内。规则的表达能力、读取预算和事务大小必须通过 Emulator；不能把文件里写了 expected 当成服务端已经 CAS。

### 4.3 拉取与本地确认也是协议的一半

本地分三层：已确认 remote mirror、尚未确认的本地命令、两者推导的 working view。上传 V1 时又保存 V2，V2 必须留在 pending，V1 的确认不能把整个当前对象标记为已同步。

拉取先固定云端 endHead，按连续提交序号获取完整 commit；收到的变更暂存，不以半个命令更新工作视图。应用时在**同一 Dexie 事务**内校验 uid/libraryId/dataGeneration，写 remote mirror、ledger 基线、确认特定 commandId、重放仍在 pending 的命令、更新 working view/冲突证据及连续 pull cursor。重放无法安全应用时保留本地版本为候选。失败则全部回滚，纯下载路径同样执行。

按 receipt 确认某次上传只更新该命令的确认信息，不越过未读提交推进 pull cursor；确认后也不能丢弃尚未进入连续远端镜像的本地可见结果。断电后凭 pending、receipt 和 cursor 重做；epoch 只是变化提示，不是行级 CAS 或确认列表。

同一账号多窗口可能重试同一命令；以稳定 ID、事务和 head 比较保障幂等，不依赖只有一个窗口活着。退避重试有上限，持续失败保留本地可用并给诊断，不无限忙循环。

## 5. 典型双端场景

- 一端改节点说明，另一端改同节点标题：独立单元合并；任一端同时删除则进入删除/编辑判定。
- 两端改同一说明：正式内容保留一个已提交版本，另一份可逐字查看、复制或合并；不能只保留冲突计数。
- 两端移动同一节点：一个正式位置加候选目标，子树始终只有一份；用户可以采用另一位置或保留当前，不能自动变成两个子树。
- 两端移动不同节点：合并后仍无环、父级有效才接受；成环意图进入待处理，导图继续可打开。
- 删除祖先与另一端编辑后代：删除不物理删后代，新内容进入可发现的“待恢复分支”；不在空白画布里永久隐藏。
- 上传已云端成功但本机超时：复用命令 ID 查询/重试；不能二次创建。上传期间继续编辑：仅确认已上传版本。
- 普通日志晚于知识引用到达：显示“原日志暂不可用，等待日志同步”，不是永久断链；后续自动刷新，不制造知识冲突。
- 恢复与在途同步相遇：数据代际隔离旧回调；云上已发生的提交不能靠本机取消请求撤回，按第 7 节处理。

## 6. 删除、归档与日志引用状态

### 6.1 专题与节点

专题归档是可逆的组织状态，不是删除；默认检索和待整理统计排除归档专题，可显式包含。专题软删除进入知识库回收站，不级联抹掉节点、引用或原日志。

节点删除默认为“此分支移入知识库回收站”：只对分支根写墓碑，后代因祖先状态不可见，仍完整保留。界面先显示影响的节点/引用数。v1 不提供含糊的“只删这个位置但保留别名”；移除引用只删引用，不影响原日志。移动子节点脱离被删祖先须为显式恢复/移动命令，不能由普通编辑偷偷完成。

并发移动已移出分支的节点不再受该祖先墓碑隐藏，但保留删除/移动分歧提示；还在隐藏分支内的新修改可从回收站和待处理定位。恢复使用当前父级；父级已删除/失效时要求选择有效位置或专题根，不盲目还原旧对象。候选位置再次应用时重新验证环与生命周期。

首期无自动永久清空知识墓碑/历史；不以“过了 30 天”替代所有设备已确认的证明。若未来做压缩/清理，需单独设计设备水位、离线过期策略与备份恢复兼容。

### 6.2 日志引用解析

引用状态是对普通日志数据的投影，不回写成知识库事实：正常可打开；日志回收站可查看/按既有入口恢复；本机未知则等待/手动同步；有可信删除证据才称“已永久删除”；损坏或权限不足单独提示。

不能从“查不到 ID”直接推定永久删除，不能由知识通道自动恢复日志。一次完整知识提交应用后再判断结构孤儿；跨通道尚未到达的 recordId 不是结构损坏。恢复原日志后引用重新可用。

## 7. 备份、恢复与旧版本兼容

### 7.1 四态解析与完整性

所有导出/导入路径按最终方案 D11/C4 处理 knowledge envelope：缺段=不触碰知识库、不建副本；合法 libraries=[]=用户选择恢复知识范围后创建一个空detached副本；显式空库/非空库=分别创建新的副本；损坏、null或未来版本=写前拒绝。**知识恢复绝不清空或替换任何已有库。** 撤回旧“空包确认后清空当前库”的表述，普通日志恢复语义另行明确。

便携备份含专题、节点、引用、墓碑、候选原文和解决关系，以及解释这些关系必要的不可变版本。pending 本机编辑的内容也不能遗漏；输出为恢复后的事实/候选，不携带原账号待上传命令。排除 UID 凭据、云 ledger、cursor、receipt、锁、设备运行状态和可重建索引。新库恢复时重建协议基线，不能冒充已经与云端确认。

覆盖普通 ZIP、Android 原生流式、目录/仓库、自动备份及相应恢复入口；普通云恢复快照的原格式保持日志范围，UI 不把它称作包含知识库的完整恢复。云端知识版本保留不是独立离线备份的替代品。按引用恢复不新造日志副本；备份引用缺少日志事实须展示未知目标，不假造正文。

### 7.2 新完整包必须让旧读取器失败关闭

仅把 manifest.version 从 6 改成 7 不足：当前普通 ZIP 与原生仓库路径检查版本，但 Android 流式入口显式重建字段，入口处没有同等版本拒绝。不能假设“新增字段旧端会透传”。

选定新完整包采用新的外层 manifest 与版本化主载荷入口，例如 manifest.json + snapshot-v7.json，**不再提供根 data.json**。新读取器先检验容器、能力和校验和，再进入 staging；受支持旧读取器应在缺少旧必需入口或版本不兼容时、任何恢复写入前失败。原生仓库等不同容器分别做等价门禁，不能只改 ZIP。具体文件名为待工程验证的编码合同，v7 为提议版本号。

可显式导出“仅日志的兼容包”，但必须提示不含知识库且不是完整备份；自动完整备份不能降级为兼容包。新客户端仍读旧 v1–v6 日志包并遵守缺字段保留语义。若任何已发布旧读取器仍能静默部分恢复新包，完整备份兼容门槛未通过，不能宣称已解决。

### 7.3 恢复后不自动覆盖云端

恢复预检显示包含范围、数量、候选、缺日志引用及云端关系；空包也明确“创建空恢复副本，现有库均保留”，不是确认清空当前库。先暂停两个通道的新任务、提高并持久化 dataGeneration，等待/隔离本地写队列；导入内容与资源暂存，全部校验后，用户选择的普通日志恢复、新增知识恢复副本、备份dirty及新代际在一次本地事务提交，不清空原知识库表中的其他库。取消/失败不留下半份正式数据。大资源 staging 与现有恢复能力需专项验证，不声称一句事务就解决内存/磁盘问题。

知识库采用保守的**恢复副本**语义：云上 V10 不变，备份 V3 恢复为新的 detached 本地 libraryId；libraries=[]也创建空副本，restoreSessionId重试复用副本身份；副本归确认时的ownerScope、与云同步断开，身份变化不得提交到新账号；原绑定库保留为可切回的库，不把其旧 ledger 复制给恢复库。旧在途操作只可能属于原库/旧代际，回调不得写入恢复库；撤销网络请求不保证云端未提交，后续原库必须核对 receipt。

恢复后可以：继续只在本机使用；切回云端库并先拉取；或明确“将恢复专题另存到当前账号云库”，为专题/节点/引用生成新 ID 并重映射内部关系，按有界导入命令同步，原日志 recordId 仅在身份一致时沿用。发现目标日志缺失/不匹配时阻止自动绑定，交由用户确认。v1 **不提供一键把整个云库回滚到备份**，避免 V3 被当成最新修改覆盖 V10。

恢复副本可能与云库重复，这是可见、可切换、可删除前备份的安全成本，不是自动合并结果。恢复普通日志后，原云知识库引用也可能暂时失效，预检必须说明；不能承诺两个独立通道有跨云原子事务。

### 7.4 两类旧版本问题分开验收

另一台旧设备：继续用普通日志，不读取/发布知识实体、不清理其存储；新命名空间和规则确保不是仅靠 UI 开关隔离。

同设备降级：新 schema 打开过数据库后，不支持安装旧应用直接读取，禁止自动降 schema、删库重建或重置。发布说明要求降级前备份、独立导出及明确恢复步骤；用真实旧 APK/EXE 验证拒绝行为。备份兼容不等于 IndexedDB 降级兼容。

### 7.5 当前身份范围、多个副本与自动备份

完整知识备份的范围是当前ownerScope的全部本机库：包括该账号的云镜像、detached恢复副本、归档/回收内容、未上传正式修改和冲突证据；切换当前正在看的库不缩小范围。其他账号以及未认领guest库不纳入。登出只能访问guest库，不能把原账号副本变成guest。此范围在repository和导出服务层验证，不只在UI过滤。

**普通日志仍是设备本地集合，不按Firebase账号分区。** 备份预检必须分开显示“本机日志（非账号隔离）”和“当前身份知识库”。不能向B承诺日志部分没有在A登录期间写的日志；首期不暗中迁移普通日志所有权。手工选定库或knowledge-only导出显式标记范围，不假称全设备完整备份。云尚未下载内容不能凭空备份，完整是当前选定范围的本机快照完整，不是云全量保证。

自动备份开关、目的地和lastSuccess/dirty按ownerScope保存，采用knowledgeBackupScopes本机存储。首次v7启用以及新身份首次设置须确认范围与独立目录分区；未确认时暂停旧的无身份自动调度并提示，不能自动降级成仅日志后称“完整成功”。不同身份不得共用latest、对象根或GC空间。目标路径用不含uid/邮箱的本机opaque ID；这不是文件加密承诺。

任务开始冻结库集合、范围代际、dirty代际和目的地；切账号不重新读取当前账号的目录/快照。已写出的A产物只能留在旧授权A目的地，不能回填B的成功状态；未完成结果不能清掉dirty。捕获快照后新建副本/新修改留给下一次。文件写入在读取一致快照的事务之外，所有ZIP/流式/仓库/自动路径都接收同一冻结范围合同，见最终方案D11/C5与SCOPE-01–05验收。

## 8. 检索合同

全局知识检索与专题 Ctrl+F 共用查询服务但结果语义不同。只搜索已保存日志、节点说明、引用备注和可用的已接受 OCR 正文；草稿、OCR 运行过程/失败消息不检索，失败的本机 OCR 重试不抹掉已接受文本。

- 全局：按 recordId 聚合日志内容结果，展示命中片段和全部有效引用位置；组织文字结果按节点/引用身份展示，不冒充日志。显示“日志 N 条、组织项 M 项”。
- 图内：覆盖折叠分支，按稳定树序返回定位点；同一日志可有多个位置，明确“日志 N 条 / 位置 M 处”，不按文本出现次数冒充节点数。默认标题/说明/备注，可选关联正文与 OCR。
- 学科/标签/日期/收藏/资源类型是日志过滤条件。开启后默认只返回满足过滤的日志引用；纯文字节点不被虚构学科，可用“另含组织文字”开关明确纳入。专题/分支过滤对所有结果有效。
- 当前专题未整理与全库未整理分开；有效引用要求专题未删除/归档、节点及祖先可见、引用未删除。候选和回收站不算已整理，另有显式检索入口。
- 默认不搜删除、归档和冲突候选；可按分类包含并清晰标注，不能将候选当成正式内容跳转。
- 不复用 SearchPage 的 200 条展示限制作为全集/精确计数。查询可分页、异步取消，精确总数需完整计算完成；尚在扫描时显示“已找到…，继续检索”，不可伪报最终总数。

节点移动使整支的路径/范围索引失效；标题、备注、引用、日志保存/恢复/删除、OCR 接受更新均使相关索引失效。索引是可重建投影，不是事实；结果携带库代际、来源 ID 与版本。异步结果仅在当前 queryGeneration/dataGeneration 匹配时进入 UI，打开前复核对象仍存在且可见。

Ctrl+F 不抢编辑器、输入框及弹窗快捷键；Enter/Shift+Enter 跳转，临时展开祖先。退出搜索撤回搜索自己造成的展开/视口变化，保留期间用户主动展开操作；若用户已手动移动视口则不强制跳回旧点。

## 9. 导航、登录退出与运行状态

返回上下文包含 libraryId/workspaceId/nodeId/referenceId、视图类型、选中、搜索和本机视口，以设备本地有界来源栈保存。专题 A → 日志 → 专题 B → 日志应逐层返回，不只存一个 returnNodeId。原位置删除时回到最近有效祖先/专题入口并解释原因。

Android Back/Escape 优先：取消未提交拖拽 → 关闭顶层弹层/处理未保存编辑 → 关闭模态详情 → 退出搜索 → 退出选择/整理子态 → 消费来源栈 → 既有页面返回；具体单次消费与宿主键盘行为见第 19.2 节。必须接入现有 TabMemory、Web history 的序列化/白名单与 Android Back 处理，不另造平行路由系统；未知旧 history 状态安全退回知识库首页。

知识库本地数据按ownerScope与libraryId隔离，云绑定另记。默认云库从 /knowledgeUsers/{uid}/registry/default 原子注册/发现；第二台空设备拉取同一库，非空未绑定库保留并通过显式另存汇入，不按同名合并。切账号/登出提升代际，A的镜像和恢复副本均锁定，不自动变成B或guest数据。恢复副本虽未绑定云也有ownerScope，详见最终方案 D11/C1、C5；不承诺本机数据库加密。

所有同步请求及回调携带 uid/libraryId/dataGeneration；旧账号回调在本地事务写入前拒绝。备份任务则冻结ownerScope、范围代际/库集合和目的地，旧A任务最多完成到旧授权A分区，绝不写B目录或确认B的dirty。不要依赖 React 卸载或 fetch abort 保障正确性。普通日志目前的账号行为不顺带重写，也不能因此把所有本地日志默认复制到新账号知识云库；知识绑定确认须提醒引用的日志是否已在该账号同步可用。

## 10. 最小改造面与未来扩展

新增独立 knowledge repository/command、merge/sync、query、outline/map projection 与 UI 模块；仅在必要接口接入现有数据库迁移、初始化/清空、备份、登录/同步面板、日志加入/反链、导航和搜索失效通知。不整体重写 storageAdapter、useAppData、普通云协议或现有日志编辑器。

数据库升级必须是增量添加与显式迁移，保留既有数据路径、品牌、签名和包标识。备份调度增加独立 dirty 来源，不让知识库写入冒充 ordinary cloud mutation。原日志编辑继续使用已修复的 expected-row 保存规则。

为未来保留稳定 ID、来源版本、类型化查询结果和独立投影适配器。知识图谱以新的语义边/概念层扩展，不把树父级强行当知识关系；RAG 以检索结果及来源为接口；AI 需要独立范围、隐私、费用及写入授权。首期不预建向量库、插件平台、AI 自动分类、段落锚点、关系连线或多位置子树。

## 11. 实施顺序与验收门槛

以下保留总体工程顺序；实际实施按最终开发方案的 P0–P7 细分执行，不是声称编写本文时已经开工：

1. 先冻结逻辑模型、版本/冲突规范、备份容器与旧版本拒绝矩阵。做纯内存交错规格测试和只读 mock 大纲/导图交互验证；无需等全部云代码完成才能试布局。
2. 实现事务式本地 repository、迁移/恢复 staging 与备份完整闭环，再接大纲、显式编辑、日志引用及检索。
3. 实现独立云规则、原子命令、连续拉取/本地 apply、账号和恢复代际隔离；通过多数据库 harness 与 Emulator 故障注入。
4. 接入导图平移缩放/整理交互，完成 desktop 与窄屏 Playwright；经授权后再做实际 Android/desktop 双端验收。

必须覆盖：两端同字段/不同字段/不同节点成环；删除与后代编辑/移动；第三设备新增冲突；两设备同时解决；已覆盖祖先重放与祖先派生新修改；重复命令/超时未知提交；云成功本机失败；V1 上传期间 V2 保存；纯下载 apply 失败；分页缺口；切账号/退出/恢复期间晚回调；四态备份及各入口；真实旧包/旧程序拒绝；普通 GC 不触及知识数据；知识-only 写入触发自动备份但不脏普通同步；一端只浏览不产生云写入。

交互验收包括触屏平移不编辑、拖动不点击、IME、长标题、长备注、分支折叠、Ctrl+F 全集与计数、返回多层来源、保存失败输入保留、失效目标可恢复。

容量目标为 500 条日志、1000 个节点、5000 引用的测试夹具，不是现有性能测量或硬容量限制。目标环境与加载/搜索/帧率预算采用最终开发方案第 13 节，执行时记录实际测量；未达到时优先分页、虚拟化和折叠，不删数据降负载。

### 11.1 已采纳的产品取舍

依据用户“默认采用推荐方案”的最新指令，确定采用：单正式位置、不自动复制并发移动子树；纯文本批注；恢复副本而非云库回滚；独立知识同步状态；新完整备份须让旧程序拒绝，新程序仍可读旧包。其余合同不得在编码时偷偷改回旧稿行为，不需再逐项请用户确认。

### 11.2 仍需工程验证，不虚报完成

排序编码、规范化/版本算法、事务与规则预算、全通道备份失败关闭、恢复 staging 的资源边界、真实旧客户端兼容均未实现或验证。推荐选择已经在最终方案 D01–D11 定下（D12 补充强制验收），P0 将算法约束变成可执行规格，后续阶段按专项门槛验证；实现假设被反例推翻时在本范围内修正规格和代码，不能通过扩大普通同步改造或降低安全门槛绕过。

当前仍只完成设计审查与修订；前一轮内存反例只证明旧稿几处逻辑不成立，不是新协议的正确性证明。SJ-AUD-01 既有 1708 项测试和 Emulator 结果不能作为本稿的实现验收证据。


## 12. 合并裁定与产品体验总纲

### 12.1 本稿是唯一现行总体方案

第 0–11 节完整承接 R2 的功能、事实、同步、备份、恢复与实施门槛；第 12–22 节将前端视觉、页面流转和操作状态具体化。这里不是一套独立 UI 可以绕过前面的合同。R2 和外部附件保留为历史材料，不再用“数据方案待决定”为删除或别名按钮留后门。

外部视觉审查细节见 knowledge-library-visual-review-2026-09-22.md。选择如下：

- 采纳：温和低饱和主题、紧凑列表、大纲为主、导图为空间浏览、独立整理态、只读选中详情、按需呈现长批注、复用既有视觉 token。
- 修正：不能只埋在更多里；删除不再叫移除位置；候选不限制为两份；批量操作显示部分成功；暂缺日志不计入永久冲突；同一套返回事件不能被多个层重复消费。
- 不做：新底部主导航、旧分类页替换、知识评分仪表盘、彩虹分支/自由皮肤、首期多位置别名、后台自动正式保存、自动把删除节点后代移到根、多级弹层堆叠。
- 视觉维护发现：现有深色主按钮白字对比不足；新知识控件必须避免复用此缺陷，但全站修复另立维护补丁，不借本设计无边界改旧页面。

产品定位是一层帮助“从日志走向主题组织再返回原文”的日常工作区，不是第二个笔记编辑器，不是专业绘图软件，也不是 AI 仪表盘。主要任务必须在大纲中完成；导图不可成为手机或键盘用户的唯一入口。

### 12.2 用户能感知的完整闭环

日志写完 → “加入专题”或暂不整理 → 从待整理批量选日志 → 在专题建分支和写说明 → 大纲/导图查关系 → 搜索定位 → 打开原日志阅读/编辑 → 返回原分支 → 本机已保存 → 主动同步两个通道 → 必要时到待处理比较版本。

空库允许先建专题与节点，也允许先从日志发起“加入专题”；后者若没有目标，先创建专题/命名节点，再确认引用。不偷偷给根目录直接挂引用，不创建无法解释的匿名节点。原日志不因取消加入流程发生任何变化。

## 13. 视觉语言、主题与组件边界

### 13.1 现有样式就是基础，不重做皮肤

使用 visual-v2.css 的最终 token，而不是 theme.css 的早期默认值。阅读/现代与浅色/深色/system 继续正交；外观为本机状态，不进入知识实体、云 ledger 或便携事实备份。

- 阅读浅色沿用纸色 bg #f8f6f2、surface #fffdfa、正文 #2b2926、主色 #a45135；现代浅色沿用 bg #f6f7f7、surface #ffffff、正文 #202523、主色 #14735a。
- 深色分别继承深棕灰/柔陶色及深绿灰/浅绿 token，不另写一套“导图夜间模式”。这些十六进制值只是本轮基线记录，产品样式必须引用 token，不能复制进多处组件。
- 强调色只用于当前主动作、选中边线、焦点与少量定位；成功、危险、警告沿用语义角色。知识冲突不是学习效果差，不用掌握度/复习评分颜色暗示成绩。
- 常规列表透明或 surface 底、细分隔线；说明区尽量用排版和留白，不在卡片里套卡片。浮层可用 floating shadow，普通大纲/专题行无悬浮阴影。
- radius-control/card 沿用约 6px、page 约 8px；不用大圆角胶囊装每个数据项，底部既有导航外观不更改。

### 13.2 文字、密度与层级

页标题复用 PageHeader 的响应式比例，不强制所有屏幕 28px。阅读主题的页/区标题可用 font-reading，工具栏、节点、输入框与长说明用 font-ui，代码文本才用 font-code。显示系统字体回退时不强制下载新字体。

正文与手机节点标题默认约 1rem；desktop 节点可在局部紧凑布局用 0.9375rem；元数据约 0.8125rem，最低不把关键说明塞到细小辅助字号。输入框基准至少 1rem；跟随系统字号与既有阅读设置的适用范围，不新加会修改原日志字号的控制。

页面横向留白沿用当前 .page，窄屏 16px，间距按 8/12/16/24px 分级。单行大纲目标 52–56px，desktop 单行紧凑目标 44–48px；这是最小布局密度而非固定高度，长标题两行、放大字号时必须自然增高。v1 不新增全局密度开关，desktop/触屏按能力适配。

每层缩进建议 16px，desktop 可 20px；当剩余标题宽度不足约 160px 时允许“聚焦此分支”并显示面包屑，不靠无限缩进、极小字或全页横向滚动容纳深树。大纲标题可两行截断，详情看全文；目录行不强制四五个计数徽章同时展开。

### 13.3 对比度与必要的局部补足

知识库以普通正文对比至少 4.5:1、必要交互轮廓/焦点与状态图形至少 3:1 为验收目标；装饰分隔线不承担唯一交互线索。小字不通过降低 opacity 表达优雅。四主题及 system-dark 均检查，不能只看截图中的浅色。

新增控件使用语义 on-primary 前景：浅色主按钮保留白字；深色浅亮主色应配深色字。可在知识库 root 和其 portal host 下提供局部 --knowledge-on-primary 等映射，仍使用共享 ActionButton；不在根 :root 中顺手改所有旧按钮。hover/pressed 必须一起校验。将来若批准统一维护再把映射收敛为共享 token，不能长期复制多套色值。

选中使用 primary-soft 底 + 2px 边线/选中标记；键盘焦点用清楚的外轮廓；搜索命中文字用单独 mark 与当前结果编号；批量选择用 checkbox；拖放目标用虚线轮廓和“移入…”文案。彼此同时存在时不能全用同一个浅底让用户猜。

### 13.4 复用的是合同，不是强行套组件

PageHeader、ActionButton、SurfaceCard 复用尺寸/状态约定，新增样式限制在 knowledge 页面与有 scope 标记的 portal 宿主下。共享 ListRow 是 button：首页若整行只有一个导航动作可以复用；带展开、选中、复选框、菜单的大纲/专题复合行用非交互容器加相邻独立控件，严禁按钮内再放按钮，也不把交互控件塞入 aria-hidden trailing。

MotionPresence 仅是呈现与动画基础，不保证 focus trap、焦点归还、Escape 或无障碍名称。知识弹层必须显式补齐这些合同；desktop 非模态详情保留大纲可交互。新树行/选择器可做局部组件，不为本功能整体重构现有组件库。

## 14. 信息架构与响应式页面

### 14.1 入口与导航归属

保留现有今天、日志、复习、更多等壳结构以及中央 + 的新建日志动作；不以“知识库是核心”为理由替换分类管理、录音或复习入口。

- 日志页：在标题/操作区域加入带文字的“知识库”次级入口，与搜索并列；320px 不强挤单行，放到标题下的操作行，不变成无标签新图标。
- 更多 → 应用：增加知识库列表行，复用现有分组风格。
- 日志详情：次级菜单提供“加入专题”；已有关联则显示简洁的所属专题区域，点击进入具体节点，不替换编辑/收藏/复习。
- 全库只有一份知识 workspace 路由状态；不同入口传入不同来源，不能各自再挂一套数据实例。活跃导航随既有宿主入口保持一致，不临时新造第六个主 tab。

### 14.2 首页

PageHeader 标题“知识库”，短副标题可折叠/窄屏省略；只保留一项主动作。栏目为“专题 / 待整理 / 已归档”，不是给三种不同对象都叫“全部”。

专题列表显示名称、可选一行简介、“节点 N · 日志 M”（日志按 ID 去重），异常时出现“待处理 K”。元数据不是复习成绩；未计算完成显示占位，不闪成 0。名称区点击进入，更多菜单是同级独立按钮，包含重命名、归档、移入回收站。不能整行和菜单同时导航。

待整理栏目展示正式、未删除、当前库中无有效未归档专题引用的日志；切换“当前专题未加入”须先指定专题并在标题显式显示范围。日志按学科/标签/日期/收藏/资源类型筛选，批量选择后主动作是“加入专题”。草稿不参选。首页不重复建设一份完整日志时间线，“查看全部日志”返回现有日志页。

已归档显示归档专题及明确恢复入口，不把归档直接等同回收站。回收站和待处理在首页工具菜单/状态区可达，有待处理时显式文字入口。未绑定库/恢复副本有身份提示；普通日常库不要长期占一整张信息卡。

### 14.3 专题工作区

宽屏层次：返回与库状态 → 标题/一行可展开简介及整理按钮 → 大纲/导图下划线切换与搜索/动作 → 仅异常出现的提示 → 主内容/可选详情。标题和状态不能重复在面包屑、卡片标题、详情栏中出现三次。

手机压缩成两层基础头部：返回+专题名+整理；大纲/导图+搜索。长简介通过“专题说明”按需展开，同步状态用可点击短文案/状态图标而不是常驻完整横幅；严重保存失败或待核对才展示可操作提示。搜索打开可多一行，批量栏仅有选择时出现，不固定叠六七行。

整理态才显示把手、复选框和结构/删除菜单；浏览态仍允许在节点详情点击明确的“编辑说明/添加日志”入口，这个动作必须先显式进入相应编辑/整理流程，不因选中直接进入输入。由日志发起“加入专题”视为明确命令入口，可打开选择器，不要求先绕回工作区再点整理。

“完成整理”只退出模式，旁边若有本机写入任务说明仍在保存；本机已保存但待上传不阻止返回浏览。没有整页未提交快照，不用“完成整理”伪装保存按钮。

### 14.4 按内容宽度决定详情，而不是设备型号

本轮在今天页默认 .page 布局测量：1440 下内宽 1040；1024 下约 722.56；768 下 736；390 下 358；320 下 288。更多等页面有自己的最大宽度，不能把这些值套到全部旧页；知识工作区拟沿用默认页宽，新布局的初始预算如下，需原型复测：

- 可用内容内宽至少约 840px：主大纲/导图不低于约 480px，gap 16px，右详情约 300–340px；最多一个知识内容主区加一个详情区，不再插一根专题侧栏。
- 内宽不足 840px 且不是窄手机：选中后用可关闭覆盖详情或详情页，主区宽度不被压成一条。切到并列布局时延续选中，不重置数据/搜索。
- 390/320：默认只有主区。点节点打开约 60% 可用视觉视口的只读详情，提供“展开详情”进入全高详情，不做多级复杂拖动吸附 sheet。长说明可以直接转详情页。
- 文字编辑/冲突手工合并使用全高编辑层或完整页面，不在半高 sheet 塞入键盘。键盘出现后按实际 visual viewport 与安全区重排；保存、关闭、输入光标保持可见。

没有足够高度时优先全高详情，而不是坚持 60%。模态层激活期间底导航在背景不可点击；正常浏览保持底导航。知识专用底部批量栏、toast、图工具不能盖住系统手势区、现有同步提示或键盘。portal 定位基于视口宿主，不放在带 transform 的退出页面层内。

## 15. 大纲、详情与导图的具体呈现

### 15.1 大纲行

逻辑顺序为展开按钮 → 可选类型标记 → 标题按钮 → 可选计数 → 整理菜单/checkbox/把手。视图可以在窄屏隐藏非必要类型图标和部分计数，不能隐藏标题或移动到入口。展开触区与标题触区分开，叶子保留对齐留白，但不制造空的可聚焦按钮。

展开只改变本机状态；点标题选中并读详情，不直接打开第一篇日志。行内标题至多两行，完整文字从详情可读；不以 tooltip 为唯一完整文本通道。直系子节点数与本节点直接引用日志数有可访问名称，不用一个数字表达两个意思。

采用嵌套列表和 button/checkbox 的常规键盘可达实现；若未来采用 ARIA tree，需完整实现方向键、Home/End、展开/收起与 roving focus，不能只加 role 装饰。长列表虚拟化不得回收当前键盘焦点/正在编辑对象。

### 15.2 节点详情

次序为可导航路径、完整标题、说明、关联日志列表。每条日志行内放该条引用备注，不把所有备注独立堆在最底部以致找不到所属日志。

说明空时浏览态不显示表单框，只在整理态给“添加说明”；无引用的纯文字节点不算错误。日志行显示原日志标题/日期/学科，标签截取少量并可展开，备注默认两行、可展开全文。只有明确标题链接打开原日志，备注展开和菜单不触发导航。

选中节点不会自动展开每条日志正文；手机不默认加载所有富文本附件。临时缺失日志仍保留位置、说明和备注，按第 6 节显示状态。永久删除原日志从既有日志模块处理，知识详情不新增该破坏性按钮。

### 15.3 导图视觉与布局

采用确定性的层级树阅读布局，首期建议从左向右排布、虚拟根连接多个顶层分支；不新增双向/放射/自由白板布局设置。根属于展示结构，不是可编辑实体，不挂日志引用。实际布局适配层可替换，坐标不是事实。

surface 底、无大网格、紧凑圆角矩形、低噪声但可辨的连线。普通连线作为结构线需可辨识，不能只用几乎不可见的 border；选中路径提高对比，未选分支不降低到无法阅读。节点仅两行标题及必要数量/状态标记，完整正文与备注留在详情，不把批注铺在分支线上。

100% 的字号与大纲基准一致；小幅缩放仍清晰，缩到概貌级别可隐藏元数据，但不冒称全文可读。初始缩放预算 40%–180%，全图概貌可允许更小的受控值并显示“概貌，放大阅读”；具体范围按测试调整。用户切换主题/视图不重新生成节点身份。

手机缩放后过小节点不能依靠扩大的互相重叠命中框假装可触达；全图概貌主要用于观察和聚焦，提供搜索结果/大纲等大命中区定位路径。恢复 100%、聚焦分支、查看全图均有明确按钮。

底部只设一组避让底导航的画布工具条：缩放 −/百分比/+，视图菜单含查看全图/聚焦分支；宽屏可分两组，320px 不放两组互相遮挡的绝对定位按钮。控件命中区触屏至少 44px，画布上还有可视的当前位置/面包屑返回。

### 15.4 平移、缩放、拖动的状态机

浏览态空白拖动平移；节点按下后在阈值内抬起才算选择，超过阈值改为平移而非结构移动。双指开始立刻取消待点击/待拖动，双指结束不能补发节点 click。画布外保持原生页面滚动，只有指针起于画布内才接管画布手势；大纲不禁用原生滚动。

desktop 在画布内触控板平移/捏合缩放，鼠标空白拖动平移；滚轮与修饰键具体映射用真实设备验证，不劫持浏览器全局字号缩放。非拖放的层级操作一律有移动到替代入口。

整理态只从把手进入 drag-armed → dragging → 合法/非法目标预览 → 本地提交 → 成功/失败/冲突。显示原位置占位、被移动分支标题、目标全路径，不能只靠一条细线猜父级。无明确有效目标释放不提交，非法目标写明自身/后代/专题不符/已失效原因。

松手后等待本地事务才正式显示移动结果；可展示不落库的预览但不能提前提示成功。提交失败回到原有效投影并保留操作说明，云端稍后发现分歧则标“位置待处理”，不瞬间复制子树。拖动、平移、文本编辑互斥；pointercancel、Escape、切后台取消未提交动作，已经提交的命令只能条件撤销，不能伪称取消网络就恢复了。

## 16. 创建、添加、编辑、移动和删除流程

### 16.1 创建专题与节点

新建专题 → 标题（必填）/说明（可选）→ 创建；本地事务成功才进入空专题。创建中按钮保宽、文字“创建中…”，阻止连点；错误就地显示，字段保留。新建节点必须显示将加入的父级路径，可在根创建；名称验证不回退为匿名默认项。

空专题给“新建节点”主动作和解释“日志仍保留在原处”。“添加已有日志”快捷动作先引导选择/创建一个命名节点，再多选日志；没有目标时不能把引用偷偷挂虚拟根。用户取消未提交输入可以保留本机草稿，但不留一批空专题/节点作为副作用。

### 16.2 添加引用与批量归类

选择目标节点 → 搜索/筛选正式日志 → 多选 → “添加 N 篇”。目标路径固定显示；改筛选保留已选集合，改目标则重新检查已加入项并明确告知，不静默迁移选择。已引用日志显示已添加且不重复选择；同日志出现在不同节点完全合法。

列表加载中、空日志库、筛选无结果、日志加载失败四种界面不同。默认最近正式日志，查找能力不限标题；不触发 OCR/AI。多选计数与“查看已选”可达，避免用户被过滤隐藏的选项误导。

依照第 4 节逐小命令提交：例如“已在本机添加 7 篇；2 篇失败，选择已保留；1 篇结果待核对”。成功项标记并移出待重试集合；仅重试失败，未知结果复用原 commandId 核对。关闭任务面板不撤销已成功项，重新进入可见未完成任务状态；不能错误承诺大批量整体原子。

全部本机成功可关闭选择器并回原节点，不等待云端；状态另显示待同步。正常离线也能完成此流程，不给每次离线保存报红错。

### 16.3 显式文本编辑

复用第 1.3 节纯文本和本机草稿合同。编辑器标明“正在编辑：节点说明/引用备注”，单个 Save/Cancel 明确，不一边自动正式保存一边展示取消。

输入上方有路径/对象名，字段下有长度/校验信息；超限在提交前解释 UTF-8 预算，不截断多字节中文。Back 提供继续编辑、保留本机草稿后离开、放弃修改；不得在没有草稿写成功时提示“已保留”。草稿写失败可继续编辑/复制输入，是否放弃必须明确。

提交期间锁定同一目标的重复提交，可返回只读/等待界面但不能许诺撤销已发出的事务；如允许继续打字，应产生单独下一版输入，不能被前一次保存回调清空。首期选择短暂锁定提交字段、保留原输入直至确定结果，减少状态分叉。

远端更新显示“此项已有更新，你的输入已保留”，提供比较；被删除则不能原位覆盖复活，可复制文字或另建节点。只更新不相关字段不强迫用户处理虚假冲突。

### 16.4 移动与批量结构操作

移动到选择器显示当前专题路径、当前父级、可展开目标、自身/后代等禁用原因；不提供跨专题拖拽假入口。提交成功定位新位置，视口保留上下文，不强制适应整张图。

多选父子时按最外层选中分支执行，预览写明“移动 2 个分支，包含 8 个后代节点”；不能把孩子再单独移动一遍。各分支仍是有界命令，逐条重新验证，部分失败展示结果清单，不承诺所有分支跨端一次原子搬运。

成功可撤销；撤销走基线检查，位置被后续修改时解释原因并给查看当前位置，不盲目放回。短 toast 是快捷入口，本会话“最近操作”还能到同一条件撤销；不新增跨设备无限 undo 历史。

### 16.5 移除引用、删除分支与归档

移除单条引用明确“只移除此处链接，原日志不会删除”；有备注时提示备注一同进入知识回收状态。分支删除必须确认“移入知识库回收站”，列可见受影响节点和引用数量，说明原日志保留。专题归档则说明会从默认搜索和已整理统计中排除，可恢复。

禁止“移除位置后后代自动回顶层”与“删除节点内容但保留两个位置”的选项。回收站显示原路径、说明和引用，恢复目标无效时选新有效父级；隐藏分支里的远端新增内容有“待恢复分支”入口。删除/恢复中本地事务尚未完成不显示成功；失败保留对话框上下文。

## 17. 保存、同步、异常与冲突的反馈合同

### 17.1 状态不相互冒充

- 没有修改：只读稳定状态，不重复写入或 toast。
- 本地提交中：“保存中/创建中/移动中”，按钮保宽，局部 aria-busy，只有相关目标锁定，其他浏览不被整库遮罩。
- 本地成功：“已保存至本机”，dirty 时补“待同步”；不是“已同步”。
- 离线：“离线 · 内容已存本机”，非阻断状态，可继续整理。
- 云请求中：同步入口展开能分别看日志/知识库，知识编辑仍写本机 pending，不把整个工作区锁到联网成功。
- 云结果未知：“同步结果待核对”，说明本机内容保留，提供核对/稍后，不引导重复新建或强制覆盖。
- 云已确认且无剩余本地命令：“知识库已同步”；有候选同时写“内容已保留，K 项待你处理”，不是假装全部无问题。
- 本地存储失败：就地持久错误、重试/复制输入；只能说输入仍在当前编辑器，不能未验证就承诺草稿已落盘。
- 远端引用暂缺：“日志暂不可用，等待日志同步”；有删除证据或回收站状态才使用相应名称。

所有 UI 异常文案经过既有 uiError 转换，不直出 error.message、hash、ledger、原始数据库堆栈或账户敏感信息。

### 17.2 提示占用与通知策略

选择、展开、画布缩放不弹成功通知；常规保存用局部状态，批量/移动/移除才用一次归并 toast。短成功提示建议约 4–6 秒；键盘/鼠标正在操作其中按钮时不自动移除焦点目标。错误与 uncertain 保留固定状态入口，可关闭浮层消息但未解决标记仍可找到。

通知使用一个知识库队列并避让已有云状态与复习提示，不堆三张底部卡。优先级：本地保存错误与未确认操作 > 同步结果 > 普通成功；可在命令面板内呈现的反馈不再复制全屏 toast。读屏普通进度 polite，真正阻断错误可一次 alert，不能每秒播报。

### 17.3 待处理中心

“需你决定”只统计持久候选：文字版本、结构位置、删除/编辑与待恢复分支。等待普通日志到达、正在同步或资源暂不可用在“数据状态”分组，动态恢复后消失，不制造冲突墓碑。

文字候选不限两份：显示来源名称/可辨时间及稳定标识，时间只供阅读不作为推荐胜者。候选列表可切换完整查看、两份对照或手工合并；手机上下分区/逐份查看，不挤两列细字，不截断原文后让用户盲选。采纳操作说明本批仅处理所选候选（至多4项且满足实际预算）；全量集合令牌变化则保留输入并刷新比较，不消费未读/未选候选，未解决总数继续显示。

位置候选显示当前正式路径和待选路径，目标若已删/成环则解释“此位置目前不可用”，允许选择有效新位置，不启用保留两处。冲突中心不打开就强制弹窗；普通阅读和不相关节点整理继续可用。

### 17.4 恢复、账号与来源安全要看得见

恢复预检显示旧包是否含知识库、空集合创建空副本而不清现有库、数据数量、候选及缺日志引用；确认后独立恢复副本有持久身份条“本机恢复副本 · 未连接云库”。主入口提供切回云库、留在本机或明确另存到云库，不能用普通同步按钮暗中回滚云内容。

切账号显示库身份变化；空设备可自动发现并拉取既有默认云库，非空未绑定库先保留再显式另存，不以全局登录成功表示已自动上传。A 的未完成命令不混到 B 的进度里。旧数据代际回调被丢弃时不弹误导性的“当前保存成功”，必要时在原库状态中核对。

## 18. 搜索、筛选与空态的界面规则

### 18.1 两类检索入口

首页综合搜索跨当前可用的正式日志与当前知识库的组织文字，包含尚未归类的日志，可结合第 8 节筛选；无引用结果标明“尚未加入专题”，不是从结果中消失。专题 Ctrl+F 只查当前专题及其关联日志，显示范围 chips。“包含日志正文/OCR”是明确开关；专题内查找不能悄悄扩大到全部本机日志。待整理及原日志搜索继续保留，不复制一套事实来源。

查找条有输入、清除、结果进度、上一/下一、关闭；窄屏辅助操作可第二行/溢出菜单，输入区域不被计数挤到几字。Enter/Shift+Enter 仅在查找焦点且非 IME 组合时导航，Escape 先关闭对应最顶层。

全局“日志 N 条/组织项 M 项”，专题“日志 N 条/位置 M 处”，扫描过程中标“已找到…仍在检索”，超过分页不谎称全量。列表结果携带路径和命中来源；纯文字节点受学科筛选的规则以提示解释，不能显示无意义空白。

### 18.2 命中与返回

导航命中临时展开祖先并定位，导图平移到节点而非整图重排；标识当前第几个定位点。用户主动点击/拖动画布后不因后台再次收到同一查询结果抢回视口。关闭搜索只撤销搜索自身造成的临时状态，期间主动修改的展开/视口优先。

异步旧 query/dataGeneration 结果不能进入当前视图；目标版本失效则说明已更新并刷新，不跳到 ID 恰巧相似的对象。恢复/账号切换清掉旧检索上下文，索引加载失败给重建/重试与基础导航，不把可恢复事实清空。

### 18.3 必须区分的空/加载/错误态

新知识库：“从一个专题开始”及引用不移动原日志说明；空专题：新建节点/添加日志引导；无待整理：“当前范围已整理，可查看全部日志”；筛选无结果：保留条件并清除筛选；未完成加载：骨架行或稳定加载文案；读取失败：重试而不是显示空库；无云绑定/恢复副本：身份提示而不是数据错误。

骨架不闪成 0、无循环耀眼 shimmer，快速操作无需故意延迟等待动画。未收到服务端/本地结果前不乐观显示“创建成功”。

## 19. 页面流转、返回与动效

### 19.1 同页操作与路由操作分开

专题首页 → 专题、专题 → 日志阅读、只读详情 → 独立编辑页用既有 forward/back PageTransition；切大纲/导图、选节点、展开、临时搜索是同页状态，不新增长页面来源栈。来源栈有界，携带库/专题/节点/引用与视图快照，但草稿正文和账号凭据不能放 Web history。

专题 A → 日志 A → 专题 B → 日志 B 逐层返回；直接从专题到日志时可显示“返回专题”，多层来源时用“返回”加目标说明，不固定一律“返回知识库”。源节点已删时回最近有效祖先/专题；整个库已不可用则回当前账号首页并说明，不显示旧账号内容。

### 19.2 Back/Escape 的唯一消费顺序

从最顶层开始：取消未提交拖动 → 顶层确认/选择/编辑层（有未保存输入先保护）→ 模态详情层 → 搜索 → 有选择的整理子态/退出整理 → 来源栈 → 现有宿主页面返回。同一次事件只消费一层；desktop 常驻非模态详情不吞掉页面返回，编辑对话框关闭也不能再次触发退出专题。

浏览器历史、Android 系统 Back、界面返回统一走导航协调入口，不各自注册相互打架的 listener。手机软键盘第一次 Back 可能先由宿主收起键盘，不能在同次事件再放弃输入，须真机验证。页面离开时退出层 inert，不重复提交/读取会写事实的 effect。

### 19.3 动效约定

复用现有 motion：按钮约 140ms；tab/replace 淡入/出 140/120ms；forward/back 180/150ms；组件层清理当前为 200ms。这些是现有基线，不为知识库把整站改成一套新数值。详情/折叠可使用现有 presence 类，内容很多时直接更新高度或淡入，避免大树逐行长动画。

仅短距离约 6–12px 位移，hover 不上浮整行、不缩放节点，pressed 可轻微着色/至多 1px 位移但拖拽中禁用；按钮文字变“保存中”保留尺寸。prefers-reduced-motion 下去非必要位移，保留即时状态与焦点反馈；不通过动画完成回调决定数据是否成功。

返回恢复滚动后不再二次飞入；选中/搜索/远端刷新不触发整图 fit 或从零重排。手势进行时冻结当前布局快照，远端更新排到结束后应用投影，提交时仍验证当前基线；不为“动画顺滑”推迟真实冲突校验。

## 20. 无障碍、键盘与宿主行为

所有可点击图标有名称，纯装饰图标隐藏；鼠标 hover 不能成为唯一文案入口；disabled 原因从旁边说明/可聚焦解释入口读取，而非不可 hover 的灰按钮 tooltip。主要移动/添加/保存保留文字，触屏命中至少 44px且相邻不重叠。

模态层有名称、dialog 语义、受限焦点循环、背景不可交互；关闭焦点回触发点，若已消失回有效父行/标题。全高详情要有明确关闭/返回，支持键盘滚动；非模态详情可以 Tab 回大纲，不错误限制全页焦点。

新增快捷键首期只做工作区 Ctrl+F/平台等价键、查找 Enter/Shift+Enter、Escape；移动/删除不绑定全局裸 Backspace/Delete，避免输入误删。节点移动全部可由按钮和目标选择器完成，导图不是屏幕阅读器唯一表示。

系统字号、200% 页面缩放、长中英文/emoji、reduced-motion、粗指针和横竖屏切换均须检查。页面无横向溢出，画布自身平移不算页面横向滚动。知识输入不改变原日志字号/富文本语义；Android IME、visual viewport、安全区、前后台取消由真实宿主验证，不把 browser isMobile 当 Android 验收。

## 21. 前端工程接入与联合验收

### 21.1 小范围接入

新增知识库页面根、树行、详情、搜索、选择器及候选比较组件；数据读写只经第 3 节 repository/command，不允许 UI 为“快速反馈”直接 db.put 或维护第二份整图真源。组件状态仅包括选择、展开、视口、输入草稿及任务展示。

MorePage/JournalPage/RecordEditorPage 增加明确入口/反链；TabMemory/WebNavigationHistory 与 App 导航协调最小扩展；MotionPresence 复用动画但补模态语义；新增 scoped 样式，不改现有主题选择、底导航创建、复习/Coach/分类页布局。全站 on-primary 修复不是此轮默许实施项。

检索、导图布局和节点列表可由可替换投影适配器读取相同版本模型；远端更新通过受控 invalidation 刷新，不能整页 remount 造成丢稿/丢选择。按最终方案 D04 采用可替换的纯函数左至右层级布局、SVG 连线与 HTML 节点，首期不引入白板/图谱依赖；实际手势和大树性能在 P6/P7 验证。

### 21.2 联合验收清单

- 主题：阅读/现代 × 浅/深，另测 system 切换；主按钮正常/hover/pressed、选中、错误、连线、焦点均有对比测试；不只检查主色十六进制值。
- 宽度：1440/1024/768/390/320 及大字号，按实际内宽看详情变化；常规页面不溢出，1024 不硬塞第三栏，320 主要动作可读可按。
- 输入：名称创建/保存失败/草稿失败/远端变化/删除时输入保留，IME Enter、不丢焦点、键盘避让及 Back 保护。
- 任务：单条与批量本地成功、部分失败、取消剩余、未知结果、离线、幂等重试；“完成整理”不当整页保存，云结果不伪装本机失败。
- 浏览：缩放/平移不写事实、不误编辑；双指后不补 click，拖动把手取消/有效目标/失效目标均测；全部图操作有大纲或菜单替代。
- 检索：折叠范围、分页计数、去重日志与位置数、清除筛选、慢查询乱序、搜索关闭恢复、远端路径变化。
- 反馈：失败可重试、候选可全文比较、第三候选与同时解决、暂缺日志不增冲突计数、删除分支不自动改后代父级、条件撤销仍受版本保护。
- 导航：多层专题/日志来源链、浏览器 Back、模态详情、编辑与退出整理顺序；仅消费一次，源失效/切账号安全回退。
- 备份恢复：四态文案、detached 副本身份、旧包不含知识字段、旧程序拒绝新容器，恢复后同步无暗中云回滚。
- 与旧功能共存：日志创建/保存/收藏、复习评级、Coach、每日计划、分类、已有云 toast 与备份入口不变；只读浏览绝不制造知识/普通同步写入。
