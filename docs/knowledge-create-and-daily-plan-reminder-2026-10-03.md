# 知识库新建日志与每日计划提醒：实施及验收记录

日期：2026-10-03。状态：实现和自动化回归完成，等待用户验收；未部署安装版。

## 授权与范围

用户先要求分析知识库直接新建日志、每天首次打开的计划提醒，随后明确同意按所提方案分阶段实施、回归和截图修正。本次是对知识库和每日计划已有范围的明确授权补充，不扩展至计划 AI 反馈、学习评分或其他冻结功能。

- 不改变应用名称、标识、数据路径、数据库 schema 27、知识协议 1 或云同步实体集合。
- 不部署 Firebase 规则，不登录真实账号，不调用付费模型，不安装 APK/EXE。
- 浏览器验收使用隔离测试上下文和测试数据，不改动用户安装版内容。

## 第一阶段：在知识节点下新建普通日志

导图和大纲共用的“添加日志”窗口顶部增加新建入口，下方保留已有日志搜索、筛选、多选及添加。

交互：选中节点 → 添加日志 → 新建空白日志 → 选择科目 → 创建并关联 → 完整日志编辑器。手机沿用科目弧形选择，桌面使用居中的科目列表。未选节点时仍先建立或选择节点，不自动创建隐藏的收集节点。

- 新日志使用现有 `createRecordBlock`：日期为今天、默认标题、空白正文，保留原有普通日志、草稿、保存与备份语义，不附加 planId。
- 新建时冻结知识库上下文、专题和节点；在创建前、创建后以及最终引用事务内检查身份、数据代际、可写状态及节点可见性。
- 引用通过现有命令通道生成，不直接写入知识表；引用身份仍由节点 ID 和日志 ID 确定。
- 同一尝试并发合并；引用写入失败后的重试复用已创建日志，不再创建第二条。
- 两个存储流程不是一个跨域原子事务。若日志已创建但关联失败，明确显示部分成功并保留日志；关闭后仍可从普通日志列表找到，再通过已有日志入口关联。重启后不自动重试旧目标。
- 取消科目选择不创建日志。创建后直接退出编辑器沿用普通日志语义，不调用每日计划的空白日志回收。
- 返回保留原专题、节点、视图及原有导航状态；不把预览面板改造成第二套编辑器。

核心文件：

- `src/features/knowledgeLibrary/createRecord.ts`：创建和关联的协调及校验。
- `src/features/knowledgeLibrary/KnowledgeLibraryPage.tsx`：入口、上下文捕获、错误及导航衔接。
- `src/components/SubjectRadialPicker.tsx`：复用科目选择、桌面工作区模式和失败展示。
- `src/App.tsx`：普通日志创建、新日志标记及编辑模式导航。

第一阶段定向回归：18 项通过，TypeScript 检查通过。随后补充了指针与失败布局测试。

## 第二阶段：每日计划欢迎卡

每日首次启动或回到前台，数据初始化后在今日首页的安全时机显示一次。若正在编辑、复习、语音会话、其他页面或弹窗、恢复数据、云同步期间，延后至安全首页，不抢占操作；不会在持续操作跨过零点时突然弹出。

- 本机自然日键：`study-journal-daily-plan-reminder-date`。显示时记录，不等按钮确认。
- 同日刷新、重启、再次聚焦不重复；关闭、暂不制定、Escape 和 Android Back 都消费本次展示。
- 本地日期取设备时区，不使用 UTC 截日或间隔 24 小时。前后台监听同时覆盖 Web 和 Capacitor。
- 多窗口使用 Web Locks 串行领取展示资格，并在锁内重新检查日期、可见性和资格。无 Web Locks 时使用本地存储检查；无法承诺不支持该能力的宿主具有同等跨进程竞态保障。
- 无可用持久化存储时降级为会话内去重，避免崩溃；此异常环境不能保证重启后仍不再显示。
- 标记只留本机，不加入备份或云同步；不按账号重新触发，各设备独立每日一次。
- 无今日计划：为今天定个小目标 / 去制定计划 / 暂不制定。
- 已有今日计划：今天的计划，已经就绪 / 真实计划项数 / 查看今日计划 / 直接开始。提前安排的当日计划也计入，删除项不计入。
- 主按钮复用 `openDailyPlan`，明确回到今天，不沿用上次查看的未来日期。
- 复习浮动提示等待本次提醒判断完成且弹窗关闭，避免同时出现。

组件采用原生 dialog，提供焦点、Escape、焦点恢复和小屏滚动，使用主题变量及局部装饰性的日期/清单插画；不嵌入计划输入表单。减少动态效果时关闭入场动画。

核心文件：`src/hooks/useDailyPlanReminder.ts`、`src/components/DailyPlanReminder.tsx`、`src/styles/daily-plan-reminder.css`。

第二阶段定向回归：提醒逻辑/展示及本地日期共 21 项通过，TypeScript 检查通过。

## 浏览器发现与修正

1. 原科目选择器桌面媒体查询强制隐藏。增加仅知识库工作区启用的桌面布局，首页手机入口不改成桌面入口。
2. 科目轨道在 pointerdown 就捕获指针，真实点击可能被重定向到轨道而无法创建。改为超过拖动阈值后捕获，浏览器新增流程验证实际点击创建成功，原弧形入口回归保留。
3. 关联失败长文案在弧形标题区不适合阅读。工作区失败时切换列表，保留诊断编号，明确已创建及重试不重复。
4. 桌面科目列表固定高度留下多余空白。改为随内容高度并限制最大滚动高度。
5. 手机新建入口副说明有单字换行。缩短为“创建后自动关联到此节点”。
6. 320px / 150% 字号下强制换行造成零散短行。改为自适应平衡换行，卡片限制视口高度并允许滚动。
7. 现代暗色主题继承的白字浅色主按钮对比不足。只为新增计划卡及知识库科目选择设置暗色前景，不更改全局主题。

截图实际检查覆盖桌面 1440×1000、手机 390×844、小屏 320×640 / 150% 字号，阅读和现代外观的明暗模式；包含添加日志、科目选择、完整编辑页、部分失败和已有计划变体。

## 用户验收与边界

待用户确认：

1. 大纲和导图选节点后，从“新建空白日志”选择科目直接开始写，返回后仍在原节点且关联正确。
2. 原有搜索筛选、关联已有日志仍顺手，没有被新入口挤占。
3. 首次打开的计划卡视觉、位置、文案及按钮操作符合预期；暂不制定后同日不再出现。
4. 已有计划时能够识别已有安排，并直接进入今日计划。

手机截图是 Chromium 窄屏模拟，不等于 Android 真机安装或 Electron 安装版验收。原生返回/前台事件有代码及单元覆盖，但物理设备升级验收仍待用户决定。未构建、发布或安装新的 APK/EXE，未提交 Git。
