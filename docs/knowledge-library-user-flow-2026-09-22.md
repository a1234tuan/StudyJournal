# 知识库使用全貌与流程草案（2026-09-22）

**R3 统一修订说明**：现行完整设计见 `docs/knowledge-library-v1-design-r3-complete-2026-09-22.md`；已选决策、实施顺序与自动验收门槛见 `docs/knowledge-library-v1-final-implementation-plan-2026-09-22.md`。推荐取舍已按用户指令定稿，实现未开始。保留本草案的使用全貌；布局、动效、操作反馈、响应式与无障碍按 R3 第 12–22 节统一。不采用同一节点多位置别名；引用归节点，冲突移动保存候选。批注为纯文本显式保存；独立展示知识同步状态；恢复知识备份（包括明确的空知识包）生成与云库隔离的新本机副本，不清空现有库。默认库发现、引用删除/恢复、有界部分冲突处理和身份备份范围按最终方案D11执行。

**2026-09-22 最新安排**：用户选择默认采用推荐决策，阶段自行测试通过后自动推进，只在最后阶段完毕后邀请用户验收。SJ-AUD-01 尚未获人工验收，P0 自动回归后并入最终人工复验；不再以中间人工确认阻断阶段。本文仍不是已实现功能说明。

这是解冻后的产品体验说明，不代表功能已实现；工程决策和验收以最终分阶段开发方案为准。授权边界见 `docs/studyjournal-scope-unfreeze-2026-09-22-knowledge-library.md`。下文均为拟议体验；示例专题、日志与批注为虚构，不来自用户设备。

**日志按时间记录，知识库按主题组织，搜索跨内容和结构定位。内容一份，入口多处。** 不要求旧日志搬家，也不要求先分类才能写日志。

## 1. 入口与首页

保留今天、日志时间线、分类、复习等工作流。统一方案改为日志页增加「知识库」入口及「更多 → 知识库」，不改现有分类页、不新增底部主标签，以减少对旧功能的影响；「复习 → 学习助教」不移位。入口选择已纳入最终方案，不再逐项确认。

首页包括「我的专题」「待整理」「全部日志」和搜索。专题如「数据结构」「考前易错题」；待整理由没有有效专题引用的日志推导，不是额外的人工状态；全部日志保留学科/标签和组合检索，不需要先归类。

## 2. 首次整理历史日志

进入待整理或全部日志 → 按关键词、学科、标签缩小范围 → 创建专题与分支 → 多选日志加入分支 → 移动排序 → 补充说明。

例如创建「数据结构」，建立「树」「图」「查找」，将相关旧日志批量加入。随时可以停止整理，未归类日志仍能从时间线和搜索访问。

批量加入不复制正文，不改变学科、标签或复习状态。「二叉搜索树删除过程」可以同时放在「数据结构 → 树」与「考前易错题 → 边界情况」，仍是同一条日志。

## 3. 专题内部

同一份结构切换「大纲」「导图」：大纲适合长标题、批量整理与阅读；导图适合整体浏览、分支折叠与结构调整。切换不复制数据。

节点有标题、可折叠说明、零到多条日志引用及子节点；允许纯文字节点。每条引用可写当前位置专属备注，同一日志在不同专题中的备注独立。

例如「二叉搜索树」节点写「重点理解删除后的结构保持」，引用日志「删除过程」，备注为「注意根节点与双子节点情况」。另一专题对同一日志写「考前重做此例」。备注不会自动写入原日志正文。

首期是层级树，日志多处引用不使树产生循环；自由白板、跨分支关系、线上批注后置。删除操作明确区分移除引用、删除节点/子树和删除原日志。

## 4. 查阅、编辑与返回

点击明确的日志引用打开操作 → 原日志浏览 → 必要时进入既有编辑器 → 保存 → 返回专题原位置。打开日志与展开分支、选中节点、移动操作区分。

原日志更新后各处打开同一份新内容，专题备注不变；返回恢复分支展开、选中位置与视口。沿用既有草稿失败和过期写入保护，不静默丢稿。

日志页显示「所属专题/引用位置」及适用的「被哪些日志引用」，可反向定位。专题位置、日志间引用与 AI 推测的语义关联不能混称为同一种关联。

## 5. 搜索与定位

输入「删除」并限定数据结构专题，再叠加易错标签或日期条件。结果按日志聚合，展示命中来源、片段与专题路径；节点自身文字以单独类型结果呈现，不冒充日志正文。

正文或 OCR 命中优先打开日志及已有可定位资源；引用备注命中优先定位引用位置；节点说明命中打开节点。首期不承诺任意正文段落的精确锚点。

全局搜索、专题搜索和添加日志选择器复用查询能力，选择日志不限标题。搜索不会自动启动 OCR、AI 或付费请求。

## 6. 日常新增

仍按原方式写日志和保存；之后可点「加入专题」，也可先不整理，稍后批量处理。专题不是保存的必填项，不自动改变学科、标签或加入复习。

完整循环：写日志 → 可选归类 → 补充专题说明 → 按主题查阅/搜索 → 修改原日志 → 回到专题。

## 7. 两端体验

- desktop 建议使用专题/大纲导航与内容主区，宽屏可提供日志侧栏预览；导图支持适合鼠标的缩放与结构操作。
- Android 建议默认折叠大纲并保留导图；用「移动到」「加入日志」「编辑备注」完成操作，不依赖精细拖拽或悬停。
- 两端共享专题、节点、引用和备注，各自保留本机浏览视口。手机也能完成核心整理，不只是查看。
- 离线编辑先保存在本机，网络恢复后通过独立 Knowledge channel 同步；既有同步按钮分别展示日志和知识库状态。不同字段可安全合并，同字段/不合法移动保留候选待处理，不承诺无冲突。

同账号第二台空设备在线启用知识同步后，自动发现并拉取同一个默认库；若本机已有离线组织内容，先保留两份，再明确“将本机专题另存到账号知识库”，不自动按名称覆盖或合并。同一节点对同一日志只有一个正式引用，两个备注可作为候选；移除隐藏整条引用，重新加入显式恢复同一引用并保留备注。

待处理支持分页和部分处理：例如10个候选先处理3个，其余7个原样保留；新版本到来时重新比较，不把未选候选自动消除。

## 8. 删除、备份与原有功能

移除引用或删除专题不删除原日志；删除专题会影响其结构与整理文字，须明确提示。日志进回收站后引用不可用但保留备注，恢复后可重新访问；永久删除后的显式清理方式待设计。

新完整知识备份包括当前身份全部本机库（含恢复副本）的组织内容、候选及墓碑，不混入其他账号库；索引可重建。旧包无知识字段时不改知识库；显式空包仅创建空恢复副本，原云库和其他本机库均保留，不自动回滚云库。新完整包必须让旧程序写前拒绝。自动备份目的地/开关按身份隔离，切账号不沿用上一账号授权；具体兼容矩阵按阶段验证。

完整包里的普通日志部分仍是设备本地集合，并非按账号隔离，预检须明确提示；不能把知识库账号隔离宣传成整个旧日志数据库已经账号隔离。

学科、标签、日期、收藏继续各司其职。专题不替代正式学习事实；复习、AI 助教、每日计划、语音与隐私边界不变。

## 9. 待定与首期目标

入口、布局、编辑、删除恢复、检索、实体/迁移与同步的推荐决策已在最终开发方案选定；算法正确性和旧客户端兼容仍须按阶段验证，不把文档定稿当作测试通过。

首期交付「整理 → 查找 → 打开 → 编辑 → 返回」闭环，包含数据持久化、同步、备份与两端验收；不是实现全功能白板。智能集合、AI 自动分类、语义搜索等不是本轮首期承诺。

## 10. 用户补充：浏览、缩放与防误触

以下内容回应 2026-09-22 用户关于缩放、防误触、批注密度、拖拽、图内查找和后续扩展的补充。问题与需求已记录；具体交互规则仍是建议方案，不能当作实现完成或真机验收结果。

### 10.1 大纲与导图采用不同的视图操作

- 导图支持二维平移、放大/缩小、恢复 100%、适应当前分支、查看全图和定位选中节点；缩放以指针/手势中心为锚点，避免目标漂移。
- desktop 建议空白区拖动平移，触控板滚动平移，明确的缩放手势或按钮缩放；节点和控件不与背景手势混用。具体滚轮/修饰键映射在原型中验证。
- Android 建议单指拖动平移、双指缩放；两指手势优先于节点点击/拖动，多点触控开始时取消未提交的节点拖动。手势结束后不能补触发一次点击。
- 大纲保留正常纵向滚动，深层结构用缩进限制、路径导航和必要的横向滚动处理。字体大小沿用应用阅读设置，不默认把整棵大纲当画布缩放，不禁用系统无障碍缩放。
- 不承诺数百个展开节点能同时全图可读；全图缩略用于导航，日常阅读依赖分支聚焦、折叠和搜索定位。缩放、平移不改变正式数据。

### 10.2 默认浏览态，显式进入整理态

- 每次进入知识库工作区默认浏览态：单击节点只选中并显示只读详情，明确点击日志链接才打开日志；拖动只浏览，不改结构。
- 浏览态不使用单击、双击或长按直接进入文字编辑；长按也不自动变成节点移动。
- 点击「整理」才显示结构操作入口和拖动把手。整理态单击仍只选中，文字输入必须通过明确的「编辑标题/说明/备注」操作打开。
- 编辑保留清晰的保存与取消路径，服从既有草稿失败、过期写入和导航保护，不把离开输入框自动当作成功提交。
- 节点拖动、画布平移、缩放、文本编辑是互斥交互；拖动开始后抑制点击和编辑入口，释放指针不能触发编辑。
- Esc/取消、pointercancel、失焦或应用切后台取消尚未提交的拖动；Android Back 优先退出当前编辑/拖动/搜索，再按页面导航返回。
- 防误触是待验证的验收要求，不宣称绝对不会发生。须覆盖触控板、触屏、手势跨节点、系统返回和输入法场景。

## 11. 用户补充：紧凑节点与按需详情

建议采用**紧凑圆角矩形节点 + 独立详情区**，不把每个节点做成包含全文和大量按钮的大卡片。

- 导图节点默认显示一到两行标题、子节点/日志数量，以及存在说明或备注的小标记；无说明时不显示空占位。
- 节点下的日志引用以紧凑条目展示，允许折叠；大量引用显示数量并在详情中查看，避免一个节点无限长高。
- 节点说明、引用备注不默认全文铺在图上。desktop 用侧栏，Android 用可扩展底部详情或详情页查看完整内容；详情保持只读，编辑有单独入口。
- 可提供「显示简短说明」开关，但不纳入默认密集布局；长标题截断后，触屏与鼠标均能通过详情读取全文，不能只依赖悬停提示。
- 大纲按行呈现，选中后展开必要详情；紧凑视觉不能以难以触达的按钮为代价。选中控件与邻近节点的命中区域不应重叠。
- 布局默认自动计算，持久化父子关系和顺序，不将拖动后的任意屏幕坐标当作内容组织真源。布局结果可重建，布局偏好与本机视口分开。
- 「查看全图」服务于看结构，「聚焦分支」服务于读内容；不以把文字缩到不可读来实现所谓全貌。

## 12. 用户补充：跨分支移动与关系连线

本轮首期的「从一个分支拖到另一个分支」解释为**改变父节点的结构移动**，不是额外创建知识关系线。

1. 在整理态从明确的拖动把手启动；触屏也保留「移动到」操作，不能强迫使用精细拖拽。
2. 达到拖动阈值后展示移动预览；移动整个子树时预览说明携带子节点、引用与备注。
3. 合法目标高亮并展示将放入/插入的位置；无明确目标不猜测最近节点，不提交移动。
4. 松手后只提交一次结构命令，原子更新父节点和顺序，不复制或编辑原日志。
5. 拒绝拖到自身、后代或失效目标；提交时再次验证，避免拖动期间远端变化造成循环、孤儿或覆盖。
6. 提供撤销移动的入口，撤销也需检查当前版本；期间已有其他设备修改时不能盲目恢复旧快照。取消操作不写入数据。

第一版先保证同一专题内跨分支移动；跨专题迁移不是这个拖拽动作的默认含义，须单独设计目标、引用和冲突规则。

如果用户希望保留两个节点原位置，只连接「前置」「对比」「应用」等关系，那属于跨分支语义关系编辑，仍是后续范围，不与树结构移动混用。

## 13. 用户补充：Ctrl+F 图内查找

- desktop 在知识库工作区按 Ctrl+F 打开图内查找；Android 有显式搜索按钮。大纲与导图共用查找状态，切换视图不丢查询。
- 快捷键仅在知识库工作区处理；日志编辑器、弹窗或输入组件已处理的查找不能被全局拦截抢走。
- 默认查当前专题的节点标题、说明、引用标题与备注，包含折叠分支；开关「包含关联日志内容」后再查原日志正文和已有 OCR，明确两种范围。
- 提供匹配数量、上一项/下一项、Enter/Shift+Enter 和关闭操作；匹配按稳定结构顺序导航，不因视口移动跳变。
- 命中时临时展开祖先并定位，突出目标且保留路径；正常查找不删除或隐藏整棵树。没有命中时给出明确结果，不改变结构。
- 同一日志在多处引用时，内容结果按日志聚合，并列出当前位置或所有引用位置，避免用户误以为是不同内容副本。
- 关闭查找撤回搜索造成的视口与临时展开变化，保留用户在搜索期间主动调整的视口与展开状态；状态仅本机保存，不制造同步写入。
- 无需先加载/渲染所有节点到画布才可查找；基于模型与可重建索引查询。失效引用、节点被远端删除等情况有明确反馈，不跳转到错误位置。

## 14. 用户补充：知识图谱、检索增强与个性化 AI 的扩展边界

用户提到的「增强前检索」暂按可能指「检索增强生成（RAG）」理解，术语仍需确认；不能据此默认指定某一技术栈或启动 AI 功能。

首期应留下清晰扩展接口，而不是预先实现整套图谱/向量数据库：

- **内容与摆放分离**：原日志是内容真源；专题、节点和引用拥有稳定 ID，父子关系与排序表达组织，画布坐标不充当实体身份。同一日志可在多个视图出现。
- **层级与关系分离**：首期层级保持无环；未来显式的语义边独立建模，带关系类型、来源和确认状态。不能直接把每个展示节点当作全局知识概念；未来概念实体与展示位置可独立关联。
- **查询与界面分离**：统一查询入口保留范围、来源 ID、命中片段、内容版本与排序信息；未来可增加关键词/语义混合检索，不能把首期接口写死为某个画布库或向量库。
- **索引与事实分离**：全文索引、向量或图谱投影可重建；日志/备注变更、删除与恢复使派生结果失效。检索读取当前可见的有效内容，不从旧索引复活已删除记录。
- **检索与生成分离**：未来 AI 的建议链建议为用户选范围 → 检索日志及组织文字 → 展示/限制证据范围 → 生成带可回溯来源的建议。优先证据定位，不默认把整座知识库发送到模型。
- **个性化显式授权**：未来偏好与目标应由用户声明、可查看/修改/清除；访问记录、语音本机历史、复习批注草稿等不因「个性化」被悄悄纳入上下文。远端请求仍需明确权限、凭据和费用边界。
- **建议与正式写入分离**：AI 建议是待确认内容，不能自动移动节点、改原日志、决定复习优先级、掌握状态或延迟验证日期；即使扩展也保持既有正式事实边界。
- **演进可测试**：设计版本化契约和迁移、实体级变更入口、可替换的布局与检索适配层。避免无约束 JSON 扩展包或提前建设复杂插件系统。

本节只描述首期的模块边界与可扩展方向，不批准图谱、RAG、个性化 AI 的实现，不承诺未来无需迁移即可加入。其数据模型、隐私、成本和验收需要后续独立方案与范围确认。
