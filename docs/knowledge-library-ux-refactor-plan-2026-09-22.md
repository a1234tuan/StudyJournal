# 知识库体验重构方案

日期：2026-09-22。状态：待用户审阅；本轮仅调查、复现与制定方案，不实施功能改动。

后续状态（2026-09-23）：以上为方案编写时的历史状态。用户随后授权直接实施，第一轮实施已完成；根据第二轮反馈继续修复，当前行为及验证见 [第二轮验收记录](knowledge-library-ux-follow-up-2026-09-23.md)。本文件保留原始方案，不代表当前同步入口位置。

## 1. 重构目标

不是缩小现有按钮，而是把技术功能控制台改成直接整理日志的大纲／导图编辑工作区。

- 更多入口与其他应用条目一致，不额外使用卡片、说明或强调色。
- 专题主体就是可直接编辑的大纲／导图，不再让用户先找“整理”开关。
- 普通主流程：新建专题 → 添加节点 → 添加日志 → 在大纲／导图中继续整理。
- 本机库、账号库、默认库发现、冲突候选等内部概念退出常驻主工具栏。
- 创建、筛选、搜索、编辑真正可用；失败说明原因与下一步，而不是只给诊断编号。
- 保留已有库、引用、备注、草稿及恢复副本；不通过清空／按名合并数据制造整洁。

本方案在交互层替换旧设计的“默认只读→整理→选节点→编辑弹窗”。不改变日志正文、复习、FSRS、Coach、知识同步协议、账号隔离和备份恢复语义；导图仍与大纲共享树结构，不扩展成自由白板或任意关系图。

## 2. 调查结论与证据边界

检查当前 HEAD b19af74，知识库初始提交 35b62f0。源码环境不等于用户已安装的 APK／EXE；以下明确区分代码事实、隔离复现和待现场确认。

### 2.1 入口不一致：已确认

src/pages/MorePage.tsx:123 将知识库 ListRow 放在 .more-list 外，额外传入 description，又缺少相邻条目的右箭头。问题在入口结构，不应通过改全局主题补救。

### 2.2 双返回与工作区太靠下：已确认并复现

- src/App.tsx:2029 的外壳返回与 KnowledgeLibraryPage.tsx:213 的内部返回同时渲染。
- 返回提示、英文眉题、大标题、副标题、本机库／同步栏、专题工具栏、专题说明逐层占据顶部。
- 隔离 Chromium，1440×1000，一个专题一个节点：可见返回按钮 2 个；大纲顶部 y≈439px，高 680px，底部超出视口。
- 当前编辑依赖“整理”模式与弹窗，不是直接操作大纲的编辑器。

### 2.3 筛选控件被挡住：窄屏复现

- knowledgeLibrary.css:37 的窄屏节点详情是固定浮层；打开搜索／待整理不关闭该详情。
- 390×844，进入专题→选节点→待整理：详情约覆盖 y=588..768；学科／标签约在 y=653，日期约在 y=706；控件中心实际命中详情文字。
- 按当前屏幕坐标点击标签输入框，输入框没有获得焦点。自动化 click 会尝试滚动避开遮挡，因此只用自动填值会漏掉这个缺陷。
- 对照：未被浮层遮挡时，桌面隔离的 100 条日志样本中，学科、标签、日期筛选可更新并正确返回对应记录。不能据此否认用户问题，也不能说所有筛选处理函数都没写。
- 原生 Android 日期选择、中文输入法、安装版资源和桌面其他遮挡情形仍待各自验证；窄屏浏览器不是 Android 真机验收。

### 2.4 同名本机库：创建逻辑导致

页面每次调用 createLibrary("本机知识库")，仓储每次默认新建 UUID，不询问名称。多次点击会产生多个独立库，而不是一行数据重复显示。用户现有三个库没有被读取，不能假定都为空，更不能按名称去重删除。

### 2.5 云按钮与诊断编号

“启用并发现账号知识库”是在查找当前账号唯一默认云知识库，必要时事务注册，再建立本机绑定。非空本机库不应被静默合并上传；它不是创建专题的前置条件。

- 页面将普通异常交给 formatUiError(error, "generic")，所以不同原因会显示相同的“操作没有完成”。
- src/lib/uiError.ts:52 中的编号由上下文、时间片段与计数生成，不是 Firebase 错误码；该生成函数没有保存底层原因映射。仅凭用户给出的编号，无法知道真实失败原因。
- 实施记录 docs/knowledge-library-v1-implementation-status-2026-09-22.md 明确标记生产规则未部署、真实账号验收未做。因此规则／生产环境不匹配必须排查，但本轮不能直接宣布它就是用户这次报错的根因。
- 本轮未连接真实账号、读取云端、重试用户云写入或部署规则。

### 2.6 卡顿：风险已发现，完整归因未完成

- 搜索结果初始上限 50，每次“显示更多”再增加 50，并非所有结果视图一开始就渲染 100 多条。
- 关联日志选择器直接渲染全部匹配日志，没有同样的行数上限。
- 搜索面板关闭时仍计算 filtered；限制渲染行数不等于限制扫描计算量。
- 滚动／平移回传应用导航状态，需量测全局重渲染成本，不直接判为唯一卡顿原因。
- 大纲已有虚拟化，但实际行高计算至少 80px，高于 CSS 的 60px，信息行偏大。
- 本轮的 100 条样本用于功能调查，不是性能基准；没有测得真实设备 p95 或内存结果。

## 3. 信息架构

### 3.1 更多入口

移入“应用”的现有 .more-list，使用同一 ListRow、图标、右箭头、行高、背景、分隔和交互状态。只保留“知识库”，删除描述。浅色跟随现有黑／深色文字 token，深色跟随主题，不硬编码黑色。

### 3.2 首页：管理专题，不先管理容器

- 顶栏：知识库、搜索、新建专题、更多。
- 主体：紧凑专题列表；点击直接进入编辑工作区，不为每条专题堆大说明卡。
- 空状态只保留“创建第一个专题”主行动，不堆技术提示。
- 没有库时，第一次确认保存专题才以幂等事务创建当前身份的默认本机容器；仅浏览或取消不写入。
- 一个库时隐藏无意义的下拉；多个库时保留轻量切换，记住当前身份下最后明确选中的有效库，不猜测合并目标。
- 待整理日志可直接选择并添加到专题，不再只是另一张查看日志的长列表。
- “新建独立知识库”下沉管理页，先输入名称、确认后创建。主页面不再并列“建库”和“新建专题”两种相似操作。

### 3.3 专题工作区：画布优先

Desktop 常态：一条紧凑顶栏，包含单一返回、专题名／面包屑、大纲／导图切换、搜索和更多；下方为编辑主体。

- 协调外壳和页面导航，只保留一套返回。顶部返回、浏览器历史和 Android Back 共享层级决策，不能仅删按钮却留下不同返回语义。
- 删除常驻英文眉题、副标题、“先浏览再整理”“组织不改变日志正文与复习记录”等说明。
- 本机库、同步管理、回收站、归档移到管理／更多。必要的数据边界说明保留在复制、删除和恢复确认中，不常驻占据画布。
- 专题说明、节点备注按需打开；没有异常不显示“待处理 0”。异常只显示紧凑入口，详情单独打开。
- 编辑区填满扣除固定导航与顶栏后的剩余高度，滚动发生在内容内部，不再在多排工具下另加固定 68dvh 区块。
- Desktop 详情默认关闭，打开时使用有宽度上限的侧栏，随时可收起。
- Android 顶栏最多两行；节点详情、筛选、搜索和日志选择器互斥，用抽屉／全屏子面板承载。软键盘出现时焦点与确认按钮仍可达。
- 常态编辑区目标：占扣除系统栏、应用固定导航后的可用内容高度，Desktop ≥80%，390×844 窄屏 ≥70%。主动打开详情／弹层和软键盘另测，不用它们混淆常态比例。

## 4. 直接编辑交互

### 4.1 大纲

- 单击选中，双击标题或 F2 原位编辑；手机选中后有明确“编辑”动作，不依赖猜测长按。
- 标题编辑时 Enter 保存；节点选中但未编辑时 Enter 新增同级、Tab 新增子级、Shift+Tab 提升层级。编辑框内 Tab 不隐式移动节点；中文输入法组合阶段不处理这些结构快捷键。
- 所有快捷键提供触屏等价入口；添加子节点、添加日志和更多操作靠近选中节点，不永远挤在顶部。
- 移动使用把手或“移动到”，保留防环校验；浏览、选中、滚动不写正式数据。
- 节点说明／引用备注按需展开；打开原日志后返回保留选中、滚动和视图。
- 保存失败保留输入；外部更新不覆盖当前草稿，提交仍校验捕获的原始基线。
- 仅在已有命令安全边界内支持撤销；外部版本变化拒绝不安全撤销，删除通过回收站显式恢复，不承诺无限撤销／重做。

### 4.2 导图

- 与大纲使用同一节点树，切换视图不复制内容。
- 双击／明确编辑操作原位改名，选中后就近添加子节点、添加日志、打开更多。
- 不再要求先进入“整理”模式；用明确编辑动作、拖动把手和防误触区分编辑与浏览。空白拖动只平移，双指只缩放。
- 缩放、适应画布放在画布角落，不另占顶部一排；删除常驻手势说明。
- 保存状态轻量显示，不为每次成功另插一整行反馈。

## 5. 搜索、待整理与筛选

- 三种入口复用查询／紧凑结果组件，但搜索、待整理和日志选择器状态独立，不共用 navigation.query 互相污染。
- 待整理定义为“当前知识库尚未引用的日志”，不是所有账号／所有库都未引用；界面范围明确。
- 待整理多选→添加到专题／节点；无目标可就地新建，有目标直接确认。部分失败保留失败项，已成功项不要求重复选择。
- 搜索放独立面板，不把整个结果区插到画布上方。
- 默认只有关键词与筛选入口。Desktop 展开紧凑条件行，手机打开专用筛选面板，应用后回到结果。
- 学科使用可点击选择；标签使用已有标签的可搜索选择，不要求记住完整标签后手动精确输入。
- 日期增加“年份”快捷选择及可选日期范围；年份转为当年起止范围，清空联动明确，非法日期就地提示。
- 已选条件显示可移除小标签，提供清空；范围／正文／隐藏内容等进筛选，不同时常驻一排复选框。
- 每行保留标题、学科／日期、必要短摘要，不重复铺标题、标签和长说明。
- 日志选择器与结果均按视口虚拟化；Desktop 普通行高目标 44–52px，触屏 52–60px，长标题有明确截断／换行规则，交互热区 ≥44px。
- 条件变化重置分页，勾选按稳定 ID 保存，滚动卸载不丢选择。
- 面板关闭时不做无需求全文扫描；先量测再增加缓存／分块处理，派生检索数据可重建，不成为同步事实。

## 6. 多库与同步管理

### 6.1 处理现有同名库

- 保留全部库及稳定 ID，不按名称合并／删除。
- 管理／切换显示名称、来源状态和专题数量；同名仍无法区分时增加短 ID，不把长 ID 放进主画布。
- 提供显式重命名。库名按本机容器元数据处理，不声称全设备共享；实现前核对 dirty generation，名称变化纳入现有备份边界。
- 新建名称必须非空，重复提示调整；同一次创建使用稳定请求身份并防重入。
- 历史同名库仍能直接访问，不强迫用户先修复名称才能使用。
- 不顺带增加永久删库／自动合并。旧库清理必须另有可核对的数据保护流程。

### 6.2 同步设置与错误

- 主画布移除“启用并发现账号知识库”；管理页称“开启知识库同步”。发现唯一默认库由系统完成，不要求用户理解内部步骤。
- 未登录提供前往登录；权限拒绝／云端未就绪说明服务配置或权限问题，可继续本机使用，不让用户无限重试。
- 网络／超时说明本机内容保留，支持安全重试；未知提交结果先核对回执，不盲目建新库。
- 非空本机库复制进账号库时，明确来源和目的，用户确认后执行，源库保留，不自动合并上传。
- 错误按安全 code／内部枚举分类，经统一 uiError 边界生成文案，禁止直接显示原始 error.message。
- 主提示回答哪一步失败、数据是否安全、接下来怎么做；诊断编号移入可展开／复制详情，并真正关联脱敏错误类别、操作阶段、版本，不含日志正文、凭据、完整账号标识，不默认上传。
- 单独调查生产规则版本、账号状态以及发现／注册／拉取阶段。部署规则、真实账号试验另行授权；不能靠放宽规则或藏掉云功能冒充修复。

## 7. 分阶段实施

### P0：锁定回归样本

补入口一致性、双返回、真实坐标遮挡、同名创建、首次专题、筛选联动和错误分类测试。准备 0／1／3 个库、100／1000／5000 条日志、深层树和长标题，全部使用隔离数据与模拟失败。

### P1：先确认工作区结构

完成首页、专题编辑器、搜索／待整理、库管理的交互样机。检查有内容、选中节点、空状态、打开筛选，不只看漂亮空页；先确认编辑区比例、返回层级、面板互斥，再接功能。

### P2：接通本机使用闭环

把 KnowledgeLibraryPage 拆成外壳、首页、专题编辑器、结果／日志选择器、详情和管理面板；查询／选择／编辑状态独立。复用 repository／commands／protocol，不重写底层协议。实现直接编辑、首次容器幂等创建、待整理归入节点、多库命名；覆盖草稿、外部更新和原日志返回。

### P3：同步与失败恢复

完成同步管理与可行动错误，覆盖登录、权限、离线、超时、账号切换、重复开启、已有默认库、非空库复制和中断恢复。线上问题另取运行证据，不用模拟测试代替生产验证。

### P4：性能与双端验收

先量旧版基线，再调查询／渲染边界。串行执行相关回归、类型检查、构建和受影响 E2E，避免并行构建污染结果。通过后提供候选包；安装覆盖、真实数据、规则发布仍需单独授权。

## 8. 验收要求

- 入口与相邻应用条目同容器、同背景／尺寸／箭头，无额外说明。
- Desktop 同屏仅一个页面返回；Android Back 先关闭编辑／抽屉，再退专题或来源，不丢未保存输入。
- 第一次新建：创建专题→输入并确认→进入编辑区，不要求先建本机库或开云。连击与取消不制造空库。
- 不点“整理”即可新建、改名、添加子节点／日志和移动；键盘／触屏皆可用，中文输入 Enter 不误提交。
- 1440×1000、1280×800、390×844、360×800，reading／modern 与 light／dark 组合；有内容、异常态均检查，常态达到编辑区比例，无横向溢出。
- 选中节点再打开查找／待整理，按当前屏幕坐标直接点学科、标签、年份／日期均能操作；测试不能靠自动滚动规避遮挡。
- 100／1000／5000 条日志下，DOM 行数随视口而非总量增长，选择器和搜索均有限制，多选不丢失。
- 性能目标：记录硬件、构建模式和样本后，输入／点击反馈 p95 ≤100ms，普通条件搜索结果更新 p95 ≤300ms。首次全文检索单独计时、可取消、不阻塞输入；Android 独立记录，不外推桌面结果。
- 三个已有同名库可区分、可打开、可重命名，内容完整；不自动合并清空。
- 每类失败都有原因、安全边界和下一步；诊断编号不是唯一提示；失败保留输入和选择。
- 浏览、缩放、筛选零正式写入；组织不改日志／复习事实；remove-wins、草稿基线、代际 fence、账号隔离、恢复副本和备份覆盖回归通过。
- 最终人工验收：用户在 Desktop 与 Android 各完成“新建专题→添加节点→筛选日志→添加引用→直接改名／移动→打开原日志再返回”，不依赖开发者指导。浏览器自动化通过不代表这一项已完成。

## 9. 本轮边界

本轮只交付此方案与隔离复现结论，未改功能代码，未跑全量测试，未读写用户安装应用的数据，未安装 APK／EXE，未部署云规则或修复真实账号云状态。比例和响应时间是后续验收目标，不是已达到的结果。
