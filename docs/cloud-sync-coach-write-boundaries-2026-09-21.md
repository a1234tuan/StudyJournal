# 2026-09-21 学习助教同步写入修复

## 问题与证据边界

用户在手机、电脑之间同步后看到三个 ai-role-config（turn-generator、question-quality-reviewer、answer-evaluator）及一个 analysis-queue-item 内容冲突，之后已在电脑选择“以云端为准”。本次修复不反向覆盖云端、不清库、不恢复旧快照，也不从截图推断某一端原先包含完整学习结果。

ADB 已识别手机，但安装的是非 debuggable 正式包，run-as 与 WebView 调试通道不可用。因此没有取得覆盖前两端的实体差异，不能证明截图中的队列冲突一定由本次发现的问题造成。电脑“分析完成”与手机“还有任务”也不是任务完成证据：分析结束本来可以生成待复习任务。

## 已修复的写入路径

1. useAppData 的练习运行时原先会在每次出题/评估前保存三个共享角色配置，将本机 providerId、model 和运行版本写入可同步实体。两端模型配置本应独立，首次各自创建角色时 createdAt 也可能不同。现在这些选择只用于实际请求，不在调用前隐式创建或覆盖 aiRoleConfigs。深度分析的 session-planner 路径同样移除隐式角色保存。
2. 已有角色配置不删除，仍沿原有同步/备份契约保留。练习请求从仓库新快照读取已有角色的 timeoutMs，缺失时使用原来的 60 秒默认值，避免同步后 React 闭包仍使用旧配置。实际模型、提示词版本与结果元数据仍由原有分析/作答流程记录。
3. 应用启动原先调用 selectNextTask，将等待任务提升为当前任务；这违背既有“初始化不得选择或替换当前任务”的边界。启动现在仅刷新到期验证、读取状态；用户显式选择任务以及正常训练后的任务推进不变。
4. 分析队列重复提交同一状态不再刷新 excludedAt、consumedAt、deletedAt 等内容字段；相同备注和已清理的 eligible 重排也不写入、不增加 cloudSyncMutation。真正的备注编辑、首次状态转换和明确重试已消费队列仍然写入。

## 保留的保护

- 未调整数据库 schema、云端实体类型、内容哈希算法、冲突判定或恢复策略。
- 未将 ai-role-config 或 analysis-queue-item 加入免冲突名单，也未采用最后写入覆盖来掩盖学习事实分歧。
- 既有、真实不同的角色策略或分析队列状态仍可能要求人工处理；修复不会自动选本机/云端。
- 已完成任务、作答结果、延迟验证与分析队列继续同步；没有把整个学习助教改成本机数据。
- 未修改 ASR、TTS、录音、缓存重播或正式复习评分逻辑。

### 新确认的风险及修复

1. **同步后的自动重复解读。** 启动/刷新/恢复网络时会扫描全部 eligible 反馈，包括另一端同步来的反馈；pending/running 解读又不是正式同步结果，因此两端可能分别请求 AI，向同一反馈解读实体写入不同结果。现在只自动续跑本次应用实例中由本机评分创建或明确请求的反馈，成功/上下文不足/失败后释放自动执行资格。进程重启或其他设备收到的未完成反馈需手动开始/继续整理，失败重试仍可用；仅展示或同步不会调用 AI。没有添加持久化设备归属或跨端分布式锁。
2. **旧 AI 回调覆盖同步结果。** 原先请求返回时未校验该解读行是否已被同步、恢复或用户确认替换。仓库现在在同一 Dexie 事务中比较请求预期的完整行；成功、失败、取消回写都带此条件，不匹配即拒写，也不增加 mutation。正常请求仍可完成，明确的人工修改不受此条件误拦。此保护针对反馈解读，不代表所有 AI 流程已有分布式锁。
3. **重复刷新断开未完成复查任务。** 原先到期刷新会无条件清掉 provisional completed 验证的 taskId，即使该 task 正在等待/进行/延期；随后 open-target 去重阻止重新排队，关联就丢失。仓库现在对空关联和活动任务保持无写入，只允许脱离已结束任务，悬空关联仍报错而非静默重建。
4. **复查多窗口复用任务身份。** 原先每轮均使用 verification-task:<verificationId>，可能撞到历史任务。现在初轮身份保持兼容，后续按 nextVerificationDueAt 生成稳定身份，同一窗口若已有结束尝试则使用确定性 retry 后缀；旧题目、任务和结果保留。completed 是已发生的验证动作而非已经得出客观结论，因此复查启动不把它倒退到 in-progress，首题仍为 delayed-first；完成路径接受关联的到期复查，延期不丢关联，放弃后可重新排队。
5. **重复操作重写证据时间。** 相同任务状态和相同验证结果现在直接返回原行，避免 endedAt/lastVerifiedAt 被重复点击改写。显式修改终止原因仍保存，但不更改原完成时间。未放宽状态机、正式学习判定或冲突保护。
