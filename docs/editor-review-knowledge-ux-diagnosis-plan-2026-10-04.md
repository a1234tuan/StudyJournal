## 3. 草稿与保存故障

### 3.1 已确认缺陷链

- src/pages/RecordEditorPage.tsx:526：草稿时间晚于正式记录时恢复；保留草稿 baseUpdatedAt，并在与正式记录不同时标记 stale。防止旧草稿覆盖新内容的目的正确。
- 同文件 :333：草稿内容没有变化、没有重点块操作意图时，flushDraft 返回 false，根本不执行写入。
- 同文件 :384：flushDraftDetached 又将真实异常折叠为 false。因此返回值混合“无需写入”“受阻”和“失败”。
- 同文件 :837：基线冲突时调用该方法，再把 false 显示为“本机草稿保存失败”。重复点击不改变基线，本轮已实际复现零写入、持续报错。
- 同文件 :879：正式保存异常的兜底也有相同误分类，可能遮盖原始正式保存失败。
- 同文件 :960：顶部使用另一套状态，可以与正文错误矛盾。
- src/lib/uiError.ts:52：编号来自上下文前缀、时间片段、序号，未关联可查询错误记录。RDS 只表示 record-draft-save 上下文，不能证明配额、磁盘或数据库故障。

**与截图相同的现象已复现，但不能据此断言用户那条真实记录必定属于此分支。** 本轮是点击保存后复现；“刚打开就出现错误”的具体时序、旧状态残留或真实写入拒绝仍需安装版取证。关机未保存可以解释草稿存在，不能单独解释持续无法保存。

### 3.2 正式提交与后续操作的边界

- src/services/storageAdapter.ts:1115 已在事务中检查 expectedRecord、写正式内容、删除对应草稿。含重点块的路径位于 src/features/reviewCoach/repository.ts:627，也有事务保护。不得另建绕过这些保护的保存路径。
- src/hooks/useAppData.ts:316 在数据库成功后仍等待 refresh 和备份 dirty 标记；它们失败不等于正式事务失败。
- src/App.tsx:1257 没有传回底层保存结果。编辑页后续还有加入复习、归档刷新和再次删除草稿，都在同一 try/catch。
- 必须分清“正式事务未提交”和“正式已保存、后续动作失败”，避免后者又恢复成未保存状态或重复提交。

### 3.3 实施契约

1. 用 saved / unchanged / blocked / failed 判别联合取代草稿布尔返回值。blocked 说明 loading、restore、commit 等原因；只有 failed 是写入失败。unchanged 自身不证明已经落盘。
2. 统一编辑保存状态：读取中、仅内存、草稿排队/写入/已提交、版本冲突、正式保存中、正式已提交、后续警告、真实草稿失败。顶部、正文与按钮由相同事实派生。
3. 正常恢复草稿使用信息提示；版本变化显示“需要核对版本”，不借用磁盘失败文案。明确正式变化也可能来自本机，不一律称另一设备修改。
4. 冗余草稿：比较统一规范化的全部可编辑字段、资源/公式引用及重点块删除/恢复意图。用户确认采用当前正式记录后，事务内重读并校验正式行和捕获草稿行未变化，仅清理该草稿，不覆写正式内容、不产生评分和学习事件。
5. 内容不同：并排查看最新正式内容和当前草稿；可保留草稿、继续核对，或明确确认采用当前编辑内容。确认后捕获最新正式完整行作为 expectedRecord；提交时又变化则再次拒绝。不能默认丢弃、覆盖或自动选“最新时间”。
6. 旧草稿只有基线时间，不能推导完整三方共同祖先；本阶段不承诺自动三方合并，不静默更新 baseUpdatedAt 绕过保护。重点块删除/恢复意图须重新核对，不能继承对未知新版本的旧授权。
7. 保留正式提交前等待资源、草稿队列及取消 Markdown 转换的顺序。保存调用链返回明确提交结果；refresh、备份 dirty、加入复习失败使用独立警告和重试。备份 dirty 失败不能静默忽略，必须保留待处理状态。
8. 提供从当前编辑器/内存草稿保留内容的出口，不能按 ID 导出旧正式记录。结构化副本保留 HTML、资源引用及重点块意图；未打包资源字节时明确不是完整备份。纯文本复制不保证表格、公式、附件全量恢复。
9. 诊断仅本机、最小化：阶段、异常 name/code、基线一致性、写入结果、构建标识，不记录正文或凭证。关联编号的信息使用内存缓冲与手动导出，不能依赖同一个故障数据库才能报告错误。
10. 异步结果按记录 ID 和编辑会话代次隔离；切换记录重置相应状态，避免旧请求/错误污染新页面。

### 3.4 红绿回归与验收

- 旧基线同内容且无重点块意图：不误报失败；显式收敛后不再恢复同一冗余草稿，正式内容未覆盖。
- 旧基线不同内容：保留两份并给出核对出口，重复保存不是死循环。
- 核对过程中同步、收藏、软删除、恢复：拒绝过期基线，不复活已删记录。
- 配额、事务中断、普通写入拒绝：显示真实失败，重试成功清除对应错误，不泄露正文。
- 无变化/恢复锁定/加载未完成：不是失败，也不假称已持久化。
- 正式成功但 refresh、备份 dirty 或加入复习失败：不重新变成未保存，不重复生成正式/复习事件。
- 队列交错、跨记录切换、资源上传未完成、退出重启、重点块意图保护全部覆盖。

## 4. 表格误选

### 根因

- src/components/RecordStructureNodes.tsx:843 定义 recordComparisonTable 为 atom: true，未禁用 NodeSelection；不是逐格可编辑的 ProseMirror 原生 table schema。
- src/lib/markdownEditor.ts:350 将 Markdown 表格也解析为此节点；其他历史 HTML 形态需另补样本。
- RecordStructureNodes.tsx:518 单元格 contentEditable=false，React 单击打开 textarea 晚于编辑器 mousedown 的节点选中。
- 当前安装的 prosemirror-view/src/input.ts:195 对可选 atom 创建 NodeSelection；Tiptap 默认 NodeView 放行该 mousedown。
- src/styles.css:5274 把 selected 与 focus-within 合成整块高亮，放大“全选”观感。本轮确认为整表节点选择，不是文字全选。

### 实施

1. 保留现有 atom、序列化和剪贴板格式；不直接迁移原生 table schema、不升级依赖碰运气。
2. 在 ComparisonTable NodeView 事件边界阻止单元格普通 mousedown 被解释为整块选择；不是全局关掉 NodeSelection，也不是全局 preventDefault。
3. 保留原生文字拖选。只读单击不创建节点选择；局部、跨格、跨表与正文复制继续使用已有序列化。
4. 编辑单击仍进入该格，不调用 select()，只显示局部焦点；整块操作仍有明确工具栏/选择入口。
5. 不吞 copy/cut/paste、链接、公式、按钮、输入控件和键盘事件。移动阈值区分点击与拖选，避免拖选结束切成 textarea 导致选区丢失。
6. 不仅隐藏高亮样式，必须断言真实 editor.state.selection；只读切换及遗留 NodeSelection 也应收敛。

### 验收

覆盖日志预览/编辑、普通复习、安排复习卡片及折叠内表格；真实单击、双击选词、跨格拖选、外部粘贴、输入/撤销/Escape/失焦、横向滚动、链接公式。单元格编辑时直接点正式保存，末次输入不得丢失或重复提交。安装版 Electron 的真实选区与外部 text/plain 粘贴另设必过门槛，Chrome 合成事件不能替代。

## 6. 导图：先改交互，再改视觉

### 6.1 现状与问题

已有双向树、颜色、缩放、平移、拖动预览、折叠、键盘、内联改名、日志详情和节点裁剪，不应全部推倒。

- KnowledgeMap.tsx:197：鼠标选择固定等待 220ms，以区分双击，反馈延迟是设计选择。
- KnowledgeLibraryPage 的 onSelect 总同时打开详情，轻量选择与阅读面板耦合。
- KnowledgeMap.tsx:73：详情打开且比例低于 .85 时强制 .85；已复现 48% → 85% 的镜头跳变。
- wheel 每事件固定乘 .9/1.1，不使用连续 delta；双指缩放默认锚点为视口中心，不是手指中点。
- presentation.ts:84 按字符估宽（非 ASCII 15px、ASCII 9px），与实际字体、换行和缩放不完全一致。
- 节点直接改 left/top、连线直接改 path，缺少统一布局过渡与锚定。
- 性能风险：移动驱动整组件状态，连线可见性逐个 visible.includes 重复扫描；端点均在屏外的穿屏连线不能只按端点裁剪。尚未测量大图卡顿，不宣称已证明性能问题。
- 实景中普通节点 14px、细线和三个散列分支色配大量留白，焦点与操作层级偏弱；这是设计评估，不当作客观错误。

### 6.2 推荐方向：阅读优先、轻量编辑、稳定视口

做专题工作台，不做无限白板。导图负责理解结构与定位，侧面板负责日志阅读和备注；品质来自层级、密度、对齐、反馈和稳定运动，不靠玻璃、渐变和装饰卡片。

1. 单击即时选择，不为双击延迟全部反馈；双击/F2 改名，拖动过阈值才移动。默认通过日志数/详情按钮开面板；已打开时跟随选择，不反复开合。这改变旧“单击即开详情”契约，须先确认样板并更新相关测试。
2. 选中不改 zoom；面板打开仅在必要时做最小平移；聚焦分支、回中心、查看全貌为显式命令。关闭面板恢复上下文。
3. 触控板双轴平移；Ctrl/Cmd+滚轮按指针锚连续缩放并归一化 deltaMode；双指按中点缩放及平移；单指平移、长按节点移动。不抢工具按钮和编辑控件。
4. 保持左右分支稳定；统一字体测量与缓存，对字体加载、字号、主题变化失效。折叠/插入/改名以所选节点为锚，仅重排受影响区域。
5. 布局变化用统一插值驱动节点与连线，初始建议 160–220ms；实时拖动/缩放不加拖尾，尊重 reduced-motion。不能节点慢动、连线瞬跳。
6. 中心/一级/普通节点及悬停/选择/编辑/拖动/非法落点区分清楚；稳定且克制的分支色不作为唯一编码。普通节点先试 15–16px，再用长中英文标题验证密度。
7. 日志数量成为明确入口；桌面可调宽侧栏、手机底部面板；开关阅读保留缩放、选中、日志滚动。每个节点不塞满按钮。
8. 保持方向键、F2、Enter 同级、Tab 子级、Escape 取消语义；不拿 Enter 打开详情而破坏新建。输入法、根节点、受保护来源与弹窗各有边界。
9. 相机状态与知识内容/布局分离；requestAnimationFrame 合并高频输入；缓存布局/可见 ID/连线索引；焦点与编辑节点不被裁掉。先量性能，暂不更换图形引擎。
