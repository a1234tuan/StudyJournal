## 1. 结论摘要

当前产品的功能深度已经明显超过界面体系的成熟度。日志、复习、搜索、离线存储、云同步、AI 问答和 Review Coach 都具备真实能力，但界面仍以“把新功能追加到现有页面”为主要生长方式，导致首页、复习页、“更多”页和编辑器不断吸收新的容器、字段和按钮。

这不是单纯的颜色或圆角问题，根因有四个：

1. **信息架构仍按功能清单组织，而不是按学习任务组织。** 桌面端有 8 个一级导航入口，移动端却把同一批能力折叠为 5 个底栏入口和一个“更多”目录，两端的心智模型不一致。
2. **页面缺少稳定的主任务、次任务和高级能力层级。** 首页同时承担新建、待复习、AI 深度分析和日志流；复习页同时承担当日复习、卡片管理、反馈采集、AI 解释和队列管理。
3. **视觉原语过少，页面级 CSS 过多。** 公共 UI 只有 `SurfaceCard`、`ActionButton`、`PageHeader`、`ListRow` 四组基础抽象，而样式由 6064 行旧总样式和 3705 行页面样式叠加覆盖，页面只能不断添加专用类名。
4. **响应式策略主要是压缩和换行。** 移动端没有围绕单手操作、软键盘、底部安全区和渐进披露重新编排任务；桌面端也没有充分利用侧栏、检查器和主内容栏。

重构建议不再让“AI 驾驶舱”以一级、常驻大面板的形态存在，而将 `复习 > 学习助教`确立为稳定的二级目的地。AI 的上下文反馈进入日志和复习流程；批量分析、OCR 风险、用量预估、暂停恢复和任务编排由学习助教完整承接。首页只保留条件式摘要，不直接删除现有工作台能力。

### 1.1 外部设计评审后的修订结论

本版接受外部评审提出的八项风险，其中第 1、2、3、4、5、6、8 项完整采纳，第 7 项按“默认简化、按需透明”修订，而不是把成本信息完全隐藏：

- **驾驶舱能力不能随入口一起删除。** 先用“学习助教中心”逐项承接批量选择、OCR 检查、用量预估、部分批次恢复、调度和结果承接，通过能力对照验收后才能撤销旧入口。
- **视觉重构不自动获得修改业务语义的授权。** 新建正式记录、草稿保护、正式保存、复习评分、卡点反馈、撤销和同步继续遵守当前事务边界；任何语义变更另开 RFC。
- **信息架构必须只有一个归属答案。** 学习洞察归属“复习”；“工具”与“设置”职责分开且设置只有一个规范目的地；AI 问答、学习助教和知识播客按任务区分；学科浏览保留一触即达。
- **视觉方向必须能被看见和量化。** 在全量编码前制作首页、日志资料库、编辑器、复习会话、学习助教、设置中心六个页面的 Desktop/Mobile 高保真可交互原型，共 12 个基准画面，并用真实长文、空态、错误态和窄屏验证。
- **编辑器检查器按内容出现。** 不永久占用右栏，宽内容也不是例外补丁，而是表格、代码和结构内容的正式布局模式。
- **组件基础与页面迁移不重复立项。** 第一阶段只建立首个垂直切片必需的原语，后续页面按需扩充；“体系化一致性”负责覆盖率和旧 CSS 退役。
- **AI 用量默认用用户语言展示。** 精确 token、模型、子批次和估算限制进入“查看用量详情”，不会从自带 API 用户面前消失。
- **禁止暴露原始异常是 P0。** 当前复习页存在直接展示 `error.message` 的路径；重构开始前必须建立错误归一化和脱敏诊断边界。

## 3. 全局问题与根因

### 3.1 产品层级被功能增长冲淡

日志记录、日志回看和复习本应构成产品的三个主要动词，但 AI、录音、统计、设置在桌面端获得同等一级权重。移动端又将其中四项放进“更多”，造成跨设备导航模型不一致。

**结果：** 新用户难以立即判断产品主线；熟练用户需要记住同一功能在不同设备上的不同位置。

### 3.2 卡片承担了过多本应由排版解决的层级

首页的新建区、复习提醒、日期组、记录行、空状态，分类列表和设置面板大量依赖“白底 + 边框 + 阴影”。`SurfaceCard` 本身默认附带边框、表面和阴影，页面在缺少其他区分手段时自然继续堆卡片。

**结果：** 所有信息都像可点击重点，但真正的主操作反而不突出；移动端出现连续大块容器，滚动成本高。

### 3.3 页面组件过大，交互状态彼此耦合

- `RecordEditorPage.tsx` 1219 行，`RichTextEditor.tsx` 2099 行。
- `ReviewPage.tsx` 1435 行，同时管理队列、卡片库、撤销、筛选、复习重点反馈和 AI 解释。
- `AiChatPage.tsx` 1024 行，`App.tsx` 约 1475 行。

**结果：** 很难单独重排移动端体验；页面级状态会迫使 CSS 通过更多专用选择器修补布局。

### 3.4 视觉规范存在，但不是完整设计系统

已有主题变量、焦点环、动效时长、深色模式和 Lucide 图标，这是应保留的基础。但缺少稳定的类型阶梯、密度模式、表单字段、工具栏、菜单、Dialog/Sheet、Skeleton、Inline Status、Save Indicator 等组件契约。

**结果：** 相同语义使用不同结构：有的返回按钮由 App 壳层提供，有的页面自己提供；状态既可能是页面内段落，也可能是底部 Toast；确认操作既可能展开行内区域，也可能出现弹窗。

### 3.5 反馈层和导航层争抢底部空间

移动端浮动底栏使用固定 78px 高度并悬浮于内容上方，见 `src/styles/layout.css:352-379`。全局复习 Toast 又固定在底栏上方，见 `src/styles.css:292-310`。真实交互中，该 Toast 会拦截 AI 菜单项点击。

**结果：** 复习评论、评分控件、“更多”列表和菜单可能被遮挡或无法点击。此项属于 P0 可用性缺陷，不应等到视觉重构后再解决。

### 3.6 文案混用产品语言与实现语言

页面同时出现 `New Record`、`Month Logs`、`Record context`、`Adaptive Review`、`Delayed Verification`、`tokens`、`v1`、`子批次`、`FSRS` 等词。普通用户无需理解模型上下文、版本号或调度实现。

**结果：** 产品像开发/分析控制台，削弱学习工具的亲和力和可信度。

### 3.7 原始运行时异常穿透到用户界面

`ReviewPage` 的评分、撤销和延期失败分支会直接插入 `error.message`，见 `src/pages/ReviewPage.tsx:647-659`、`690-693`、`725-734`。因此 Dexie、IndexedDB、对象存储名和底层事务文本可能原样显示在学习流程中。

**结果：** 用户既无法据此恢复，也会误以为数据已经损坏；异常详情还可能包含不应进入普通界面的实现信息。

**处理原则：** UI 只能接收稳定错误码、面向用户的中文说明和明确动作。原始异常进入本地脱敏诊断记录，生成可复制的短诊断编号；只有“查看诊断详情”才显示经过清洗的技术信息，且不得包含 API Key、Prompt、正文、供应商原始响应或同步载荷。

### 3.8 必须保留的现有交互与数据契约

- `createRecordBlock` 当前会立即调用 `storage.saveBlock` 持久化正式记录，见 `src/hooks/useAppData.ts:713-743`；因此“一键空白草稿”不是无数据影响的视觉改动。
- 编辑器变化会持续写入本地 `RecordDraft`，显式保存再提交正式内容，见 `src/pages/RecordEditorPage.tsx:265-346`。
- 复习评分、复习日志、决策块反馈、分析队列、日统计和投影重建位于同一 Dexie 事务，见 `src/services/storageAdapter.ts:1118-1266`。
- 撤销会恢复旧复习状态、写入撤销事件、tombstone 同次反馈并重建 Review Coach 投影，见 `src/services/storageAdapter.ts:1309-1356`。

这些契约是重构测试的基线。视觉层可以改变呈现顺序和渐进披露，但不能把一次原子操作拆成多笔松散写入，也不能把本地草稿状态描述成正式保存或云端同步。

## 4. 逐页面审查与目标方案

### 4.1 首页 / 今天

**当前问题**

- `TodayPage` 顺序为页面头、新建卡片、待复习横幅、完整 Review Coach 工作台、日志标题和记录列表，见 `src/pages/TodayPage.tsx:91-199`。
- Review Coach 只要回调存在就整块渲染，并非按用户当前任务或信息重要度出现，见 `src/pages/TodayPage.tsx:155-167`。
- 桌面端首屏有四个以上高权重区域；移动端 AI 分析内容将当日日志推到数屏之后。
- 新建记录要求先确定学科、可选模板，再点击带动态文案的按钮；对“先写下来”的场景仍有摩擦。
- 日期、每日格言、目标倒计时、同步、收藏同时占用页头注意力。

**目标布局**

- 首屏唯一主操作：`记录今天学到的内容`。第一轮 UI 重构继续调用当前正式记录创建流程，不擅自引入新的“临时记录”语义；学科和模板通过轻量 Quick Create 展开确认。后续若要做到真正一键进入空白草稿，必须另行决定空草稿退出、默认学科、同步资格和恢复规则。
- 待复习仅在有任务时显示为紧凑任务行：数量、预计时长、开始按钮。
- 最近记录使用无卡片列表，显示 3-5 条；“查看全部”进入日志页。
- Desktop 可在右侧窄栏展示本周节奏和一个当前建议；Mobile 采用单列顺序：记录 -> 待复习 -> 最近记录。
- AI 只在有明确动作时出现一条上下文建议，例如“有 2 个卡点可生成针对性练习”；无动作时完全不占位。

### 4.2 日志编辑器与日志详情

**当前问题**

- 顶栏、标题/标签/学科、工具栏、正文分别成为独立块，见 `src/pages/RecordEditorPage.tsx:786-1132`。
- 当前移动端真实首屏中，标题卡片和两至三行工具栏占据大部分高度，正文仅剩一小段可见区域。
- 编辑时应用底栏仍可见；即使键盘弹出后会隐藏，未弹键盘时仍与编辑工作区竞争空间。
- 工具栏一次暴露标题层级、引用、代码及语言、附件、公式、结构块、录音等能力。高频格式与低频插入没有分层。
- Desktop 中内容仍是单列卡片堆叠，左右空白没有转化为大纲、元信息、附件或引用检查器。
- 保存是显式按钮，草稿恢复、保存错误和导出状态都复用页面内 `status-message`，缺少统一“正在保存/已保存/离线/失败”状态模型。

**目标布局**

- 进入编辑即切换为专用工作区，隐藏全局侧栏/底栏；退出后回到来源页面和滚动位置。
- 标题为文档中的无边框大标题；下一行用紧凑元信息展示日期、学科、标签，点击后在 Popover/Sheet 编辑。
- Desktop 不采用永久固定窄列。标准文字内容使用 680-760px 居中阅读列；表格、代码、结构图和便签板可切换 960-1200px 宽内容模式。检查器只在宽度至少 1280px 且存在附件、引用或复习属性时停靠为 280px，否则以抽屉打开且不预留空白。用户可在“专注 / 标准 / 宽内容”三种布局间切换。
- Mobile：52px 顶栏；正文使用 16px 安全边距并尽可能占满高度；键盘上方仅保留粗体、斜体、列表、高亮和“更多”，插入能力进入 `+` 菜单或底部 Sheet。
- 桌面主工具栏单行分组，溢出菜单收纳代码语言、结构块和低频操作；文本选区出现上下文工具条。
- 保留当前双层保存契约：编辑过程只自动写入本地 `RecordDraft`，顶部显示 `草稿已存于本机`；显式“保存”才把内容提交为正式 `RecordBlock` 并进入现有同步边界。不得把草稿保护误写成“已同步”或“正式记录已保存”。是否将来改为正式记录自动保存，必须作为独立产品/同步 RFC 评估。
- 阅读模式直接显示高频“编辑”入口；“加入复习”“AI 提问”和低频操作进入页面操作菜单。

### 4.3 日志列表与回看

**当前问题**

- 日志页先显示“本月有记录日期”卡片，再显示一个面积很大的月历/热力图，见 `src/pages/JournalPage.tsx:81-192`。

### 4.7 AI 驾驶舱 / Review Coach

**任务定位**

它服务的不是“查看 AI 系统状态”，而是三个用户任务：发现复习中的真实卡点、进行短时针对性训练、间隔后验证是否仍能独立提取。

**当前问题**

- 首页工作台显示候选块、上下文预览、评论、选中数、自动子批次、预计 tokens、OCR 缺失、供应商、最近批次和训练效果，见 `src/features/reviewCoach/ReviewCoachWorkbench.tsx:111-281`。
- `v1`、等待天数、子批次、token、问题类型/练习类型英文枚举和“证据不足”是系统状态，不是用户任务。
- 独立预览页将“驾驶舱、自适应训练、延迟验证”并列，这适合作为验收工具，不应直接成为产品 IA。
- 自适应复习页仍展示 `目标版本 v...`、`Delayed Verification` 和 FSRS 技术说明，见 `src/features/reviewCoach/AdaptiveReviewPage.tsx:92-184`。

**建议结论**

不保留常驻首页或一级导航级的“AI 驾驶舱”。`复习 > 学习助教`是稳定、长期存在的二级目的地，不是迁移完成后还要拆散的临时页面；其他位置只能提供打开同一页面的快捷链接。中心分为四个任务视图：

- `待分析`：批量选择学习重点；在确认前汇总重点数、缺少 OCR 的图片数和预计用量等级；允许排除重点和补充本次分析说明。
- `进行中`：承接已确认、运行中、部分完成和失败批次；使用“已完成 3/6 个重点”等用户语言，并提供现有接口支持的继续、恢复和重试。只有完成业务接口与状态转换设计后才能新增“取消分析”。
- `训练与验证`：显示当前任务、接下来两项、延期项和到期验证；默认由调度器排序，用户可在“管理队列”中调整当前项或延期。
- `学习洞察`：样本足够后展示练习效果；证据不足时只说明“继续完成几次验证后可形成趋势”，不展示内部分类和误导性百分比。

能力迁移期间，旧工作台入口只从首页撤下，不能删除其批量分析和恢复能力。完成以下对照验收后才可移除旧入口：候选数量一致、OCR 风险一致、分析计划一致、暂停批次可恢复、生成任务一致、当前/等待/延期排序一致、结果投影一致。

**字段处理**

- 保留：日志标题、学科、用户原始卡点、练习目标、预计用时、任务状态、到期时间、重点数量、OCR 完整性、用量等级和可执行动作。
- 重命名：`Adaptive Review` -> `针对性训练`；`Delayed Verification` -> `间隔验证`；`Blueprint objective` -> `本次目标`。
- 默认摘要：`将分析 6 个学习重点 · 预计用量中等 · 2 张图片没有可用文字`。用量等级表达相对输入规模，不伪装成精确金额。
- “查看用量详情”中保留：预计 token、模型、子批次数、供应商计费提示和估算限制；使用自有 API 的用户仍能判断成本。
- 普通界面隐藏：内容版本、内部 problem/practice type、状态机枚举和 FSRS 技术边界。
- 用户主动确认发送材料时可以查看完整学习材料预览，这是正常内容查看，不属于错误诊断。错误诊断模式只显示允许字段、状态码和脱敏元数据，不显示日志正文、Prompt 或供应商原始响应；质量评估内部字段仅在开发调试模式可见。暂停/恢复不能藏进诊断模式，因为它是用户可恢复操作。

## 5. Desktop 与 Mobile 专项问题

### 5.1 Desktop

- 260px 固定侧栏加单列 1120px 页面，超宽屏空白较多；没有利用双栏主从结构。

## 7. 新信息架构与主要路径

### 7.1 Desktop 导航

1. **今天**：记录入口、今日复习、最近日志、一个当前建议。
2. **日志**：最近列表、日历、学科/标签、收藏和全文搜索。
3. **复习**：首页提供“日志复习”和“学习助教”两个主要入口，“卡片库”作为管理入口；待分析、进行中、针对性训练、间隔验证和学习洞察都组织在同一个学习助教页面内。
4. **录音**：录音库与播放。
5. **工具**：AI 问答、知识播客、模板和其他低频创作工具；它是工具启动器，不承载账户或系统设置。

侧栏底部固定同步状态和唯一的齿轮“设置”入口；不存在第二个“更多设置”。AI 不作为一级导航；全局搜索位于壳层顶部并支持快捷键。侧栏顶部提供明确的“新建记录”按钮。

### 7.2 Mobile 导航

底栏使用四个稳定目的地：今天、日志、复习、工具；中央 `+` 是全局动作，不是第五个 Tab，不获得选中态，也不改变当前 Tab。原型同时比较两条路径：当前学科已经明确时直接新建，以及展开 Quick Create 后确认学科/模板；取消时原 Tab、筛选和滚动位置不变。只有确认或明确沿用当前学科后才按现有逻辑创建正式记录并进入编辑器，退出后回到来源页面状态。进入编辑、复习会话、AI 问答、播放器和设置详情后隐藏底栏，改为局部导航。

Mobile 的设置入口只存在于“工具”页右上角齿轮，目标与 Desktop 侧栏底部设置完全相同。“工具”页不复制设置项目，只列出 AI 问答、知识播客、录音、模板等可直接启动的能力。

### 7.3 功能归属与边界

- **学习洞察**：归属 `复习`，汇总记录级复习节奏和 Review Coach 验证结果；日志页只在单条日志详情显示与该日志有关的简短结果。
- **AI 问答**：即时、用户发起、围绕选定日志或搜索范围回答问题，不创建 Review Coach 训练任务。
- **学习助教**：结构化处理复习卡点，负责批量分析、针对性训练、延期与验证，并受正式事实和调度规则约束。
- **知识播客**：把用户选择的内容生成可收听材料，音频和记录保持本机专属，不进入云同步，也不与 AI 问答历史混合。
- **学科浏览**：从“日志”顶部保留常驻学科筛选按钮；Desktop 一次点击展开学科栏，Mobile 一次点击打开带最近学科的 Sheet。学科管理才进入设置，浏览不增加层级。

### 7.4 核心路径

- 记录：打开 App -> 首页主按钮沿用明确显示的当前学科直接创建，或通过 `+` 展开 Quick Create 确认学科/模板 -> 创建正式记录并进入编辑 -> 本地草稿持续保护 -> 显式保存正式内容 -> 返回来源页面。
- 回看：日志 -> 最近/日历/学科切换 -> 打开详情 -> 编辑、加入复习或提问。
- 复习：首页任务行或复习 Tab -> 单条复习 -> 可选展开并记录卡点 -> 评分与卡点原子提交 -> 可选生成针对性练习。
- AI 辅助：从具体日志/卡点进入 -> 先带入上下文 -> 用户确认范围 -> 生成反馈/练习。
- 同步：全局状态可见 -> 点击执行增量同步 -> 成功静默收敛；仅冲突、异常或大流量计划要求用户决策。

## 8. 建议视觉语言与设计系统

### 8.1 气质

关键词：清爽、专注、可信、耐读。采用偏中性的明亮背景和白色工作面，深绿作为“学习/完成”主色，蓝色承担链接、信息和同步状态，暖色仅用于提醒。避免整页米黄，也避免深蓝/紫色单色化。

### 8.2 排版

- 默认不依赖网络字体。字体栈为 `"Segoe UI Variable", "Segoe UI", "PingFang SC", "Microsoft YaHei UI", system-ui, sans-serif`；Android 使用系统 `sans-serif`。如果未来选择 Inter，只能随应用打包经许可的 WOFF2，并继续由上述本地字体作为离线回退。
- 固定类型阶梯，不随视口宽度缩放：Display 28/36/700（仅首页日期或空态主句），Page 24/32/650，Section 18/26/600，Body 15/24/400，Small 13/20/400，Meta 12/18/550。
- 中文编辑正文默认 16/28，阅读详情 16/29；紧凑列表 14/20。正文行长 34-42 个中文全角字符或 58-72 个西文字符；编辑器由用户字号设置整体缩放。
- 字重限制为 400、550/600、700；避免大面积粗体。
- 英文 eyebrow 只在确有分类价值时使用，不作为每页装饰。
- 日期、进度和用量数字使用 `font-variant-numeric: tabular-nums`，避免状态更新造成宽度跳动。

### 8.3 色彩与表面

- 明亮主题试验值：Canvas `#F5F7F6`，主工作面 `#FFFFFF`，次级带 `#EEF2F0`，主文字 `#18201C`，次文字 `#5C6862`，结构线 `#D9E0DC`。它们不是冻结 token；必须先放入真实中文内容原型，与更中性的灰白方案对照并通过对比度校验后再决定。
- 品牌/完成使用森林绿 `#176B52`，链接/同步使用蓝 `#2563A6`，提醒使用琥珀 `#A45B08`，危险使用红 `#B42318`。页面不能由同一绿色家族铺满。
- 主色仅用于主按钮、当前导航、完成状态和焦点环。
- 蓝色用于链接、同步和信息提示；橙色用于到期/警告；红色只用于危险和错误。
- 表面层级不是靠卡片堆叠：L0 是全页 Canvas；L1 是连续工作面；L2 是通过 24-32px 间距、标题和 1px 分隔线形成的区域；L3 才是重复实体、浮层或独立工具。普通段落和设置分组不得自动进入 L3。
- 圆角：页面/卡片 6-8px，控件 6px；只有标签、状态和分段控件可使用胶囊形。
- 阴影只用于浮层、菜单、拖拽项和悬浮播放器；普通列表/区块无阴影。
- 深色主题不是颜色反转：Canvas 使用近黑中性层，正文工作面只比 Canvas 提升一个明度层级；降低高饱和状态色亮度并增加结构线对比，正文保持舒适的非纯白文字。高保真验收分别调整暗部层级、代码块、图片遮罩、焦点环和禁用态。

### 8.4 密度与空间

- Desktop 页面最大内容宽 1200px，左右内边距 32px；Mobile 左右内边距 16px；平板为 24px。
- Desktop 顶栏 56px、侧栏 232-248px、单行标准列表最小 52px、紧凑列表最小 44px、单行表单字段 40px、主要按钮 40px。Mobile 顶栏 52px、列表行至少 56px、字段和按钮 44-48px；长标题、大字号、帮助或错误出现时必须自然增高。
- 页面标题到底部工具栏间距 20px；一级分区 32px；分区内标题与内容 12px；同组字段 16px。密度切换只允许在日志资料库和管理列表使用，不影响编辑/复习触控尺寸。
- 首页 Desktop 首屏在 1440x1000 下应同时看到主记录入口、待复习任务和至少 3 条最近日志；Mobile 390x844 下应看到主记录入口、完整待复习行和最近日志标题，不依靠缩小字号实现。
- 日志资料库在默认字号和普通标题下，Desktop 每屏目标显示 10-13 条标准记录，Mobile 每屏 7-9 条；长标题和大字号优先保证可读性，不为达成数量强压行高。设置中心使用连续分组列表，不把每个字段包成独立卡片。

### 8.5 控件与组件外观

- 图标统一使用 Lucide：正文操作 18px，紧凑工具栏 16px，移动主操作 20px；图标按钮必须有 Tooltip 和可访问名称。不得混用手写 SVG、文字箭头和不同笔画粗细。
- 主按钮使用实色主色背景；次按钮为中性描边；三级动作使用图标或文字；危险操作只在确认点转红。页面同一视口通常只有一个主按钮。
- 分段控件只用于 2-4 个互斥视图；筛选使用带状态点/数量的 Filter Button；二元偏好使用 Switch 或 Checkbox，不用带文字的圆角块模拟。
- 菜单宽度 220-280px，项目高 36-40px，图标、标签和快捷键三列对齐；Mobile 同类操作转为底部 Sheet。状态提示优先使用行内图标 + 短句，Banner 只用于跨区影响，Toast 只用于已完成且无需持续处理的事件。
- 输入框默认无厚重容器；标签始终稳定，帮助和错误按需出现并推动下方内容，不预留机械的三行空槽。错误不造成横向跳动，保存、同步和生成按钮在 Loading 时保持原尺寸。

组件按垂直切片增量建立，不先造完整组件库。首个切片只需要：`AppShell`、`WorkspaceHeader`、`NavItem`、`ActionButton`、`IconButton`、`ListItem`、`QuickCreateSheet`、`SaveIndicator`、`Toast`、`InlineError`。迁移到复习、搜索和设置时再加入 `Toolbar`、`OverflowMenu`、`Field`、`SegmentedControl`、`FilterBar`、`StatusBanner`、`Dialog`、`MobileSheet`、`Skeleton`、`EmptyState`、`UndoBar`。

`SurfaceCard` 不再作为默认分区；改为有明确语义的 `EntityCard`。页面不得出现卡片内再嵌同形卡片。

### 8.6 高保真视觉证明门槛

在改导航和批量迁移页面前，必须先完成六个真实页面的 Desktop 1440x1000 与 Mobile 390x844 高保真可交互原型，共 12 个基准画面：

1. 首页：有待复习、有最近日志、仅一条条件式 AI 建议。
2. 日志资料库：长标题、多个标签、学科筛选、搜索命中和密集列表。
3. 编辑器：长文、表格/代码宽内容、`草稿已存于本机`、正式保存失败和移动键盘状态；阅读态保留直接可见的“编辑”入口。
4. 复习会话：卡点折叠/展开、评分、原子提交中、撤销和错误恢复。
5. 学习助教：批量选择、OCR 缺失、用量摘要、部分批次恢复、训练/验证队列和洞察不足；同时覆盖自适应答题、回答反馈和间隔验证的完整任务状态。
6. 设置中心：数据与同步、AI 服务、高级参数折叠、危险操作和脱敏错误详情。

原型门槛不是静态审美投票。每个页面必须能够走通主操作、返回、Loading、空、错误和窄屏溢出；视觉评审通过后才冻结 token 与壳层契约。深色主题至少为编辑器、复习会话和设置中心提供独立画面，验证其不是机械反色。

## 9. 状态、反馈与动效规范

### 9.1 操作反馈

- Hover：只在支持 hover 的设备启用，使用轻微底色或边框变化，不抬升所有列表项。
- Press：80-120ms 的底色/轻微缩放，布局尺寸不得变化。
- Focus：2px 高对比焦点环，不能仅靠颜色。
- Disabled：除降低对比外必须保留原因；关键操作可通过 Tooltip/辅助文本解释。
- Loading：按钮保持原宽，图标替换为 Spinner；超过 800ms 才显示文字加载状态。

### 9.2 保存与同步

- 本地草稿保护：顶部内联显示 `草稿已存于本机`，不弹 Toast，不写成 `正式内容已保存` 或 `已同步`。
- 正式保存：按钮保持显式；成功后显示 `已保存到本机 · 尚未同步` 或与真实状态一致的短句。
- 同步成功且无变化：状态图标更新，静默完成。
- 同步有新增变化：短 Toast，可点“查看详情”，不得拦截底层点击。
- 保存/同步失败：就地错误 + 重试；如果可能丢数据，持续显示到用户处理。
- 冲突：Dialog 只展示用户能理解的实体、修改时间和差异；默认推荐小范围合并。

### 9.3 空、错、载入

- 空状态必须说明“为什么为空”和唯一下一步；避免“很干净”“没搜到”等只有情绪没有方向的文案。
- 首次载入用页面骨架保持布局稳定；局部请求只替换对应区块。
- 错误按可恢复性分类：重试、修改输入、离线继续、联系/查看诊断。
- 禁止组件直接渲染 `error.message`。统一 `normalizeUiError(error, context)` 将底层异常映射为稳定错误码、中文说明和建议动作，例如：数据库暂时不可用 -> `暂时无法保存评分，请重试；你的当前内容仍保留在本页`。原始堆栈只进入本地脱敏日志并关联短诊断编号。
- 用户界面和诊断导出都必须过滤 API Key、Authorization、Prompt、日志正文、同步载荷和供应商原始响应；未知异常显示通用恢复建议，不猜测“数据损坏”。
- 删除、移出复习、评分等可逆动作优先使用 5-8 秒 Undo Bar；永久删除再用确认 Dialog。

### 9.4 动效

- 微反馈 120ms、控件/Disclosure 180ms、页面切换 200-240ms。
- 页面切换以淡入和 4px 内位移为上限；编辑器和复习会话避免整页运动。
- 支持 `prefers-reduced-motion`，Spinner 除外也需提供静态状态文字。

## 10. 可访问性与响应式标准

- 移动端交互热区至少 44x44px；Desktop 图标按钮至少 36x36px，紧凑按钮不得低于 32px。
- 正文/背景对比达到 WCAG AA 4.5:1；大字和非文本控件至少 3:1。
- 所有图标按钮必须有可访问名称和 Tooltip；危险图标不能只靠颜色区分。
- 页面保持单一 H1；Tab、Menu、Dialog、Progress、Status 使用正确语义和键盘行为。
- 目标视口：390x844、412x915、768x1024、1280x800、1440x1000、1920x1080。
- 不允许横向页面溢出；工具栏和复杂表格在组件内部明确滚动或转为 Sheet/分段视图。
- 使用 `100dvh` 和安全区变量处理软键盘、底栏、播放器和复习评分；任何两个固定层不得覆盖。
- 字号不随 viewport width 缩放；仅布局、间距和列数响应式变化。

## 11. 优先级与实施成本

### P0：立即修复

- Toast 拦截点击、底栏/评分/输入区互相覆盖。
- 编辑和复习会话进入沉浸模式时隐藏全局底栏。
- 移动端关键按钮热区、危险操作确认和错误可恢复性。
- 建立 UI 错误归一化边界，移除对原始 `error.message` 的直接展示；为评分、撤销、保存、同步和 AI 请求提供中文可恢复错误与脱敏诊断编号。
- 为当前关键页面补齐 Desktop/Mobile 截图回归。

影响高，成本低到中；不改变信息架构即可先消除真实阻断。

### P1：视觉证明与最小基础

- 完成六页、双端、12 个高保真交互基准以及深色关键页。
- 冻结字体、颜色、空间、密度和响应式 token。
- 只建立新壳层与首页垂直切片实际需要的最小组件原语。
- 通过创建/返回语义、学科可发现性、移动 `+` 状态和 AI 能力分配评审。

影响高，成本中；它把视觉方向和交互契约从文字判断变成可验证基线。

### P2：核心任务迁移

- 新导航壳层、首页与日志资料库。
- 编辑器连续工作区、草稿保护状态和移动工具栏。
- 复习会话与卡片库拆分；学习助教完整承接驾驶舱能力后再撤旧入口。
- 每迁移一个页面，按需增加控件并删除该页面已无引用的旧样式。

影响最高，成本高，是“首次打开就感觉升级”的主要来源。

### P3：全产品覆盖与精修

- 搜索、设置、备份、AI 设置、录音、播客、模板和统计按新体系迁移。
- 扩展通用控件、状态组件、Dialog/Sheet 和菜单；移除剩余旧 CSS 重复层。
- 动效、骨架、上下文帮助、快捷键和空状态文案。
- 可用性埋点、任务完成率、误触/退出点和性能预算。
- 深色模式与高字号下的完整视觉回归。

影响中，成本中；在结构稳定后实施。

## 12. 分阶段实施方案

### 阶段 0：重构护栏（可见改善：阻断问题消失）

- 固化页面/状态/视口截图矩阵。
- 修复 Toast 指针事件和固定层覆盖。
- 增加错误归一化与脱敏诊断服务，先替换复习评分、撤销、保存和同步的原始异常展示。
- 为导航返回、软键盘、复习评分、编辑草稿、云同步弹窗建立交互回归测试。
- 引入 `design-v2` 功能开关或壳层分支，允许逐页迁移和回退。

### 阶段 1：高保真原型与契约冻结（可见改善：团队看到明确的新产品）

- 完成首页、日志资料库、编辑器、复习会话、学习助教、设置中心的 Desktop/Mobile 12 个交互基准。
- 用真实长内容、批量分析、OCR 缺失、部分失败、离线和错误状态走查，不使用理想化占位数据。
- 冻结信息架构、创建/返回/保存/评分/撤销契约、视觉 token、密度、响应式和固定层规则。
- 本阶段不删除旧入口、不改数据模型、不引入正式记录自动保存。

### 阶段 2：最小设计基础与应用壳层（可见改善：整体已像新产品）

- 建立新 token 和首个垂直切片所需的按钮、图标按钮、列表、Quick Create Sheet、保存状态、Toast 与行内错误；不预建未被页面使用的完整组件库。
- 重做 Desktop 侧栏与 Mobile 底栏；统一两端目的地。
- 清理空 Pinned 占位、重复返回按钮和装饰性 eyebrow；有内容时保留可点击的“置顶日志”快捷入口。
- 新页面只引用新样式层，旧样式冻结。

### 阶段 3：首页与日志资料库（可见改善：产品定位被立即纠正）

- 首页改为记录、待复习、最近日志三层。
- 先把现有工作台原样迁入稳定入口 `复习 > 学习助教`，验证批量分析、恢复和任务入口仍可达，再把首页完整工作台收起为条件式一行建议；阶段 5在该稳定目的地内部完成重设计。
- 合并日志、分类和收藏的浏览模型；新增列表/日历/学科视图。
- 重做全局搜索与筛选。

### 阶段 4：编辑器（可见改善：写作空间和效率显著提升）

- 拆分文档栏、元信息、主工具栏、移动上下文栏和检查器。
- 统一本地草稿保护、显式正式保存、失败重试和草稿恢复状态，不改变现有存储语义。
- 处理 Android 软键盘、IME、选区工具条、附件插入和焦点模式。
- 模板编辑器复用同一框架。

### 阶段 5：复习与学习助教（可见改善：复习更专注，AI 不再抢占）

- 复习首页拆分为日志复习、学习助教和卡片库；学习助教内部组织待分析、进行中、训练与验证和学习洞察。
- 决策块评论渐进披露；评分后提供 AI 建议。
- 学习助教完整承接批量选择、OCR 风险、用量摘要/详情、部分批次恢复、任务调度和结果承接；对照验收通过前保留旧工作台入口。
- 普通视图隐藏版本、内部枚举和 FSRS；用量摘要保留，token/模型/子批次进入详情。
- 保持现有正式事实写入、任务调度和延迟验证语义不变。

### 阶段 6：设置、数据与 AI（可见改善：低频功能更清晰可靠）

- 将当前“更多”拆为工具启动器和唯一设置中心，不复制入口。
- 重做同步/备份状态和冲突 Dialog，但不更改同步协议。
- AI 设置改为摘要 + 详情 + 高级参数。
- OCR、TTS、回收站和教程迁入统一设置框架。

### 阶段 7：录音、播客、统计与全状态收口（可见改善：长尾页面达到同一品质）

- 录音列表/播放器、播客步骤编辑、统计和模板迁移。
- 补齐空、错、载入、离线、权限、撤销和成功状态。
- 完成深色、高字号、窄屏、平板和超宽屏验收。
- 删除不再引用的旧 CSS，完成性能和可访问性审计。

## 13. 主要风险与控制策略

1. **导航与系统返回风险。** 当前自定义 `tabMemory` 同时处理 Web 历史和 Android 返回。先替换壳层视觉，不在同一阶段重写导航状态机；所有深层页面必须有自动化返回路径测试。
2. **编辑器回归风险。** 富文本、粘贴、IME、附件和结构块高度耦合。先拆 UI 外壳，不更换 TipTap/ProseMirror 文档模型；Android 真机必须覆盖中文输入、键盘开合和长文滚动。
3. **复习事实写入风险。** UI 拆分不得改变 FSRS、Review Coach 原子提交和撤销规则。新视图只调用现有 orchestrator/repository 接口。
4. **云同步风险。** 视觉重构不新增同步实体，不改变哈希、tombstone、增量计划或本地专属数据。任何新增 UI 偏好默认仅本地保存，若需同步必须单独审计。
5. **CSS 迁移风险。** 当前两套大样式层存在级联依赖。采用“新壳层命名空间 + 逐页迁移 + 删除已迁移选择器”，不可一次性重命名全局类。
6. **跨端分叉风险。** Desktop 和 Mobile 应共享任务模型和组件状态，但允许布局组合不同；禁止复制出两套业务组件。
7. **性能风险。** 毛玻璃仅用于少量导航/浮层；长列表虚拟化或分页；避免在编辑器和移动设备上使用大面积 blur 与复杂过渡。
8. **可发现性风险。** 将 AI、高级设置和分类管理降级后，需要通过上下文入口、全局搜索和设置索引保证仍可找到。
9. **学习助教能力遗漏风险。** 首页撤下工作台不等于删除能力。以候选、OCR、用量、批次恢复、调度、结果六类对照测试作为旧入口删除闸门，并保持旧入口可回退一个发布周期。
10. **创建与保存语义漂移风险。** 当前新建会立即持久化正式记录，编辑过程保护本地草稿，显式保存才提交正式内容。Quick Create 只重排入口，不得隐式引入未同步临时记录或正式内容自动保存。
11. **错误诊断泄密风险。** 错误归一化层必须先清洗再记录；诊断导出使用允许字段清单，并增加密钥、Prompt、正文和同步载荷的拒绝测试。

## 14. 验收标准

### 产品与路径

- 首次打开后 3 秒内能识别“记录学习”和“开始复习”两个主要任务。
- 从首页到正文可输入不超过 2 次点击：一次打开 Quick Create，一次确认；最近学科可预选但不得静默改变正式记录归属。
- 最近日志、按日期、按学科、收藏和搜索均能从“日志”内到达。
- AI 不占首页固定大区；无待处理 AI 任务时首页不展示 AI 模块。
- 普通模式显示人类可读的 AI 用量等级和 OCR 风险，但不出现精确 token、子批次、内容版本、FSRS、内部枚举或 Prompt；用量详情可查看模型和估算限制。
- AI 问答、学习助教、知识播客三者的入口、标题和结果去向清晰，不互相混入历史或任务队列。

### 布局与交互

- 所有目标视口无页面级横向滚动、意外裁切或控件重叠；摘要和次要字段可以使用明确的单/双行省略，但必须提供展开、Tooltip 或详情页查看全文。
- 编辑态与复习会话隐藏全局导航；移动键盘弹出后正文/回答区仍可见且可滚动到操作按钮。
- Toast 不拦截点击；底栏、播放器、评分条、Undo Bar 和键盘有明确层级与安全区。
- 移动端主要触控目标不小于 44x44px；相邻危险/常规操作间距至少 8px。
- 页面切换不造成内容尺寸跳动；加载、保存、同步和错误状态都有稳定占位。

### 视觉与内容

- 普通页面最多一个主要实心按钮；卡片仅用于独立重复实体或真正工具面板。
- 页面结构主要由排版、留白和分隔线表达，不出现卡片嵌卡片。
- 字体层级、控件高度、图标尺寸、圆角、状态色和文案语气通过 token/组件统一。
- 长文正文行长和行高满足连续阅读；大字号设置下仍不溢出。
- 六页双端 12 个高保真基准全部通过主任务、真实内容、空/错/载入和窄屏走查；编辑器、复习和设置的深色版本具有独立层级调整，不是机械反色。

### 可访问性与质量

- WCAG AA 对比度、可见焦点、键盘导航和屏幕阅读器名称通过检查。
- `prefers-reduced-motion` 下无非必要动画。
- Playwright 覆盖 Desktop、Android narrow、平板和超宽屏的主路径截图与交互。
- Android 真机覆盖中文 IME、系统返回、前后台、离线恢复和权限拒绝。
- UI 重构前后的备份/恢复、增量云同步、冲突合并和本地知识播客数据边界测试全部保持通过。
- 用户可见区域不出现 Dexie、IndexedDB、堆栈、对象存储名或原始供应商异常；错误消息均有下一步，诊断导出不包含密钥、Prompt、正文和同步载荷。
- 复习评分与卡点仍原子提交；撤销会失效同源反馈、队列项和派生任务，不留下孤立的学习助教任务。

## 15. 推荐的第一批实际改动

在进入全面重构前，先完成“安全护栏 + 视觉证明”，再编码一个可独立验收的垂直切片：

1. 修复 Toast 点击拦截与底部固定层覆盖。
2. 建立错误归一化层，首先封住复习评分/撤销、编辑保存、同步和 AI 调用的原始异常。
3. 制作并评审六页双端高保真交互基准；在此之前不删除驾驶舱、分类或现有导航入口。
4. 原型通过后，新建 v2 壳层、最小 token 和首屏所需组件，只重构首页与“Quick Create -> 正式记录创建 -> 编辑 -> 草稿保护 -> 显式保存 -> 返回”路径。
5. 同时保留旧页面入口，进行 Desktop/Android 对照验收；该切片通过后，再迁移日志资料库和复习流程。

这批改动能最快验证新的产品定位、视觉语言、响应式策略和编辑体验，同时把对云同步与 Review Coach 正式事实的影响控制在最低范围。
