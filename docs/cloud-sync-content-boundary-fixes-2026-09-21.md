# 云同步内容边界修复（2026-09-21）

## 范围

基于 226e60d 的内容边界审查修复。没有改变 schema、同步协议版本、正式学习事实范围或真实冲突保护；没有访问真实账号、调用付费服务、提交、推送或安装客户端。

## 修复

### P0：播客资源原子分类

- 原生 TTS 产物导入与非原生生成都在首次 saveAsset 时传入 generatedBy、播客 ID 和音频单元 ID，不再先保存普通资源再补来源。
- 资源与普通资源的 mutation 标记在同一事务提交；播客资源不增加云 mutation。失败不会留下无分类资源或孤立 mutation。
- 未自动识别或删除历史无标记资源；已有云端资源和恢复点不做追溯清理。

### P1：OCR 内容与本机执行状态

- 云实体导出、小文档写入、大载荷文档生成均剥离五个运行字段：ocrStatus、ocrError、ocrJobId、ocrUpdatedAt、ocrResultSummary。有效 ocrText 仍参与内容哈希和同步。
- 老客户端上传的运行字段在接收与实体物化时忽略。云恢复事务从当前设备数据库读取并保留本机 OCR 运行态，不能依靠已经脱敏的本地导出获取它。
- 新设备根据有无已保存文本初始化本机状态；已有设备的真实队列状态保持不变。已保存的非空 ocrText 是内容，不再由一次本机识别失败状态否决。现有 OCR 写入器只在识别成功且文本非空后写入 ocrText，失败不产生结果文本。
- 自动入队不会重新识别已有文本；用户明确强制识别仍可执行。没有扩大 AI 聊天附件的接收规则，也没有修改 OCR 提供商调用。

### P1：本机正文字号

- editorFontScale 从共享导出排除；云同步、普通恢复和流式恢复均保留当前设备字号，没有本机值时采用默认 1。
- 有 basePayload 的旧设置 ledger 按去除本机字段后的共同基线比较，避免单纯字段隔离导致无意义上传。真实共享设置改动仍会被识别。
- 无共同基线的历史设置仍走原有保守处理，不为避免提示而跳过真正的差异。

## 验证

- 最终确定性测试：216 个文件 / 1679 项通过（排除 live provider 文件）；TypeScript 检查和生产构建通过。构建保留现有大分块体积警告。

- 新增资源初次落库、数据库重开、写入失败事务回滚测试；两个播客入口均断言首次调用携带来源，且不再依赖 patchAsset。
- OCR 覆盖有效文本与 idle/running/failed/timeout 的组合、空文本、外来任务信息过滤、大载荷脱敏、自动识别不重复调用。
- 独立 A/B 数据库及 ledger、可控远端的服务测试覆盖两个方向：A 更新 OCR，B 拉取，B 和 A 重开数据库并再次同步。
- 每个方向仅上传一个资源元数据实体、接收一个资源实体；图片字节两端和远端已存在，测得一次 Storage 元数据检查，零附件上传、零附件下载；再次同步无新增远端写入。此计数不代表所有同步场景或真实账单费用。
- 正文字号覆盖旧设置基线、真实设置变化，以及云/普通/流式三个恢复入口。
- Firebase Emulator 使用 demo-noteproject-stage9，本轮 4/4 通过；不等于新边界用例已在真机验证。

## 明确保留的边界

- 普通编辑草稿、软删除内容、历史归档、助教正式诊断仍同步；临时语音、语音历史、批注草稿、聊天历史、凭据等排除范围不变。
- 未引用普通资源仅补充说明，不添加自动过滤、自动删除或新诊断 UI。
- 未追溯删除历史云端 OCR 运行字段或无标记播客音频。旧客户端仍可能产生旧行为，应两端一起更新；本轮不构建或安装 APK/EXE。
- 测试使用一个进程中的隔离数据库和模拟远端，不模拟真机进程并行、网络生命周期或付费 OCR。未承诺修复其他既有 OCR 异步回调竞态。
