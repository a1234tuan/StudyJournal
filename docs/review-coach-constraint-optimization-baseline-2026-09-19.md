# 学习助教约束优化冻结基线（2026-09-19）

本文件冻结本次学习助教约束优化的实施边界。它是现有 Review Coach 的维护性修复与可诊断性改进，不改变正式任务、掌握状态、FSRS、调度、云同步、备份或数据库事实语义。

## 核心原则

- 对来源事实严格：不得伪造日志内容、用户原话、来源引用、版本或正式状态。
- 对教学推理开放：允许基于可见来源进行可复核的数学、逻辑或学科推导，并指出错误前提与题面歧义。
- 对教学加工积极：允许拆解、辨析、变式、前置知识检查、例题和提示；推导结果不得冒充来源事实。
- 对正式状态克制：AI 不得直接修改掌握、任务优先级、验证日期或其他正式状态。
- 对失败原因透明：区分 Provider、JSON、Schema、上下文、证据和本机状态失败，并显示是否可能已产生用量。

## `insufficient-context` 门槛

只有同时满足以下条件才允许返回 `insufficient-context`：

1. 无法识别任何训练目标；
2. 无法形成任何可验证判据；
3. 无法通过澄清题、辨析题或前置知识检查继续推进。

缺少标准答案、需要学科推导、用户理解可能错误、题面存在歧义、需要先检查前置知识，均不再单独构成拒绝理由。

## 分阶段闸门

1. P0：建立失败分类、黄金样例和回归基线。
2. P1：向模型提供完整成功 Schema/模板，使成功与拒绝契约对称。
3. P2：重写事实、推理、教学边界和 `insufficient-context` 提示。
4. P3：增加阶段化错误诊断与请求状态反馈。
5. P4：增加最多一次、仅修复格式的 JSON/Schema 重试。
6. P5：Provider 能力分级和兼容性测试。
7. 最终回归：完整测试、构建、Android 验证，最后由用户进行真实 Provider/手机验收。

## 明确不做

- 不删除来源和版本校验。
- 不以放宽本地 Schema 换取成功率。
- 不允许模型自行决定正式掌握、任务优先级或延迟验证日期。
- 不把模型推导写回用户原始事实。
- 不进行无限重试，不在未批准时反复调用付费 Provider。
